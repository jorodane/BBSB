# Beat! Block, Shake~ Beat!

Unity 모바일 버전의 탐험 흐름, 음악 슬롯, 몬스터 전투 계획과 Call & Response 전투 화면 구현. Unity **6000.3.5f2**, URP 2D, Input System을 사용한다.

## 실행

1. `codex/roguelike-foundation` 브랜치를 받아 Unity Hub에서 프로젝트 루트를 연다.
2. `Assets/BBSB/Scenes/RunMap.unity`를 열고 Play를 누른다.
3. Game 뷰를 **16:9 또는 16:10 가로 화면**으로 설정하고 **탐험 시작**을 누른다. 기본 실행 크기는 1280×720이며 모바일도 가로 방향을 사용한다.
4. 화면 전체를 채우는 지도에서 왼쪽의 밝은 노드부터 선택하고 오른쪽으로 진행한다. 연결된 다음 단계만 진입할 수 있다. 우측 상단의 **원형 메뉴 버튼 → 장비 · 가방 · 증강**에서 이번 탐험의 장비와 보상을 확인한다.
5. 전투 노드의 **준비하기**에서도 몬스터와 주인공을 큰 무대로 보여준다. **몬스터 패턴** 버튼으로 전조 신호, 대응 패턴, 휴식 길이와 등장 횟수를 확인한다. 각 카드의 시간은 해당 패턴 안의 상대 박자다. 닫으면 같은 준비 화면으로 돌아온다.
6. 우측 하단의 **연주 시작**을 누른다. 화면 전체가 전투 무대이며 왼쪽 앞쪽에 웨폰 마스터와 다섯 무기, 오른쪽에 몬스터들이 배치된다. 몬스터의 Call 모션과 금빛 신호를 보고 화면을 눌러 대응한다. 박자 신호, 현재 판정과 입력 상태는 전투 장면 위에 겹쳐 표시된다. 메뉴와 신호 줄이 전투 화면의 크기를 줄이지 않는다.
7. Tap은 누르기, Hold는 유지, Dive는 끝에 떼기, Flick은 미리 누른 뒤 빠르게 움직이며 떼기, Shake는 누른 상태로 흔들기다. **Shake는 구간의 50% 이상 흔들면 반미스, 75% 이상이면 성공**이며 진행 비율이 표시된다. 끝까지 계속 흔들 필요는 없다. 마우스 왼쪽 버튼이나 한 손가락을 사용한다. 판정은 몬스터별 표시와 전체 **PERFECT / 반미스 / MISS** 집계에 반영된다.
8. 판정이 확정될 때마다 플레이어가 기본 피해의 **미스 100% / 반미스 75% / 퍼펙트 50%**를 받는다. 좌측 상단의 HP 바와 받은 피해를 확인한다. 현재 샘플 기본 피해는 판정당 4로, 각각 4 / 3 / 2 피해를 받는다. **메뉴** 또는 **Esc**로 일시정지하며, **연주 정보 · 패턴**에서 상세 판정을 확인한다. 유지 중에 멈췄다면 **이어하기 → 화면을 다시 누르기**로 이어간다. 곡 끝까지 살아남으면 **연주 결과 → 다시 준비**로 돌아오며 남은 HP·음악·몬스터 계획을 유지한다. 메뉴에서 준비로 돌아가도 HP는 복구되지 않는다. HP가 0이면 연주가 멈추고 게임오버로 이동한다.
9. 준비 화면의 **메뉴 → 개발 도구 → 슬롯 펼치기**에서 다섯 곡과 각 마디를 둘러볼 수 있다. 이 메뉴와 전투 결과 테스트 버튼은 `Show Battle Test Controls`가 켜져 있을 때만 표시된다. 몬스터 패턴과 연주는 이 옵션을 꺼도 사용할 수 있다.

`RunMap`은 Build Settings의 활성 시작 씬으로도 등록되어 있다. UI, EventSystem, 폰트는 씬의 `RunBootstrap`이 연결하므로 수동 오브젝트 연결은 필요하지 않다. 마우스 클릭과 모바일 터치를 지원하며 화면 안전 영역을 사용한다. 지도·준비·연주 화면은 스크롤 없이 전체 영역에 맞추며, 상점·보상·메뉴 등 긴 목록만 세로로 스크롤한다. 화면 구성과 메뉴 경로는 [Docs/ScreenLayout.md](Docs/ScreenLayout.md)에 있다.

## 이번 버전에서 할 수 있는 일

- 3개 선택지 × 3단계와 4번째 단계의 보스로 구성된 무작위 연결 맵.
- 노드를 배치한 뒤 후보 연결을 무작위로 끊는다. 같은 라인을 잇는 직선 길도 제거 대상이며, 고립된 노드 없이 분기와 보스까지의 경로를 유지한다.
- 한 필드의 각 진행 경로에서 상점과 휴식은 **각각 최대 1회**만 만난다. 합류하거나 옆 라인으로 이동하는 경로도 포함한다.
- 몬스터·엘리트·보스 클리어 → 골드 획득 → 무기/아이템/증강 중 하나 선택.
- 항상 무기 5슬롯 유지. 새 무기는 교체할 슬롯을 명시적으로 선택하며 기존 강화도 교체된다.
- 휴식: 최대 체력 비율 회복. 강화: 무기 하나 +1, 최대 +3. 각각 방문당 한 번 사용하거나 건너뛸 수 있다.
- 상점: 골드로 상품 구매, 재구매/초과 지출 방지. 구매하지 않고 나갈 수 있다.
- 회복 물약, 최대 체력 증강, 휴식량 증강, 상점 할인 증강.
- 보스 보상 처리 후 새 필드 생성. 체력·골드·장비·보상은 유지된다.
- 게임오버/탐험 종료 시 이번 런의 보상을 버린다. 새 탐험은 1필드의 기본 상태에서 시작한다.
- 전투 노드마다 다섯 샘플 곡 중 하나를 선택하고 Tap/Hold/Dive/Flick/Shake 슬롯을 생성한다. 같은 전투에서는 곡과 슬롯을 유지한다.
- 정박·엇박·유지 길이·하이라이트 가중치가 다른 16마디 설정과 개발용 마디별 미리보기. 실제 음원은 아직 없다.
- 몬스터 패턴의 전체 리듬, 유지 길이, 전조 선행 시간을 만족하는 후보를 `IEnumerable<PatternPlacement>`로 조회한다.
- 샘플 몬스터 6종 중 곡에 맞는 몬스터를 뽑아 독립적인 Call/Response 계획을 제출한다. 일반·엘리트·보스 모두 1필드는 최대 1종, 2필드는 최대 2종, 3필드부터 최대 3종이다.
- 서로 다른 몬스터의 입력이 겹칠 때 종류가 다르면 충돌로 처리하며, 같은 종류도 누름/떼기와 유지 조건이 호환되어야 공유한다. 몬스터 자체에 작성된 복합 동작은 유지한다. 점유 박자가 많은 몬스터가 해당 공격 묶음과 전조를 통째로 양보하고, 남은 점유량으로 다음 충돌을 비교한다.
- 준비 화면은 실제 공격이 남은 몬스터의 고유 패턴을 한 번씩 보여준다. 곡 전체의 공격 위치를 플레이어에게 펼쳐 놓지 않는다.
- 지도·준비·전투 무대는 HUD 뒤까지 화면 전체를 사용한다. 작은 원형 메뉴 버튼이 우측 상단에 독립적으로 떠 있고, 준비 화면의 시작 버튼도 무대 위에 놓인다. 메뉴를 열어도 선택 중인 보상·스테이지·곡·몬스터 계획은 유지된다.
- 준비 화면에서 시작하는 실제 마우스/터치 연주. 몬스터별 Call·Response·휴식, 진행선, 입력별 결과를 표시한다.
- 주인공과 샘플 몬스터 6종의 투명 이미지, 몬스터별 Call/공격 모션, 주인공의 베기·방어·회피·올려 베기·무기 난무. 공유 입력의 여러 결과를 동시에 표현하며 Perfect/반미스/Miss의 강도와 색을 구분한다.
- 공격이 없는 박자에도 정박과 엇박 신호가 독립적으로 점멸한다. 샘플 박자음과 화면·판정은 같은 DSP 시계를 사용한다.
- 5종 손동작과 공유 입력을 판정한다. 한 번의 누르기나 떼기를 여러 몬스터가 함께 판정할 수 있으며 Dive-Shake-Flick 같은 연속 동작도 지원한다.
- 일시정지/앱 포커스 상실 시 시계와 소리를 멈춘다. 곡 종료 후 정확·반미스·미스와 몬스터별 집계를 보여주고 같은 계획으로 다시 준비한다.
- 판정마다 플레이어 피해를 한 번 적용한다. 소수 HP, 체력 바, 최근 피해 및 회차 누적 피해를 표시한다. 사망 시 남은 노트에 추가 미스를 만들지 않고 연주와 런을 종료한다.

**입력 판정, 2D 전투 연출, 플레이어 피격과 사망 처리를 구현했다.** 다섯 곡은 BPM/슬롯 설정과 합성 박자음이며 실제 음악 파일은 없다. 캐릭터는 한 장의 이미지에 이동·회전·스케일 변화를 주는 컷아웃 모션을 사용한다. 몬스터에게 주는 피해는 무기 배치 구현 이후에 연결한다. 따라서 적 HP 감소와 자동 승리·Overkill·콘페티는 아직 없으며, 곡 종료만으로 스테이지를 클리어하지 않는다. 보상 흐름은 준비 화면의 `메뉴 → 개발 도구 → 테스트용 전투 결과`로 확인한다. 전용 전조 음원과 관절 애니메이션도 후속 작업이다.

## 임시 콘텐츠와 조정 값

- 첫 필드부터 매 필드 4단계, 보스 한 노드. 최종 필드 수는 아직 정하지 않았으므로 보스 후 다음 필드로 반복한다.
- 시작 HP 100, 골드 60, 휴식 30%: 씬의 `RunBootstrap` Inspector에서 변경.
- 샘플 몬스터의 판정당 기본 피해는 4. `MonsterDefinition`의 `damagePerNote` 인자로 몬스터마다 지정할 수 있다. HP와 피해는 `decimal`로 계산하므로 기본 피해 3의 퍼펙트 1.5, 반미스 2.25도 반올림 없이 누적한다.
- `Use Fixed Seed`를 켜면 같은 시드로 재현 가능. 기본은 새 탐험마다 다른 시드다.
- 시작 무기 다섯 개, 상품 이름/설명, 가격, 회복량, 보상 골드는 샘플 값이다. 확정된 전투 밸런스가 아니다.
- `ContentCatalog.cs`에서 샘플 아이템을, `MapGenerator.cs`에서 노드 종류의 분포를 변경한다.
- 각 필드에 다섯 종류의 일반 노드가 모두 등장하도록 분포를 섞는다. 이는 초기 테스트용 분포다.
- 일반 단계 사이의 앞/인접 라인을 후보로 연결한 뒤 7개 후보 중 3~4개만 남긴다. 모든 노드의 진입/퇴로, 실제 경로별 상점·휴식 제한을 만족하는 제거안을 무작위로 고른다. 각 단계 사이에서 같은 라인의 직선 연결도 최소 하나 제거한다.
- 상점·휴식 제한은 필드 전체 노드 수가 아니라 경로별 제한이다. 서로 다른 경로에는 여러 개가 배치될 수 있고, 다음 필드에서는 다시 만날 수 있다.
- 강화는 현재 레벨을 저장한다. 실제 계수는 전투 구현에서 사용한다.
- 회복 물약은 현재 전투 밖에서만 사용 가능. 저장/불러오기, 앱 재시작 후 런 복원, 영구 성장, 최종 엔딩은 아직 없다.

대화에서 확정한 리듬 전투 규칙은 [Docs/Design.md](Docs/Design.md)에 보존했다.
다섯 곡의 설정과 몬스터 배치를 위한 API 예시는 [Docs/MusicStages.md](Docs/MusicStages.md)에 있다.
샘플 몬스터와 계획 생성/양보 규칙은 [Docs/MonsterPlans.md](Docs/MonsterPlans.md)에 있다.
연주 조작, 판정 수치와 재생 구조는 [Docs/RhythmPlayback.md](Docs/RhythmPlayback.md)에 있다.
전투 무대, 입력별 모션, 시간 동기화와 아트 경로는 [Docs/BattlePresentation.md](Docs/BattlePresentation.md)에 있다.

## 구조와 전투 연결

| 파일/폴더 | 역할 |
|---|---|
| `Assets/BBSB/Core` | Unity에 의존하지 않는 맵·음악 슬롯 생성, 몬스터 계획/충돌 중재, 리듬 판정, 런 상태, 보상 규칙 |
| `Assets/BBSB/Runtime/RunBootstrap.cs` | 씬 진입점, 초기 값, 한글 폰트, 입력 모듈 |
| `Assets/BBSB/Runtime/RunPresenter.cs` | 화면 구성과 사용자 명령 전달 |
| `Assets/BBSB/Runtime/RhythmPlayback.cs` | 한 회차의 DSP 시계, 포인터 입력과 일시정지, 종료 전달 |
| `Assets/BBSB/Runtime/UI` | 레이아웃, 노드 연결선, 안전 영역, 몬스터 패턴 카드와 개발용 슬롯 미리보기 |
| `Assets/BBSB/Runtime/UI/BattleArenaView.cs` | 현재 계획/판정에서 몬스터와 주인공의 포즈·효과를 구성 |
| `Assets/BBSB/Resources/BBSB/BattleArt` | 주인공과 몬스터 6종의 투명 Sprite 원본 |
| `Assets/BBSB/Tests` | EditMode 핵심 규칙 테스트와 PlayMode UI 연결 테스트 |

`RunPresenter.BattleRequested(ticket, stageKind, fieldNumber)`는 전투 노드 진입을 알린다. 준비 화면의 `StartRhythmRound()`는 `RunSession.StartRhythmRound()`를 통해 `Session.BattlePlan`으로 새 회차를 만들며 `ActiveRound`에서 조회할 수 있다. 세션은 활성 회차의 `ResultJudged`를 구독하여 HP를 즉시 차감하고, 종료·중단·런 재시작 시 구독을 해제한다. 준비 미리보기용으로 직접 만든 `RhythmRound`는 세션 HP를 바꾸지 않는다. 향후 무기 효과 계층이 적 공용 HP와 승리를 판정한 뒤 `SubmitBattleResult(ticket, victory, remainingHealth)`로 결과를 돌려준다. `remainingHealth`는 소수 HP를 보존하는 `decimal`이며, 고유 ticket이 이전 스테이지/런의 늦은 결과나 중복 보상을 거부한다.

`BattleRequested`가 호출될 때 `Session.BattleMusic`에 곡과 슬롯, `Session.BattlePlan`에 배치된 몬스터·전체 공격 묶음·시간순 Call 신호가 준비되어 있다. 같은 전투의 준비/연주 반복은 이 객체들을 재사용한다. 스테이지 종료, 게임오버, 런 재시작 시 해제된다. 개발용 샘플 곡 둘러보기는 실제 전투의 음악이나 몬스터 계획을 변경하지 않는다.

맵 난수와 보상 난수는 분리되어 있고, 음악 선택은 런 시드와 필드/노드 위치로 독립적으로 결정된다. 상점을 들르거나 다른 종류의 보상을 받았다고 다음 필드 맵이 달라지지 않는다. `RunSession`은 플레이어 피격을 실시간 반영하며, 보상과 다음 스테이지 이동은 스테이지 전체의 승리 결과가 제출된 뒤 처리한다.

## 검증

핵심 로직은 .NET 8에서 실행해 **78개 테스트 통과**. 탐험 17개, 음악 11개, 몬스터 계획 14개, 입력 판정 24개, 플레이어 피해 12개다. 기존 리듬·맵·배치 검증에 더해 피격 배율과 소수 피해, 공유 입력의 개별 피해, 중복 방지, 유지 입력의 최종 판정, 일시정지, 중도 복귀와 재연주의 HP 유지, 사망 즉시 중단, 이전 회차 무효화 및 소수 HP 회복을 확인한다.

```sh
dotnet run --project Tools/CoreChecks/BBSB.CoreChecks.csproj --configuration Release
```

Unity에서는 **Window → General → Test Runner**에서 EditMode의 `BBSB.Core.Tests`, PlayMode의 `BBSB.UI.Tests`를 실행한다. PlayMode에는 연주/박자/결과/재준비, 포인터와 일시정지, 외부 승패, 가로 레이아웃과 메뉴, 캐릭터 모션 검증이 있다. 체력 HUD의 수치·비율과 입력 통과, 준비 복귀 시 HP 유지, 사망 시 연주 해제와 게임오버 표시도 추가했다. C# 38개 파일의 구문 검사는 통과했지만 작업 환경에는 Unity Editor가 없어 **Unity 컴파일·PlayMode 테스트·모바일 빌드는 아직 실행하지 못했다.** `RunMap`의 16:9와 16:10 Game 뷰에서 판정별 HP 감소, 메뉴/재준비 시 HP 유지, 사망을 확인한다.

한글 글꼴은 OFL 라이선스의 Noto Sans CJK KR 일부를 `BBSB UI`로 이름을 바꿔 포함했다. 새 한글 텍스트를 넣을 때는 `Tools/subset_font.py`로 글자 집합을 갱신한다. 출처와 라이선스는 폰트 폴더에 있다.
