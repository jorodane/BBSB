# Beat! Block, Shake~ Beat!

Unity 모바일 버전의 탐험 흐름, 음악 슬롯, 몬스터 전투 계획과 Call & Response 전투 화면 구현. Unity **6000.3.5f2**, URP 2D, Input System을 사용한다.

## 실행

1. `codex/roguelike-foundation` 브랜치를 받아 Unity Hub에서 프로젝트 루트를 연다.
2. `Assets/BBSB/Scenes/RunMap.unity`를 열고 Play를 누른다.
3. Game 뷰를 **16:9 또는 16:10 가로 화면**으로 설정하고 **탐험 시작**을 누른다. 기본 실행 크기는 1280×720이며 모바일도 가로 방향을 사용한다.
4. 화면 전체를 채우는 지도에서 왼쪽의 밝은 노드부터 선택하고 오른쪽으로 진행한다. 연결된 다음 단계만 진입할 수 있다. 우측 상단의 **원형 메뉴 버튼 → 장비 · 가방 · 증강**에서 이번 탐험의 장비와 보상을 확인한다.
5. 전투 노드의 **무기 배치 · 연습**에서 장착한 5개 무기를 몬스터의 패턴별로 배치한다. 카드를 드래그하거나 무기 선택 후 밝은 박자 칸을 누른다. 같은 박자에 여러 무기를 겹쳐 놓을 수 있으며, 기존 몬스터 판정 하나로 각 무기의 효과가 함께 발동한다. 무기 배치가 별도 입력을 추가하지 않는다. **이 패턴 연습**은 배치와 실제 판정으로 짧게 연습하고 결과에서 다시 시도한다. 탐험의 HP·적 HP·보상은 바뀌지 않는다. 전투 노드의 **준비하기**에서도 몬스터와 주인공을 큰 무대로 보여준다. **몬스터 패턴** 버튼으로 전조 신호, 대응 패턴, 휴식 길이와 등장 횟수를 확인한다. 각 카드의 시간은 해당 패턴 안의 상대 박자다. 닫으면 같은 준비 화면으로 돌아온다.
6. 우측 하단의 **연주 시작**을 누른다. 화면 전체가 전투 무대이며 작아진 웨폰 마스터와 다섯 무기는 왼쪽에, 몬스터들은 오른쪽에 깊이를 달리해 선다. 중앙의 낮은 경로로 공격이 날아오고, 반격은 위쪽 곡선을 따라 돌아간다. 패턴이 시작되는 몬스터가 한 걸음 앞으로 나와 Call과 Response 전체를 수행한 뒤 돌아가는 고정 측면 구도다. 몬스터의 Call 모션과 금빛 신호를 보고 화면을 눌러 대응한다. 박자 신호, 현재 판정과 입력 상태는 전투 장면 위에 겹쳐 표시된다. 메뉴와 신호 줄이 전투 화면의 크기를 줄이지 않는다.
7. Tap은 누르기, Hold는 유지, Dive는 끝에 떼기, Flick은 미리 누른 뒤 빠르게 움직이며 떼기, Shake는 누른 상태로 흔들기다. **Shake는 지정 구간 안에 한 번 왕복하면 성공**이다. 바깥 이동만 하고 돌아오지 못하면 반미스, 이동량이 부족하면 미스다. 왕복 완료 후에는 멈추거나 떼어도 된다. 마우스 왼쪽 버튼이나 한 손가락을 사용한다. 판정은 몬스터별 표시와 전체 **PERFECT / 반미스 / MISS** 집계에 반영된다.
8. 판정이 확정될 때마다 플레이어가 기본 피해의 **미스 100% / 반미스 50% / 퍼펙트 0%**를 받는다. 좌측 상단의 HP 바와 받은 피해를 확인한다. 현재 샘플 기본 피해는 판정당 4로, 각각 4 / 2 / 0 피해를 받는다. **메뉴** 또는 **Esc**로 일시정지하며, **연주 정보 · 패턴**에서 상세 판정을 확인한다. 유지 중에 멈췄다면 **이어하기 → 화면을 다시 누르기**로 이어간다. 곡 끝까지 살아남으면 **연주 결과 → 다시 준비**로 돌아오며 남은 플레이어 HP·적 공유 HP·무기 배치·음악·몬스터 계획을 유지한다. 메뉴에서 준비로 돌아가도 HP는 복구되지 않는다. HP가 0이면 연주가 멈추고 게임오버로 이동한다.
9. 준비 화면의 **메뉴 → 개발 도구 → 슬롯 펼치기**에서 다섯 곡과 각 마디를 둘러볼 수 있다. 이 메뉴와 전투 결과 테스트 버튼은 `Show Battle Test Controls`가 켜져 있을 때만 표시된다. 몬스터 패턴과 연주는 이 옵션을 꺼도 사용할 수 있다.

`RunMap`은 Build Settings의 활성 시작 씬으로도 등록되어 있다. UI, EventSystem, 폰트는 씬의 `RunBootstrap`이 연결하므로 수동 오브젝트 연결은 필요하지 않다. 마우스 클릭과 모바일 터치를 지원하며 화면 안전 영역을 사용한다. 지도·준비·연주 화면은 스크롤 없이 전체 영역에 맞추며, 상점·보상·메뉴 등 긴 목록만 세로로 스크롤한다. 화면 구성과 메뉴 경로는 [Docs/ScreenLayout.md](Docs/ScreenLayout.md)에 있다.

## 이번 버전에서 할 수 있는 일

- 4개 노드 × 5단계와 6번째 단계의 보스로 구성된 무작위 연결 맵. 시작 지점 네 곳은 모두 일반 몬스터 전투다.
- 2~5번째 단계마다 물음표 지역이 하나씩 등장한다. 진입하면 몬스터·엘리트·강화·휴식·상점 중 하나로 밝혀지고, 방문한 곳의 정체는 지도에 남는다.
- 노드를 배치한 뒤 후보 연결을 무작위로 끊는다. 같은 라인을 잇는 직선 길도 제거 대상이며, 고립된 노드 없이 분기와 보스까지의 경로를 유지한다.
- 한 필드의 각 진행 경로에서 상점과 휴식은 **각각 최대 1회**만 만난다. 합류하거나 옆 라인으로 이동하는 경로도 포함한다.
- 몬스터·엘리트·보스 클리어 → 골드 획득 → 무기/아이템/증강 중 하나 선택.
- 항상 무기 5슬롯 유지. 새 무기는 교체할 슬롯을 명시적으로 선택하며 기존 강화도 교체된다.
- 휴식: 최대 체력 비율 회복. 강화: 무기 하나 +1, 최대 +3. 각각 방문당 한 번 사용하거나 건너뛸 수 있다.
- 상점: 골드로 상품 구매, 재구매/초과 지출 방지. 구매하지 않고 나갈 수 있다.
- 회복 물약, 최대 체력 증강, 휴식량 증강, 상점 할인 증강.
- 보스 보상 처리 후 새 필드 생성. 체력·골드·장비·보상은 유지된다.
- 게임오버/탐험 종료 시 이번 런의 보상을 버린다. 새 탐험은 1필드의 기본 상태에서 시작한다.
- 전투 노드마다 다섯 샘플 곡 중 하나를 선택하고 Tap/Hold/Dive/Flick/Shake 슬롯을 생성한다. 같은 전투에서는 곡과 슬롯을 유지한다.
- 정박·엇박·유지 길이·하이라이트 가중치가 다른 16마디 설정과 개발용 마디별 미리보기. 실제 음원은 아직 없다.
- 몬스터 패턴의 전체 리듬, 유지 길이, 전조 선행 시간을 만족하는 후보를 `IEnumerable<PatternPlacement>`로 조회한다.
- 샘플 몬스터 **12종·24개 패턴** 중 곡에 맞는 몬스터를 뽑는다. Tap 테마는 8종이며 정박·Call 응답·트레실로·엇박·긴 쉼·박자 전환·드문 혼합형으로 나뉜다. 몬스터마다 배치 전략을 지정하며 기본은 패턴별 독립 배치다. 일반·엘리트·보스 모두 1필드는 최대 1종, 2필드는 최대 2종, 3필드부터 최대 3종이다.
- 패턴별 Call의 소리·동작을 구분하고, 첫 Response 전에 식별할 준비 시간을 검사한다. 같은 길이의 전조는 신호 종류도 다르다. 거북은 쿵 뒤 꼬리 신호를 확인한 다음 Hold 또는 Hold→Tap으로 대응한다.
- 서로 다른 몬스터의 입력이 겹칠 때 종류가 다르면 충돌로 처리하며, 같은 종류도 누름/떼기와 유지 조건이 호환되어야 공유한다. 몬스터 자체에 작성된 복합 동작은 유지한다. 점유 박자가 많은 몬스터가 해당 공격 묶음과 전조를 통째로 양보하고, 남은 점유량으로 다음 충돌을 비교한다.
- 독립 배치된 같은 몬스터의 두 패턴은 Call/Response와 휴식이 겹치면 같은 입력이어도 하나를 통째로 철회한다. 명시적으로 연결한 종합 배치는 묶음 전체를 함께 철회한다. 준비 화면은 몬스터마다 두 패턴과 각각의 등장 횟수를 보여준다. 곡 전체의 공격 위치를 플레이어에게 펼쳐 놓지 않는다.
- 최종 계획에서 Call·Response가 모두 없는 4박 이상 구간을 보충한다. 전조와 대응을 합쳐 짧은 패턴 → 현재 등장 횟수가 많은 패턴 → 동률 시 시드 추첨 순으로 선택한다. 매번 다시 계산하며 슬롯·충돌·휴식·전주/간주를 지킨다.
- 졸음 슬라임은 Call에서 4박 뒤, 시계 정령은 7박 뒤에 Tap한다. 각각 한 박 뒤 Tap하는 짧은 패턴을 더 자주 사용한다. 긴 쉼은 보충 대상에서 제외한다. 맥은 중간 접근 없이 목표 박자에 실체화하고, 인형은 작은 인형이 한 박씩 걸어오며 카운트를 돕는다. 원본 Call과 Response 수는 그대로다.
- 시소 도깨비는 기본 Tap을 반복하다 마지막 Tap을 반 박 당겨 다음 Call까지 엇박으로 옮기고, 다음 전환에서 정박으로 돌아온다. `IMonsterPatternPlanner`가 몬스터의 두 패턴을 함께 평가한다. 연결된 `PatternChain`은 충돌·공백 보충에서도 하나의 배치 단위다. 현재 샘플에서는 `rapid-drive`의 슬롯이 전체 구간을 수용한다.
- 지도·준비·전투 무대는 HUD 뒤까지 화면 전체를 사용한다. 작은 원형 메뉴 버튼이 우측 상단에 독립적으로 떠 있고, 준비 화면의 시작 버튼도 무대 위에 놓인다. 메뉴를 열어도 선택 중인 보상·스테이지·곡·몬스터 계획은 유지된다.
- 준비 화면에서 시작하는 실제 마우스/터치 연주. 몬스터별 Call·Response·휴식, 진행선, 입력별 결과를 표시한다.
- 제공된 플레이어 캐릭터의 40개 키포즈와 발 피벗·모션별 크기 조절, 기본 몬스터 6종의 투명 이미지와 여섯 Tap 변종의 색상 구분. 몬스터별 Call/공격과 주인공의 왼손·오른손·어퍼, 크로스가드, 덕킹, 점프, 밀쳐내기. 공유 입력의 여러 결과를 동시에 표현하며 Perfect/반미스/Miss의 강도와 색을 구분한다. 노트가 없는 공미스 입력에도 펀치·가드·점프·밀기를 재생하며 판정·피해·반격은 추가하지 않는다. 공미스 가드 해제는 Hold 복귀로 이어지고, 덕킹은 실제 Dive 노트의 유지와 결과에서 재생한다.
- 공격이 없는 박자에도 정박과 엇박 신호가 독립적으로 점멸한다. 배경 박자음과 구분되는 몬스터 Call 합성음을 재생하며, 화면·판정과 같은 DSP 시계를 사용한다.
- 5종 손동작과 공유 입력을 판정한다. 한 번의 누르기나 떼기를 여러 몬스터가 함께 판정할 수 있으며 Dive-Shake-Flick 같은 연속 동작도 지원한다.
- 일시정지/앱 포커스 상실 시 시계와 소리를 멈춘다. 곡 종료 후 정확·반미스·미스와 몬스터별 집계를 보여주고 같은 계획으로 다시 준비한다.
- 판정마다 플레이어 피해를 한 번 적용한다. 소수 HP, 체력 바, 최근 피해 및 회차 누적 피해를 표시한다. 사망 시 남은 노트에 추가 미스를 만들지 않고 연주와 런을 종료한다.

**입력 판정, 2D 전투 연출, 무기 배치·연습, 플레이어 피격·사망과 스테이지 클리어를 구현했다.** 다섯 곡은 BPM/슬롯 설정과 합성 박자음이며 실제 음악 파일은 없다. 모션 이미지 8장과 레퍼런스가 포함되어 있다. 시트가 하나라도 없으면 기존 캐릭터 초상화를 사용한다. 전체 이미지가 설치되면 플레이어는 8개 시트의 40개 키포즈 중 실제 판정에 대응하는 포즈와 복귀 포즈를 교체하며 발 피벗을 공통 지면에 고정한다. 이전의 전신 흔들림·이동·기울기는 제거했다. `Assets/BBSB/Resources/BBSB/BattleArt/PlayerMotionDisplay.asset`에서 지면 위치와 전체·시트·포즈별 배율을 미리보기와 함께 조절한다. 펀치는 연속 중복 없이 선택하고 매 입력마다 짧은 준비 → 뻗기 → 회수로 연결한다. 각 동작의 짧은 스쿼시·스트레치는 발 피벗을 유지하며 `Squash Stretch Strength`로 강도를 조절한다. Dive/Flick 미스 뒤의 앉기는 다음 입력까지 시간이 있을 때만 보여준다. 몬스터는 기존 컷아웃 모션을 사용한다. 프레임 대응과 가져오기 규칙은 [PlayerAnimation.md](Docs/PlayerAnimation.md)에 있다. **8종 무기의 고유 패턴, 효과, 공격 모션과 스테이지 공유 HP를 구현했다.** 배치한 무기의 성공 판정이 공격 또는 방어막을 발동한다. 적 HP가 0이면 새 공격과 피해를 멈추고 현재 패턴의 Overkill을 마친 뒤 보상 화면으로 이동한다. 마지막 입력 성공 시 콘페티가 나오며 실패해도 승리는 유지된다. 곡 종료 시 적 HP가 남으면 양쪽 HP와 배치를 유지한 채 다시 준비한다. [무기 규칙과 수치](Docs/Weapons.md)를 참고한다. 전용 전조 음원과 관절 애니메이션도 후속 작업이다.

현재 12종·24개 패턴을 [리듬 몬스터 걸 종족 개편안](Docs/MonsterGirls.md)으로 정리했다. 종족마다 신체·성격에서 리듬과 공격이 나오며, 같은 입력도 서로 다른 형태로 표현한다. [공격 표현 명세](Docs/MonsterAttacks.md)는 대응의 경향과 Perfect/반미스/Miss 결과를 다룬다. 새 종족 이름·PNG는 후속 작업이다. **36개 공격 이미지 슬롯과 종족별 이동·판정 연출**은 런타임에 연결했고, 파일이 없으면 도형으로 표시한다. [이미지 폴더·파일명·위치 조절 안내](Docs/MonsterAttackArt.md)에 따라 PNG를 넣으면 전투와 연습에 자동 적용된다.

## 임시 콘텐츠와 조정 값

- 첫 필드부터 매 필드 6단계, 총 21개 노드 중 보스 한 노드. 시작 선택지는 4개다. 최종 필드 수는 아직 정하지 않았으므로 보스 후 다음 필드로 반복한다.
- 시작 HP 100, 골드 60, 휴식 30%: 씬의 `RunBootstrap` Inspector에서 변경.
- 샘플 몬스터의 판정당 기본 피해는 4. `MonsterDefinition`의 `damagePerNote` 인자로 몬스터마다 지정할 수 있다. HP와 피해는 `decimal`로 계산하므로 기본 피해 3의 반미스 1.5도 반올림 없이 누적한다. 퍼펙트는 피해를 완전히 무효화한다.
- `Use Fixed Seed`를 켜면 같은 시드로 재현 가능. 기본은 새 탐험마다 다른 시드다.
- 시작 무기 다섯 개, 상품 이름/설명, 가격, 회복량, 보상 골드는 샘플 값이다. 확정된 전투 밸런스가 아니다.
- `ContentCatalog.cs`에서 샘플 아이템을, `MapGenerator.cs`에서 노드 종류의 분포를 변경한다.
- 첫 단계는 몬스터 4개다. 2~5번째 단계에는 몬스터 8개와 엘리트·강화·휴식·상점 각각 2개를 섞고, 단계마다 한 곳을 물음표로 가린다. 이는 초기 테스트용 분포다.
- 물음표의 실제 종류는 맵 생성 시 고정한다. 지도 조회·메뉴·잘못된 진입으로는 공개되지 않으며, 성공적으로 진입한 뒤 기존 전투/서비스 흐름으로 이어진다. 같은 시드로 재시작하면 배치와 정체는 같고 다시 가려진다.
- 일반 단계 사이의 앞/인접 라인을 후보로 연결한 뒤 10개 후보 중 4~5개만 남긴다. 모든 노드의 진입/퇴로, 실제 경로별 상점·휴식 제한을 만족하도록 전체 연결을 탐색한다. 각 단계 사이에서 같은 라인의 직선 연결도 최소 하나 제거한다.
- 상점·휴식 제한은 물음표 속 결과까지 포함한 경로별 제한이다. 서로 다른 경로에는 여러 개가 배치될 수 있고, 다음 필드에서는 다시 만날 수 있다. 연결 불가능한 분포의 재배치는 횟수를 제한하며 마지막에는 각 서비스 종류를 한 단계에 모아 유효한 연결을 보장한다.
- 강화 1단계당 무기의 피해·완주 보너스·방어막이 25% 증가한다. 최대 +3이다.
- 회복 물약은 현재 전투 밖에서만 사용 가능. 저장/불러오기, 앱 재시작 후 런 복원, 영구 성장, 최종 엔딩은 아직 없다.

대화에서 확정한 리듬 전투 규칙은 [Docs/Design.md](Docs/Design.md)에 보존했다.
다섯 곡의 설정과 몬스터 배치를 위한 API 예시는 [Docs/MusicStages.md](Docs/MusicStages.md)에 있다.
샘플 몬스터와 계획 생성/양보 규칙은 [Docs/MonsterPlans.md](Docs/MonsterPlans.md)에 있다.
연주 조작, 판정 수치와 재생 구조는 [Docs/RhythmPlayback.md](Docs/RhythmPlayback.md)에 있다.
전투 무대, 입력별 모션, 시간 동기화와 아트 경로는 [Docs/BattlePresentation.md](Docs/BattlePresentation.md)에 있다.

## 구조와 전투 연결

| 파일/폴더 | 역할 |
|---|---|
| `Assets/BBSB/Core` | Unity에 의존하지 않는 맵·음악 슬롯 생성, 몬스터 계획/충돌 중재, 리듬 판정, 런 상태, 보상 규칙 |
| `Assets/BBSB/Runtime/RunBootstrap.cs` | 씬 진입점, 초기 값, 한글 폰트, 입력 모듈 |
| `Assets/BBSB/Runtime/RunPresenter.cs` | 화면 구성과 사용자 명령 전달 |
| `Assets/BBSB/Runtime/RhythmPlayback.cs` | 한 회차의 DSP 시계, 포인터 입력과 일시정지, 종료 전달 |
| `Assets/BBSB/Runtime/UI` | 레이아웃, 노드 연결선, 안전 영역, 몬스터 패턴 카드와 개발용 슬롯 미리보기 |
| `Assets/BBSB/Runtime/UI/BattleArenaView.cs` | 현재 계획/판정에서 몬스터와 주인공의 포즈·효과를 구성 |
| `Assets/BBSB/Resources/BBSB/BattleArt` | 주인공과 몬스터 6종의 투명 Sprite 원본 |
| `Assets/BBSB/Tests` | EditMode 핵심 규칙 테스트와 PlayMode UI 연결 테스트 |

`RunPresenter.BattleRequested(ticket, stageKind, fieldNumber)`는 전투 노드 진입을 알린다. 준비 화면의 `StartRhythmRound()`는 `RunSession.StartRhythmRound()`를 통해 `Session.BattlePlan`으로 새 회차를 만들며 `ActiveRound`에서 조회할 수 있다. 세션은 활성 회차의 `ResultJudged`를 구독하여 HP를 즉시 차감하고, 종료·중단·런 재시작 시 구독을 해제한다. 준비 미리보기용으로 직접 만든 `RhythmRound`는 세션 HP를 바꾸지 않는다. 무기 효과 계층이 기존 몬스터 판정을 공유하여 적 공용 HP와 승리를 판정한 뒤 `SubmitBattleResult(ticket, victory, remainingHealth)`로 결과를 돌려준다. `remainingHealth`는 소수 HP를 보존하는 `decimal`이며, 고유 ticket이 이전 스테이지/런의 늦은 결과나 중복 보상을 거부한다.

`BattleRequested`가 호출될 때 `Session.BattleMusic`에 곡과 슬롯, `Session.BattlePlan`에 배치된 몬스터·전체 공격 묶음·시간순 Call 신호가 준비되어 있다. 같은 전투의 준비/연주 반복은 이 객체들을 재사용한다. 스테이지 종료, 게임오버, 런 재시작 시 해제된다. 개발용 샘플 곡 둘러보기는 실제 전투의 음악이나 몬스터 계획을 변경하지 않는다.

맵 난수와 보상 난수는 분리되어 있고, 음악 선택은 런 시드와 필드/노드 위치로 독립적으로 결정된다. 상점을 들르거나 다른 종류의 보상을 받았다고 다음 필드 맵이 달라지지 않는다. `RunSession`은 플레이어 피격을 실시간 반영하며, 보상과 다음 스테이지 이동은 스테이지 전체의 승리 결과가 제출된 뒤 처리한다.

`StageNode.Kind`는 맵 생성 때 정한 실제 결과다. 지도에는 `MapKind`를 사용한다. 미공개 지역은 `StageKind.Mystery`이며 `RunSession.Enter()`가 성공한 뒤에만 실제 종류로 표시된다. `IsMystery`는 원래 물음표였는지, `IsRevealed`는 공개되었는지를 나타낸다. 숨겨진 종류를 확인하느라 플레이 중 맵 난수를 추가로 소비하지 않는다.

## 검증

탐험 검증은 1,000개 시드에서 시작 몬스터 4개·6번째 보스·막다른 길 부재를 확인한다. 경로별 상점·휴식 제한은 음수/경계 시드와 연속 4개 필드, 숨겨진 서비스까지 포함한다. 물음표의 잘못된 진입 거부·진입 시 공개·5종 결과의 전투/서비스 연결·지도 복귀 후 유지·같은 시드 재시작도 확인했다.

핵심 로직은 .NET 8에서 실행해 **157개 테스트 통과**. 탐험 21개, 음악 11개, 몬스터 계획 14개, 몬스터 테마 7개, 전조 구분 10개, 빈 구간 보충 13개, 입력 판정 25개, 플레이어 피해 13개, 긴 쉼 6개, 몬스터 종합 배치 9개, 플레이어 모션 17개, 포즈 크기 계산 3개, 몬스터 전진·복귀와 측면 배치 6개, 공격 궤적과 중앙 공간 2개다. 24개 패턴의 배치 가능성, Tap 등장 비중, 자기 패턴 중첩, 트레실로/엇박 위치와 Shake 한 번 왕복을 확인했다. 구분이 늦거나 문구만 다른 전조를 거부하며, 거북의 두 패턴이 같은 곡에서 배치·판정되는지도 확인했다. 빈 구간 보충의 4박 경계·선택 순서·동률 추첨·앞뒤 휴식·반복 계산과 추가된 Call/판정도 검증했다. 긴 쉼의 4박·7박 대응, 중간 Call 부재, 한 몬스터의 복수 쉼 거부, 보충 시 보호와 짧은 패턴의 실제 등장 우위도 확인했다. 종합 배치는 정박→엇박→정박 전환, 실제 13회 Tap 판정, 연결 구간의 일괄 철회와 보충, 사용자 정의 배치 전략과 가변 길이 후보의 짧은 순 선택도 확인했다. 기존 리듬·맵·배치 검증에 더해 퍼펙트 무피해·반미스 절반 피해와 HP 1에서의 연속 퍼펙트 연주, 소수 피해, 공유 입력의 개별 피해, 중복 방지, 유지 입력의 최종 판정, 일시정지, 중도 복귀와 재연주의 HP 유지, 사망 즉시 중단, 이전 회차 무효화 및 소수 HP 회복을 확인한다.

```sh
dotnet run --project Tools/CoreChecks/BBSB.CoreChecks.csproj --configuration Release
```

Unity에서는 **Window → General → Test Runner**에서 EditMode의 `BBSB.Core.Tests`, PlayMode의 `BBSB.UI.Tests`를 실행한다. PlayMode에는 21개 맵 노드의 배치와 비중첩, 물음표 표시·진입·복귀, 연주/박자/결과/재준비, 포인터와 일시정지, 외부 승패, 가로 레이아웃과 메뉴, 캐릭터 모션 검증이 있다. Call 합성음의 안정적인 구분과 거북의 대응 전 꼬리 모션 검증도 추가했다. 긴 쉼의 정적인 안내와 대응 직전 공격 준비 동작 억제도 검사한다. 연결된 Call과 현재 Tap을 함께 표시하는 PlayMode 테스트도 추가했다. 체력 HUD의 수치·비율과 입력 통과, 준비 복귀 시 HP 유지, 사망 시 연주 해제와 게임오버 표시도 추가했다. 발 피벗·원본 Sprite 재사용·포즈와 배율 변경·일시정지 중 화면 크기 변경 테스트도 추가했다. 작업 환경에는 Unity Editor가 없어 **Unity 컴파일·PlayMode 테스트·모바일 빌드는 아직 실행하지 못했다.** `RunMap`의 16:9와 16:10 Game 뷰에서 판정별 HP 감소, 메뉴/재준비 시 HP 유지, 사망을 확인한다.

한글 글꼴은 OFL 라이선스의 Noto Sans CJK KR 일부를 `BBSB UI`로 이름을 바꿔 포함했다. 새 한글 텍스트를 넣을 때는 `Tools/subset_font.py`로 글자 집합을 갱신한다. 출처와 라이선스는 폰트 폴더에 있다.
