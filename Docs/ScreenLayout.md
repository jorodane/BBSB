# 전체 화면 구성과 메뉴

지도, 준비, 연주는 각각 하나의 화면을 사용한다. 상시 장비 바와 긴 설명으로 주 화면을 줄이지 않고, 추가 정보는 우측 상단 **메뉴**로 연다.

| 화면 | 기본 표시 | 추가 정보 / 동작 |
|---|---|---|
| 스테이지 선택 | 필드·HP·골드, 남은 영역 전체의 지도, 진행 방향 | 메뉴의 장비·가방·증강, 조작 방법, 탐험 종료 |
| 준비하기 | 곡·BPM, 큰 캐릭터 무대, 하단 연주 시작 | 몬스터 패턴 버튼 또는 메뉴에서 전조·대응·휴식 확인 |
| 연주 | 곡 진행, 정박·엇박 신호, 큰 전투 무대, 현재 판정, 접촉/Shake 비율 | 메뉴에서 일시정지, 연주 정보·패턴, 조작 방법, 박자음, 준비로 돌아가기 |
| 상점·강화·휴식·보상·결과 | 해당 화면의 내용과 행동 | 긴 목록만 스크롤, 장비와 탐험 종료는 메뉴 |

**개발 도구**는 전투의 준비/결과 메뉴에서만 보이며 `Show Battle Test Controls`가 켜져 있어야 한다. 슬롯 미리보기, 샘플 곡 탐색과 테스트용 승패 처리를 이곳으로 옮겼다.

## 크기와 입력

- CanvasScaler는 짧은 변을 720 UI 단위로 유지한다 (`ScaleWithScreenSize`, `720 × 720`, `Expand`). 9:16 세로 화면뿐 아니라 16:9·정사각형 Game 뷰에서도 같은 기준으로 조작 요소의 크기를 정한다.
- 안전 영역을 채우는 화면에 작은 헤더와 필요한 행동만 고정하고 지도/캐릭터 무대가 나머지 높이를 받는다. 지도 노드는 지도 크기에 비례해 커지며 스크롤하지 않는다. 준비 화면의 시작 버튼도 스크롤 밖에 있다.
- 캐릭터 배치는 RectTransform 크기가 바뀔 때 다시 계산한다. 준비 화면의 정지 미리보기와 일시정지 상태도 화면 크기 변경에 대응한다.
- 탐험 메뉴는 현재 화면 위에 열리고 아래 화면의 CanvasGroup이 클릭과 선택을 막는다. 단순히 열고 닫을 때 화면을 다시 만들지 않아 지도, 보상 교체 선택, 스크롤 위치와 전투 계획을 유지한다.
- 연주 메뉴를 열면 기존 DSP 시계, 박자음, 판정과 모션이 함께 멈춘다. 메뉴를 탐색하는 동안 리듬 입력을 받지 않는다. 이어하기 후 유지 입력 재접촉을 기다리는 도중에도 다시 메뉴를 열 수 있다.
- 메뉴 버튼을 제외한 연주 화면은 기존처럼 한 입력 영역이다. Shake 진행 비율과 50%/75% 기준은 주 화면에 남는다. Esc로 탐험 메뉴를 열고 닫거나 연주를 일시정지/재개할 수 있다.

## 검증

기존 PlayMode 테스트를 새 메뉴 경로에 맞췄다. 720×1280, 1280×720, 720×720 논리 뷰포트에서 지도·무대의 공간 점유, 노드/입력 표시/시작 버튼의 영역 내 배치, 메뉴 아래 노드 입력 차단, 메뉴를 닫은 뒤 동일 화면·계획 보존, 재접촉 대기 중 메뉴 재진입과 입력 차단을 확인하도록 했다.

작업 환경에는 Unity Editor가 없어 PlayMode 실행과 실제 화면의 시각 검증은 수행하지 못했다. C# 구문 검사와 기존 핵심 로직 테스트는 별도로 실행하며, 실제 화면은 Unity Test Runner의 `BBSB.UI.Tests` 및 `RunMap`의 세로/가로 Game 뷰에서 확인한다.
