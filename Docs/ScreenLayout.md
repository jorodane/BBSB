# 전체 화면 구성과 메뉴

지도, 준비, 연주는 **16:9·16:10 가로 전체 화면**을 사용한다. 지도와 전투 장면이 화면을 채우고, 상태 정보와 작은 원형 메뉴 버튼이 그 위에 겹쳐 표시된다. 장비와 긴 설명은 우측 상단 **메뉴**로 연다.

| 화면 | 기본 표시 | 추가 정보 / 동작 |
|---|---|---|
| 스테이지 선택 | 왼쪽에서 오른쪽으로 진행하는 전체 지도, 좌측 상단 필드·HP·골드 | 메뉴의 장비·가방·증강, 조작 방법, 탐험 종료 |
| 준비하기 | 전체 전투 장면, 좌측 앞의 주인공과 우측 몬스터, 곡·BPM, 우측 하단 연주 시작 | 몬스터 패턴 버튼 또는 메뉴에서 전조·대응·휴식 확인 |
| 연주 | 전체 전투 장면 위에 곡 진행·정박/엇박 신호, 좌측 상단 HP 바·최근 피해, 우측 하단 현재 판정·접촉/Shake 비율 | 메뉴에서 일시정지, 연주 정보·패턴, 조작 방법, 박자음, 준비로 돌아가기 |
| 상점·강화·휴식·보상·결과 | 해당 화면의 내용과 행동 | 긴 목록만 스크롤, 장비와 탐험 종료는 메뉴 |

**개발 도구**는 전투의 준비/결과 메뉴에서만 보이며 `Show Battle Test Controls`가 켜져 있어야 한다. 슬롯 미리보기, 샘플 곡 탐색과 테스트용 승패 처리를 이곳으로 옮겼다.

## 크기와 입력

- CanvasScaler의 기준 해상도는 `1280 × 720`이며 `ScaleWithScreenSize`와 `Expand`를 사용한다. 16:9는 1280×720, 16:10은 1280×800의 논리 영역으로 표시하여 더 넓은 세로 공간을 장면에 사용한다. PC와 Web 기본 창도 1280×720이다.
- 모바일은 가로 방향으로 시작하며 양쪽 가로 회전을 허용하고 세로 회전은 막는다. 노치와 시스템 영역에는 기존 `SafeAreaPanel`을 적용한다.
- 주 화면 루트에는 `LayoutGroup`을 두지 않는다. 지도/전투 무대는 안전 영역 전체에 Stretch하고, 메뉴·상태·박자·판정·행동 버튼은 같은 루트 아래 별도 형제 요소로 배치한다. 상단 표시가 장면 높이를 차지하지 않는다.
- 전투는 바닥이 조금 보이는 고정 측면 구도다. 플레이어는 좌측, 몬스터는 우측의 깊이가 다른 자리에 선다. 패턴을 발동하는 몬스터는 첫 Call부터 한 걸음 전진해 패턴 전체를 수행하고 복귀한다. 배우 레이어는 접지점의 높이로 정렬하며, 이름표는 별도 상위 레이어에서 해당 위치를 따라간다. 지면 그림자와 공격 효과도 이동한 위치를 공유한다.
- 원형 메뉴는 80×80 UI 단위이며 우측 상단에서 20 단위 안쪽에 놓인다. 원 바깥의 투명 모서리는 입력을 가로채지 않는다. 연주 화면에서는 나머지 표시도 입력을 통과시킨다.
- 지도는 왼쪽의 몬스터 시작점 네 곳에서 오른쪽의 6번째 단계 보스로 진행한다. 앞의 다섯 단계는 위아래 네 개 노드로 나뉘며 보스는 경로의 세로 중앙에 놓인다. 노드와 연결선이 같은 좌표를 사용하고, 전체 21개 노드는 HUD와 겹치지 않게 스크롤 없이 배치한다. 준비 화면의 시작 버튼은 우측 하단에 독립적으로 고정한다.
- 미공개 지역은 실제 종류 대신 `?`로 표시한다. 노드 색상이나 버튼 이름에도 숨겨진 종류를 넣지 않는다. 실제로 들어간 지역은 원래 종류로 표시하며, 지도 하단과 조작 방법에서 물음표의 의미를 안내한다.
- 캐릭터 배치는 RectTransform 크기가 바뀔 때 다시 계산한다. 준비 화면의 정지 미리보기와 일시정지 상태도 화면 크기 변경에 대응한다.
- 탐험 메뉴는 현재 화면 위에 열리고 아래 화면의 CanvasGroup이 클릭과 선택을 막는다. 단순히 열고 닫을 때 화면을 다시 만들지 않아 지도, 보상 교체 선택, 스크롤 위치와 전투 계획을 유지한다.
- 연주 메뉴를 열면 기존 DSP 시계, 박자음, 판정과 모션이 함께 멈춘다. 메뉴를 탐색하는 동안 리듬 입력을 받지 않는다. 이어하기 후 유지 입력 재접촉을 기다리는 도중에도 다시 메뉴를 열 수 있다.
- 메뉴 버튼을 제외한 연주 화면은 기존처럼 한 입력 영역이다. Shake 진행 비율과 50%/75% 기준은 주 화면에 남는다. Esc로 탐험 메뉴를 열고 닫거나 연주를 일시정지/재개할 수 있다.

기존 상단 줄이 크게 늘어난 원인은 중첩된 LayoutGroup의 여유 높이 배분이었다. 목록과 메뉴에 남아 있는 공용 `Size`는 `flexibleHeight = 0`을 명시하고, 늘어날 스크롤 영역만 1로 설정한다. 공용 가로줄도 자식의 너비를 강제로 확장하지 않아 닫기 버튼의 지정 너비를 지킨다. 지도/전투에는 이 줄 배치 자체를 사용하지 않는다.

## 검증

PlayMode 테스트는 1280×720, 1280×800 및 안전 영역을 줄인 1220×680 논리 뷰포트를 사용한다. 지도·무대의 너비와 높이가 뷰포트와 정확히 일치하는지, 메뉴가 별도 원형 요소인지, 주인공과 몬스터가 좌우로 나뉘는지 확인하도록 했다. 노드/박자/입력 표시/시작 버튼의 영역 내 배치, 가로 경로 연결, 원형 메뉴의 모서리 입력 통과, 메뉴 아래 노드 입력 차단, 메뉴를 닫은 뒤 동일 화면·계획 보존과 재접촉 대기 중 메뉴 재진입 검증도 포함한다.

6단계 지도에는 시작 전투 버튼 4개, 전체 노드 21개, 노드끼리 및 HUD/메뉴와의 비중첩 검사도 추가했다. 물음표가 진입 직전까지 유지되는지, 진입 후 실제 전투/서비스를 열고 지도 복귀 시 공개된 이름이 남는지를 확인하는 테스트도 작성했다.

작업 환경에는 Unity Editor가 없어 PlayMode 실행과 실제 화면의 시각 검증은 수행하지 못했다. C# 구문 검사는 별도로 실행하며, 실제 화면은 Unity Test Runner의 `BBSB.UI.Tests` 및 `RunMap`의 16:9·16:10 Game 뷰에서 확인한다.
