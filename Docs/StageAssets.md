# 장르 맵과 80개 음악 스테이지

탐험 시작 화면에서 랜덤 또는 팝·R&B·재즈·랩·바드코어·켈틱·뉴에이지·메탈을 선택한다. 선택한 장르는 첫 필드에 적용되며, 이후 필드는 시드로 섞인 나머지 장르로 넘어간다. 8개 장르를 돈 뒤 같은 순서가 반복된다.

장르마다 서로 다른 스테이지 10개를 보유한다. 기존 4갈래 입구와 6단계 분기 경로는 유지한다. 카탈로그의 10곡은 한 필드에서 반드시 10번 전투한다는 뜻이 아니다. 필드를 만들 때 모든 전투 노드에 `SongId`를 배정한다. 현재 장르의 곡만 사용하며, 노드에 들어가거나 준비 화면으로 돌아와도 곡을 다시 뽑지 않는다. 미확인 지역은 입장 전 곡 이름도 숨긴다.

## 에셋 설치

별도로 전달하는 `BBSB_Stage_Assets_v1.zip`을 푼다. ZIP 안의 `Assets` 폴더를 Unity 프로젝트의 같은 위치에 병합한다. `Assets/BBSB/Resources/BBSB/StageAssets/<ID>/`에 `background.png`와 `music.ogg`가 한 쌍으로 들어간다. 새로운 한글 스테이지 이름을 지원하는 `Fonts/BBSBUI.otf`도 함께 적용한다. 폰트의 기존 `.meta` GUID는 유지한다.

코드를 먼저 갱신한 다음 에셋을 넣으면 `StageAssetImporter`가 배경과 음원의 초기 임포트 설정을 적용한다. 이미 아티스트가 수정한 임포트 설정은 덮어쓰지 않는다. Unity 메뉴 **BBSB → Validate stage asset pack**은 80쌍 누락과 음악 길이를 검사한다.

에셋 없이도 기존 개발용 기본 배경과 박자 안내음으로 프로젝트를 실행할 수 있다. 실제 곡과 그림을 확인하려면 ZIP을 설치해야 한다. 이미지·음악 폴더와 작곡 원본은 `.gitignore`에서 제외한다. 새 음원과 이미지는 Git에 올리지 않는다.

## 곡과 박자

80곡 모두 44.1 kHz 스테레오 OGG이며 정확히 80초다. 직접 작성한 멜로디·화음·베이스·퍼커션 악보를 합성 악기로 렌더링한 오리지널 인스트루멘털 v1이다. 외부 곡이나 녹음 샘플을 사용하지 않았다. ZIP의 `StageAssetSources/<ID>/`에는 MIDI, 악기별 노트 원본, 후크 시간표가 들어 있다. `preview.html`을 열면 배경과 곡을 함께 확인하고 각 후크로 이동할 수 있다.

4/4와 3/4의 BPM은 4분음표 기준이다. 6/8은 점4분음표 BPM으로, 한 마디에 큰 박 두 개가 있다. MIDI는 4분음표 BPM을 1.5배로 기록해 같은 재생 시간을 유지한다. 게임의 한 틱은 표시된 큰 박의 1/4이고, 몬스터 Call과 Response는 기존 상대 간격을 유지한다. 음악의 장식적인 셋잇단음은 플레이어에게 별도의 미표시 입력을 요구하지 않는다.

각 곡에 4마디 후크가 3번 있다. 도입·중간 전개·후크 복귀·마무리를 악기 수, 리프, 드럼 필로 구분한다. 작은 퍼커션으로 모든 큰 박을 유지한다. MIDI·JSON·C# 카탈로그는 같은 마디 위치를 사용한다.

## 후크 패턴 보장

`MusicSection.IsHook`는 음악의 실제 후크 구간이다. 몬스터 선택 → 독립 제안 → 충돌 중재 → 빈 구간 보충 뒤 `HookPatternGuarantee.Ensure`가 모든 후크를 검사한다. 후크 안에서 시작해 그 안에서 Response가 끝나는 완전한 패턴을 최소 하나 보장한다. 누락되면 시드가 정한 후보를 예약하고, 충돌하는 기존 공격을 조정한다. 사전 Call, 입력 호환성, 몬스터 휴식, 연결 패턴 전체를 보존한다. 긴 연결 패턴이 여러 후크를 충족하면 재사용하고 중복 삽입하지 않는다. 높은 가중치만으로 출현을 약속하지 않는다.

이 규칙은 생성된 전투 계획에 대한 보장이다. 이미 승리했거나 플레이어가 사망해 연주가 끝난 이후의 후크에서는 공격을 다시 시작하지 않는다.

## 화면과 재생

전투 준비와 전투 본화면이 같은 `StageDefinition.BackgroundPath`를 사용한다. 그림에 그려진 바닥의 형태가 그 곡의 전투 필드이며, 캐릭터의 기존 지면 위치와 접지 그림자는 유지한다. 바닥의 형태는 플랫폼 이동이나 충돌 장애물을 추가하지 않는다.

`StageMusicPlayer`는 판정에 쓰는 `AudioSettings.dspTime` 시작점으로 `PlayScheduled`를 호출한다. 일시정지 시 음원을 멈추고, 재개 시 동결된 시간의 샘플 위치부터 같은 시계로 다시 시작한다. 유지 입력 재접촉을 기다리는 동안 음악도 기다린다. 연습 반복은 같은 클립의 80초 루프를 사용한다. 실제 녹음이 있으면 개발용 메트로놈은 끄고 몬스터 Call만 함께 재생한다. 음악·Call 음소거는 시간을 바꾸지 않는다.

## 검증

순수 C# 검사 226개 통과. 80곡 × 일반/보스 조건, 모든 후크의 완전한 Response, 공격 간 충돌, 3/4·6/8, 8개 맵의 선택·배정 재현성, 12종의 연결 패턴 보존을 검사했다. Core·Runtime·Unity EditMode/PlayMode 테스트 소스도 참조 컴파일했다. Unity Editor의 실제 화면과 오디오 장치 지연은 이 환경에서 실행하지 못했다.

Unity에서는 ZIP 설치 후 8개 맵을 각각 선택해 배경과 음악을 확인하고, 후크 전후·일시정지·유지 입력 재개·연습 루프를 실제 장치에서 점검한다. 테스트용 5곡은 슬롯/도감 개발 도구와 회귀 검사에 계속 남아 있다.
