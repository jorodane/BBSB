# 플레이어의 대응으로 막는 몬스터 공격

상태: **공격 표현 명세**. 현재 런타임의 공통 공격 화살표를 아래 형태로 교체하기 위한 문서다. 새 투사체·차단·회피 연출은 아직 구현하지 않았다. Tap의 파괴·빗겨나감 예시를 기준으로, 나머지 네 종류는 기존 플레이어 포즈와 판정에 맞춘 1차 표현안이다.

몬스터의 공격이 중앙을 지나 플레이어에게 다가오며 리듬 노트의 역할을 한다. 플레이어가 그 공격을 때려 부수거나, 막거나, 피하거나, 밀쳐내는 모습으로 대응 결과를 보여준다. 대응 판정에 연결된 무기들은 동시에 각자의 효과를 발동한다.

## 입력별 공격과 결과

| 입력 / 신체 동작 | 공격의 형태 | Perfect | HalfMiss | Miss |
|---|---|---|---|---|
| Tap / 펀치 | 주먹 높이로 날아오는 작고 부서지는 투사체 | 주먹과 접촉한 자리에서 완전히 부서진다 | 주먹 가장자리에 비껴 맞아 궤도가 틀어지고, 남은 덩어리가 팔이나 몸을 스친다 | 펀치가 빗나가거나 늦어 투사체가 몸통에 맞는다 |
| Hold / 크로스가드 | 정해진 구간 동안 밀려오는 굵은 압력파·분사 | 교차한 팔 앞에 막혀 양옆으로 흩어지다 구간 끝에 잦아든다 | 가드가 밀리며 일부 압력이 몸에 닿는다 | 가드가 열리거나 유지가 끊겨 압력을 그대로 받는다 |
| Dive / 덕킹 | 머리 높이를 정해진 시간 동안 훑고 지나가는 긴 상단 파동 | 시작에 숙이고 끝까지 낮춘 자세로 통과시킨 뒤 정해진 떼기에 일어난다 | 늦게 숙이거나 끝 타이밍을 놓쳐 머리가 파동의 앞·뒤 가장자리에 스친다 | 숙이지 못하거나 중간에 일어나 상단 공격에 맞고 넘어진다 |
| Flick / 점프 | 발목 높이로 다가오는 낮은 충격파·구르는 고리 | 목표 박자에 뛰어넘어 발아래로 통과시킨다 | 다리가 공격 끝에 걸려 공중에서 균형을 잃는다 | 발이 걸리거나 몸이 부딪혀 앞으로 넘어진다 |
| Shake / 양손 밀쳐내기 | 플레이어 앞까지 밀려오는 크고 탄성 있는 방울·덩어리 | 인정 구간 안에서 한 번 밀었다 돌아와 앞에서 튕겨낸다 | 바깥으로 밀기만 성공해 일부가 튕겨나가고 남은 압력을 접힌 팔로 받는다 | 유효한 밀기가 없어 덩어리가 양팔을 벌리고 몸에 부딪힌다 |

Tap의 성공은 투사체의 파괴, Shake의 성공은 큰 덩어리의 밀려남으로 구별한다. Hold는 앞에서 계속 받아내는 접촉, Dive는 머리 위 통과, Flick은 발아래 통과로 구별한다. 몬스터별 색을 제거해도 모양·높이·지속 시간과 접촉 결과로 대응 종류를 읽을 수 있어야 한다.

반미스의 빗겨나감은 확률적 완전 회피가 아니다. 일부 접촉이 남았다는 표현이며 기존 공격 효과의 50%를 적용한다. 기본 피해는 Perfect 0%, HalfMiss 50%, Miss 100%이고, 이후 방어막이 남은 피해를 흡수한다. 방어막이 모두 흡수했으면 가드가 불완전했더라도 별도의 방어막 접촉 효과로 HP 피해가 없었던 이유를 보여준다. 시각 효과 자체가 피해를 계산하지 않는다.

## 현재 몬스터에 적용할 외형

입력과 간격은 현재 `MonsterCatalog`의 12종·24개 패턴을 따른다. 아래 재질·형상은 그 리듬을 보여줄 외형안이다. 같은 몬스터라도 혼합 패턴에서는 각 단계의 입력에 맞는 공격을 사용한다.

| 몬스터 ID / 이름 | 공격 외형안 | 기존 패턴에 적용 |
|---|---|---|
| `tap-slime` / 통통 슬라임 | 얇은 껍질이 있는 작은 젤리탄 | 두 패턴의 단발 Tap에 한 발씩 |
| `march-slime` / 행진 슬라임 | 단단한 작은 젤리탄 행렬 | 세 번 연사 또는 사이를 비운 두 발 |
| `tresillo-bat` / 춤추는 박쥐 | 깨지는 작은 결정탄 | 3+3+2 또는 3+2+3 간격의 세 발 |
| `offbeat-goblin` / 뒷박 도깨비 | 부서지는 작은 돌탄 | 엇박의 한 발 또는 두 발 |
| `drowsy-slime` / 졸음 슬라임 | 작은 수면 방울탄 | 단발 Tap; 긴 쉼에는 접근 전조 생략 |
| `clock-spirit` / 시계 정령 | 깨지는 시계 결정탄 | 단발 Tap; 일곱 박 쉼에는 접근 전조 생략 |
| `seesaw-goblin` / 시소 도깨비 | 작은 돌탄 | 기존 정박·엇박 전환 간격을 그대로 표현 |
| `spark-bat` / 반짝 박쥐 | 결정탄 / 굵은 전기 압력파 | 빠른 Tap 두 발 / 1박 Hold 분사 |
| `iron-turtle` / 철갑 거북 | 두꺼운 압력파 / 꼬리가 튕기는 작은 갑각 조각 | 2박 Hold; 꼬리 패턴은 한 박 쉬고 Tap 한 발 |
| `diving-ray` / 잠수 가오리 | 머리 높이를 가르는 넓고 긴 수평 파동 | 4박 또는 2박 동안 덕킹 후 정해진 떼기 |
| `bubble-spirit` / 방울 정령 | 밀면 찌그러졌다 튕겨나는 큰 방울 | 1박 안에 왕복 한 번; 둘째 패턴은 사이를 비워 두 번 |
| `flick-goblin` / 튕김 도깨비 | 지면을 따라 오는 낮은 충격파 고리 | 정박 또는 엇박의 Flick 시점에 발밑 통과 |

## 도착 박자와 유지 구간

- Call의 소리·포즈와 패턴 구별 규칙은 기존 계획을 따른다. 공격이 날아오는 모습은 해당 Call 이후의 공격 준비와 연결하고, 정상 패턴의 선두가 판정 지점에 도착하는 시각을 기존 Response 시작 박자에 맞춘다. 화면 거리나 종횡비 때문에 요구 박자를 바꾸지 않는다.
- Tap/Flick은 한 공격의 도착 박자를 읽게 한다. Hold/Dive는 선두가 시작 박자, 접촉 또는 통과가 끝나는 후미가 종료 박자를 나타낸다. 유지 입력의 시작·끝에 각각 다른 피해 투사체를 만들지 않는다. 한 `ResponseNote`의 피해 판정은 한 번이다.
- Hold가 끝나는 시각에 가드를 풀어도 되고, Dive는 기존 규칙대로 정해진 끝 박자에 떼어야 한다. 상단 파동의 후미가 지나가는 모습을 Dive의 종료 동작과 연결한다.
- Shake의 방울은 인정 구간에 한 번 밀었다 돌아오는 동작을 받는다. 왕복 완료 뒤 계속 흔들거나 누르고 있을 필요가 없다. 실제 진행도에 따라 방울이 눌리고 밀려나는 중간 상태를 보여주고, 구간 끝의 최종 `RhythmResult`로 성공·반미스·미스와 효과를 확정한다. 시작 박자에 정확히 눌러야 한다는 새로운 조건을 만들지 않는다.
- 허용된 이른·늦은 입력은 판정 지점 주변의 짧은 접촉 연출로 받아낸다. 최종 Grade와 접촉 결과는 실제 결과가 나온 뒤 결정한다. 투사체의 화면 위치로 성공 여부를 다시 계산하지 않는다.
- 너무 이른 입력으로 Miss가 먼저 확정되어도 공격을 미리 삭제하거나 파괴 성공을 재생하지 않는다. 빗나간 동작 뒤에도 해당 공격의 접근·피격 흐름은 남으며 재입력으로 결과를 바꾸지 않는다. 기존 피해 계산 시각과 판정 창은 유지한다.
- Tap의 짧은 준비 → 펀치 → 회수에 맞춰 접촉과 파편을 표시한다. 준비 자세에서 투사체가 이미 완전히 사라지지 않게 하고, 시각 효과를 맞추기 위해 입력 판정이나 무기 발동을 늦추지 않는다. 자동 Miss에는 성공 준비·파괴를 재생하지 않는다.

졸음 슬라임의 네 박 쉼과 시계 정령의 일곱 박 쉼은 기존 기억 과제를 보존한다. Call 뒤 대기 중에는 날아오는 탄, 점점 커지는 그림자, 후속 발사 신호나 카운트다운을 보여주지 않는다. 목표 박자에 공격이 판정 지점에서 순간적으로 나타나도록 표현하여 그 박자의 접촉·파괴·스침·피격을 보여준다. 이 두 긴 쉼은 일반 비행 전조의 예외다.

## 대응과 무기 효과

몬스터 공격의 파괴·차단·회피·밀쳐내기는 기존 `RhythmRound` 판정의 표현이다. 무기가 없는 박자도 Perfect 대응이면 공격 효과를 무효화한다. 투사체를 부쉈다는 이유로 적에게 별도 피해를 추가하지 않는다.

같은 Response에 연결된 모든 무기는 동일한 결과를 받아 각자 효과를 낸다. 예를 들어 Tap 한 번에 투사체 하나를 부수면서 창·한손검·단검이 함께 출동할 수 있다. 적 공유 HP의 감소는 `WeaponBattle`의 실제 무기 효과를 따른다. 무기 타격과 몬스터의 피격 반응은 `WeaponActivation`의 표적·발동에 연결한다. 공격을 막았다는 이유만으로 멀리 있는 몬스터가 무조건 맞는 연출을 붙이지 않는다.

| 표시 단위 | 결과 연결 |
|---|---|
| 한 몬스터의 한 공격 단계 | `PlannedAttack.Id` + `ResponseNote.StepIndex`로 추적하고 해당 노트의 실제 결과로 처리 |
| 같은 입력을 공유하는 서로 다른 몬스터 | 각 공격의 접근과 차단 결과를 모두 표시; 각 원본 몬스터 판정의 효과를 한 번씩 적용 |
| 동일 노트에 배치된 여러 무기 | 원본 공격·피격 판정을 복제하지 않고 모든 무기의 발동을 표시 |
| 한 시점의 플레이어 신체 | 기존 `PlayerMotionTimeline`의 공유 포즈 및 나쁜 Grade 우선 규칙을 사용 |
| 공미스 입력 | 기존 신체 모션만 재생; 공격 파괴나 무기 피해·판정 성공을 만들지 않음 |

## 화면과 실행 규칙

- 공격은 오른쪽의 실제 발동 몬스터에서 왼쪽으로 진행한다. 주먹·가드·머리·발 기준의 접촉 위치는 플레이어의 공통 지면과 기준 캐릭터 높이에서 계산한다. 몬스터의 전진 위치·깊이, 플레이어의 크기·포즈 보정, 16:9·16:10 화면을 반영한다.
- 상단 파동도 상단 HUD를 가리지 않는 전투 영역을 사용한다. 지면 공격은 발아래, 나머지는 주먹·가드 앞을 향한다. 중앙의 주 진행 경로와 무기별 반격 경로가 구분되어야 한다. 같은 종류의 동시 공격도 발사자와 접촉 효과를 추적할 수 있게 한다.
- 공격별 형태를 보여주기 위해 플레이어의 상시 흔들림·좌우 이동을 되살리지 않는다. 현재의 발 피벗, 짧은 스쿼시·스트레치와 Flick의 지정된 점프 높이를 사용한다.
- 이동·변형·파편은 `round.ElapsedSeconds`를 따라 멈추고 재개한다. 프레임 저하로 시간이 건너뛰어도 피해를 재계산하거나 끝난 효과를 다시 발생시키지 않는다. Collider 접촉이나 파편 수를 판정 근거로 사용하지 않는다.
- 승리 이후의 새 적 공격과 피해 중지는 기존 Overkill 규칙을 따른다. 남은 대응 구간을 마무리하는 표현 때문에 적 피해를 다시 활성화하지 않는다.
- 준비 화면의 패턴 설명과 연습에서 같은 공격 형태·결과를 사용한다. 연습은 실제 전투의 입력과 무기 발동을 보여주되 기존의 탐험 HP·보상 격리를 유지한다.

## 구현 시 확인할 기준

1. Tap에서 파괴·빗겨 스침·몸통 명중이 뚜렷이 구분되고 기존 0/50/100% 효과와 일치한다.
2. Hold의 유지 접촉, Dive의 머리 위 통과와 종료, Flick의 발아래 통과, Shake의 한 번 왕복이 기존 판정 및 플레이어 포즈와 맞는다.
3. 공격 외형을 바꿔도 원본 Response 수, 박자, 판정 창, 피해 횟수와 무기 발동 수가 변하지 않는다.
4. 한 박자에 여러 몬스터 또는 여러 무기가 연결되어도 각자의 효과가 누락되거나 중복되지 않는다. 방어막 흡수와 공미스도 구분한다.
5. 빠른 연속 Tap, 이른 입력, 자동 Miss, 일시정지·재접촉, 화면 크기 변경과 긴 프레임에서 공격이 잘못 사라지거나 재생되지 않는다.
6. 긴 쉼의 대기 중에는 마지막 박자를 알려주는 접근 연출이 없고, 연습에서도 같은 예외가 유지된다.

이 항목들은 새 연출을 구현할 때의 검증 기준이며, 현재 실행을 통과했다는 의미는 아니다. 기존 판정·무기는 [Weapons.md](Weapons.md), 신체 동작은 [PlayerAnimation.md](PlayerAnimation.md), 현재 화살표 기반 화면은 [BattlePresentation.md](BattlePresentation.md)를 참고한다.
