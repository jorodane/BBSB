# 플레이어의 대응으로 막는 몬스터 공격

상태: **공격 표현 명세와 구현된 이미지 연결 규칙**. 공통 공격 화살표를 12종·24패턴·36단계의 경로와 이미지 슬롯으로 교체했다. 종족별 임시 도형이 동작하며, 실제 PNG는 [MonsterAttackArt.md](MonsterAttackArt.md)의 위치에 넣어 교체한다. 입력별로 공유하는 것은 대응 동작과 공격의 관계이며, 아래 공격 형태는 예시다. 12종의 구체적인 개편안은 [MonsterGirls.md](MonsterGirls.md)에 있다.

몬스터의 공격이 중앙을 지나 플레이어에게 다가오며 리듬 노트의 역할을 한다. 플레이어가 그 공격을 때려 부수거나, 막거나, 피하거나, 밀쳐내는 모습으로 대응 결과를 보여준다. 대응 판정에 연결된 무기들은 동시에 각자의 효과를 발동한다.

## 입력별 대응 경향과 결과

| 입력 / 신체 동작 | 공격이 갖는 성질과 예시 | Perfect | HalfMiss | Miss |
|---|---|---|---|---|
| Tap / 펀치 | 한 번의 짧은 접촉으로 받아칠 수 있는 공격. 젤리탄·깃털·장갑 주먹·길게 뻗는 꼬리 등 | 종족의 재질에 맞춰 파괴·흩뜨리기·쳐내기·되튕김 | 불완전하게 쳐내어 공격 일부가 팔이나 몸을 스침 | 타격을 받아내지 못해 몸통 피격 |
| Hold / 크로스가드 | 정해진 구간 동안 정면 압력이 이어지는 공격. 뇌수의 방전·용인의 무거운 비늘 방패 등 | 가드를 유지해 끝까지 받아낸 뒤 공격이 잦아들거나 밀려남 | 가드가 밀리며 압력 일부가 몸에 닿음 | 가드가 열리거나 유지가 끊겨 압력을 받음 |
| Dive / 덕킹 | 일정 시간 상단 공간을 차지하는 공격. 라미아의 긴 꼬리 장막 등 | 시작에 숙이고 낮은 자세를 유지한 뒤 정해진 떼기에 일어남 | 공격의 앞·뒤 가장자리에 머리가 스침 | 숙이지 못하거나 중간에 일어나 맞고 넘어짐 |
| Flick / 점프 | 정해진 박자에 발밑을 지나가는 공격. 아라크네가 당기는 실 등 | 목표 박자에 뛰어넘어 발아래로 통과시킴 | 다리가 끝부분에 걸려 공중에서 균형을 잃음 | 발이 걸리거나 몸이 부딪혀 앞으로 넘어짐 |
| Shake / 양손 밀쳐내기 | 한 번 밀고 회수해 떨칠 수 있는 공격. 해파리의 우산막 등 | 목표 전후의 반미스 범위 안에서 왕복하여 밀어내거나 뒤집음 | 사용하지 않음 | 왕복을 완료하지 못해 양팔이 벌어지며 피격 |

예를 들어 같은 Tap이라도 젤리탄은 터지고, 깃털은 흩어지며, 골렘 장갑은 되튕기고, 네코마타의 꼬리는 쳐내어진다. 같은 Hold도 전기를 받아내는 모습과 무거운 방패를 버티는 모습이 다르다. 종족의 신체·능력으로 공격을 설계하고, 모양·높이·지속 시간과 접촉 결과로 대응 종류를 읽게 한다.

반미스의 빗겨나감은 확률적 완전 회피가 아니다. 일부 접촉이 남았다는 표현이며 기존 공격 효과의 50%를 적용한다. 기본 피해는 Perfect 0%, HalfMiss 50%, Miss 100%이고, 이후 방어막이 남은 피해를 흡수한다. 방어막이 모두 흡수했으면 가드가 불완전했더라도 별도의 방어막 접촉 효과로 HP 피해가 없었던 이유를 보여준다. 시각 효과 자체가 피해를 계산하지 않는다.

## 종족별 공격 명세

입력과 간격은 현재 `MonsterCatalog`의 12종·24개 패턴을 따른다. 종족·실루엣·성격·두 패턴의 Call과 공격은 [리듬 몬스터 걸 개편안](MonsterGirls.md)에 각각 기록한다. 기존 몬스터 ID로 대응하며, 같은 종족의 혼합 패턴도 신체 능력의 서로 다른 사용법으로 표현한다.

## 도착 박자와 유지 구간

- Call의 소리·포즈와 패턴 구별 규칙은 기존 계획을 따른다. 투사체의 접근과 신체의 전개를 해당 Call 이후의 공격 준비에 연결하고, 정상 패턴의 접촉 시각을 기존 Response 시작 박자에 맞춘다. 화면 거리나 종횡비 때문에 요구 박자를 바꾸지 않는다.
- Tap/Flick은 한 공격의 접촉 박자를 읽게 한다. Hold/Dive는 압력·상단 위협의 시작과 종료가 요구 구간을 나타낸다. 유지 입력의 시작·끝에 각각 다른 피해 공격을 만들지 않는다. 한 `ResponseNote`의 피해 판정은 한 번이다.
- Hold가 끝나는 시각에 가드를 풀어도 되고, Dive는 기존 규칙대로 정해진 끝 박자에 떼어야 한다. 상단으로 전개된 신체나 공격이 거두어지는 모습을 Dive의 종료 동작과 연결한다.
- Shake의 대상은 인정 구간에 한 번 밀었다 돌아오는 동작을 받는다. 왕복 완료 뒤 계속 흔들거나 누르고 있을 필요가 없다. 실제 진행도에 따라 대상이 눌리고 밀려나는 중간 상태를 보여주고, 왕복 완료 순간의 `RhythmResult`로 Perfect와 무기 효과를 확정한다. 목표 전후의 일반 반미스 허용 범위가 지나도 미완료라면 Miss이며 부분 성공은 없다. 시작 박자에 정확히 눌러야 한다는 새로운 조건을 만들지 않는다.
- 허용된 이른·늦은 입력은 판정 지점 주변의 짧은 접촉 연출로 받아낸다. 최종 Grade와 접촉 결과는 실제 결과가 나온 뒤 결정한다. 투사체의 화면 위치로 성공 여부를 다시 계산하지 않는다.
- 너무 이른 입력으로 Miss가 먼저 확정되어도 공격을 미리 삭제하거나 파괴 성공을 재생하지 않는다. 빗나간 동작 뒤에도 해당 공격의 접근·피격 흐름은 남으며 재입력으로 결과를 바꾸지 않는다. 기존 피해 계산 시각과 판정 창은 유지한다.
- Tap의 짧은 준비 → 펀치 → 회수에 맞춰 접촉과 종족별 결과를 표시한다. 준비 자세에서 공격이 이미 완전히 해소되지 않게 하고, 시각 효과를 맞추기 위해 입력 판정이나 무기 발동을 늦추지 않는다. 자동 Miss에는 성공 준비·차단을 재생하지 않는다.

긴 쉼은 입력을 쉬는 구간이다. 카운트 보조 여부는 공격 컨셉에 따른다. 꿈먹는 맥의 네 박 낮잠은 중간 접근을 감추고 목표 박자에 꿈방울이 실체화한다. 태엽 인형의 일곱 박 쉼은 작은 인형을 바로 내려놓고 한 박씩 걷게 하며, 일곱 번째 걸음의 도착·공격이 기존 Response가 된다. 작은 인형의 걸음은 카운트를 돕지만 추가 ScheduledCall이나 입력 노트를 만들지 않는다.

## 대응과 무기 효과

몬스터 공격의 파괴·차단·회피·밀쳐내기는 기존 `RhythmRound` 판정의 표현이다. 무기가 없는 박자도 Perfect 대응이면 공격 효과를 무효화한다. 투사체를 부쉈다는 이유로 적에게 별도 피해를 추가하지 않는다.

같은 Response에 연결된 모든 무기는 동일한 결과를 받아 각자 효과를 낸다. 예를 들어 Tap 한 번에 투사체 하나를 부수면서 창·한손검·단검이 함께 출동할 수 있다. 적 공유 HP의 감소는 `WeaponBattle`의 실제 무기 효과를 따른다. 무기 타격과 몬스터의 피격 반응은 `WeaponActivation`의 표적·발동에 연결한다. 공격을 막았다는 이유만으로 멀리 있는 몬스터가 무조건 맞는 연출을 붙이지 않는다.

| 표시 단위 | 결과 연결 |
|---|---|
| 한 몬스터의 한 공격 단계 | `PlannedAttack.Id` + `ResponseNote.StepIndex`로 추적하고 해당 노트의 실제 결과로 처리 |
| 같은 입력을 공유하는 서로 다른 몬스터 | 각 공격의 접근과 차단 결과를 모두 표시; 각 원본 몬스터 판정의 효과를 한 번씩 적용 |
| 동일 노트에 배치된 여러 무기 | 원본 공격·피격 판정을 복제하지 않고 모든 무기의 발동을 표시 |
| 한 시점의 플레이어 신체 | 기존 `PlayerMotionTimeline`의 공유 포즈 및 나쁜 Grade 우선 규칙을 사용 |
| 공미스 입력 | 기존 신체 모션만 재생; 공격 파괴나 무기 피해·판정 성공을 만들지 않음 |

## 화면과 실행 규칙

- 공격은 오른쪽의 실제 발동 몬스터에서 왼쪽으로 진행한다. 주먹·가드·머리·발 기준의 접촉 위치는 플레이어의 공통 지면과 기준 캐릭터 높이에서 계산한다. 몬스터의 전진 위치·깊이, 플레이어의 크기·포즈 보정, 16:9·16:10 화면을 반영한다.
- 상단으로 전개되는 공격도 상단 HUD를 가리지 않는 전투 영역을 사용한다. 지면 공격은 발아래, 나머지는 주먹·가드 앞을 향한다. 중앙의 주 진행 경로와 무기별 반격 경로가 구분되어야 한다. 같은 종류의 동시 공격도 공격자와 접촉 효과를 추적할 수 있게 한다.
- 공격별 형태를 보여주기 위해 플레이어의 상시 흔들림·좌우 이동을 되살리지 않는다. 현재의 발 피벗, 짧은 스쿼시·스트레치와 Flick의 지정된 점프 높이를 사용한다.
- 이동·변형·파편은 `round.ElapsedSeconds`를 따라 멈추고 재개한다. 프레임 저하로 시간이 건너뛰어도 피해를 재계산하거나 끝난 효과를 다시 발생시키지 않는다. Collider 접촉이나 파편 수를 판정 근거로 사용하지 않는다.
- 승리 이후의 새 적 공격과 피해 중지는 기존 Overkill 규칙을 따른다. 남은 대응 구간을 마무리하는 표현 때문에 적 피해를 다시 활성화하지 않는다.
- 준비 화면의 패턴 설명과 연습에서 같은 공격 형태·결과를 사용한다. 연습은 실제 전투의 입력과 무기 발동을 보여주되 기존의 탐험 HP·보상 격리를 유지한다.

## 구현 시 확인할 기준

1. 종족별 Tap의 성공(파괴·쳐내기 등), 빗겨 스침, 몸통 명중이 뚜렷이 구분되고 기존 0/50/100% 효과와 일치한다.
2. Hold의 유지 접촉, Dive의 머리 위 통과와 종료, Flick의 발아래 통과, Shake의 한 번 왕복이 기존 판정 및 플레이어 포즈와 맞는다.
3. 공격 외형을 바꿔도 원본 Response 수, 박자, 판정 창, 피해 횟수와 무기 발동 수가 변하지 않는다.
4. 한 박자에 여러 몬스터 또는 여러 무기가 연결되어도 각자의 효과가 누락되거나 중복되지 않는다. 방어막 흡수와 공미스도 구분한다.
5. 빠른 연속 Tap, 이른 입력, 자동 Miss, 일시정지·재접촉, 화면 크기 변경과 긴 프레임에서 공격이 잘못 사라지거나 재생되지 않는다.
6. 긴 쉼에서 맥의 비노출 대기와 인형의 한 박씩 걷기를 구분하고, 연습에서도 같은 동작과 기존 Response 시각을 유지한다.

이 항목들은 새 연출을 구현할 때의 검증 기준이며, 현재 실행을 통과했다는 의미는 아니다. 기존 판정·무기는 [Weapons.md](Weapons.md), 신체 동작은 [PlayerAnimation.md](PlayerAnimation.md), 현재 전투 화면은 [BattlePresentation.md](BattlePresentation.md)를 참고한다.
