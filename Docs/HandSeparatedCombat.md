# 손 분리 전투 구현과 설계 검토

## 적용한 규칙

| 구분 | 이전 5선 구현 | 현재 기본 전투 |
| --- | --- | --- |
| 공격 입력 | 무기 배치에 따라 S/D/F/Space/J/K/L 사용 | Z/X/C/V가 각각 공격 무기 한 개에 대응 |
| 공격 시작 | 무기별 첫 입력과 시작 박자 처리 | 준비된 무기를 자유 타이밍으로 Call. Call 자체에는 성공 판정·피해 없음 |
| 후속 입력 | 무기 노트의 타이밍과 입력 라인을 따라 연주 | 같은 무기 키로 고유 리듬 연주. 모션·소리로 다음 입력 안내 |
| 방어 입력 | 장착한 방패의 점유 라인, 선봉/후열 구분 | ←/↓/↑/→가 몬스터 공격 노트의 4개 라인에 직접 대응 |
| 장비 구성 | 여러 라인을 점유하는 장비, 장착 한도 2→5 | 공격 4슬롯 + 방어 장비 1슬롯 |
| 화면 | 공격·방어의 이동 노트가 같은 배치 사용 | 왼쪽 공격 카드와 무기 동작, 오른쪽 방어 노트 4라인 |
| 동시 진행 | 장비 라인별 상태와 음악 시계 | 같은 시계에 공격 4개와 방어 4방향의 입력 상태를 독립 유지 |

공격을 먼저 시작하거나 방어하면서 공격할 수 있다. 공격 미스가 방어 입력을 중지하지 않으며, 방어 입력이 공격의 후속 노트를 대신 성공시키지 않는다. 공격 키의 패링 효과도 몬스터 방어 라인을 대신 처리하지 않는다. 일시정지 후에는 실제로 유지 중이던 양손 입력을 모두 다시 잡아야 재개한다.

공격 Call의 자유 타이밍은 준비 상태에서의 개시를 뜻한다. 이미 연주 중인 키는 후속 입력이며, 기존 쿨타임은 유지한다. Call을 계속 누르는 것만으로 후속 타격을 자동 성공시키지 않는다.

## 기존 구현 재사용

- 원본 `WeaponPhrase`·속성·노트 조립 데이터를 수정하지 않고 실행 시 새 입력 배치에 연결한다. 복수 라인의 입력 순서와 간격은 보존하되 동일 무기 키로 접는다.
- 기존 첫 노트 준비 시간과 빛/어둠 시작 박자를 유지한다. Call은 즉시 접수하며 후속 판정은 공통 음악 시계에 예약된다. 별도의 공격용 시계를 만들지 않는다.
- 단검·쌍검 반복, 홀드, 연속 타격, 속성 전환과 쿨타임 처리를 재사용한다.
- 활은 당기기와 놓기를, 석궁은 기존 장전 입력과 선택적 발사 기회를 유지한다. 발사를 미루는 석궁 입력을 강제 미스로 바꾸지 않는다.
- 기존 공격·방어·투사체 애니메이션을 재사용하고 다음 입력 전 준비 모션을 덧붙인다. 슬롯별 합성 안내음은 같은 DSP 음악 시계로 예약한다. 음원 파일을 새로 추가하지 않는다.
- 방어 장비의 첫 방어 동작, 패링 방식, 홀드 길이, 피해 경감과 회복, 축적 방패의 공명 처리를 재사용한다. 이전 방패의 후속 수동 반격 콤보는 방향키에서 요구하지 않는다.
- 이동 공격 노트는 전투 화면과 노트 조립의 공격 시연에서 제거한다. 노트 조립의 정적인 패턴 편집은 남긴다. 방어 노트와 기존 몬스터 공격 연출은 유지한다.
- 시작 장비는 기존 단검·히터실드다. 새 공격 슬롯이 열려 있어도 무기 지급량을 임의로 늘리지 않는다. 구버전 배치 저장값은 입력 체계를 구분해 기본 편성으로 안전하게 전환한다.

## 설계 검토 항목

아래는 확정된 새 게임 규칙이 아니다. 실행에 필요한 최소 연결 방식과 기존 동작을 명시해 후속 검토에서 구분한다.

1. **Call과 첫 판정의 간격**: 기존 무기별 준비 시간·속성 박자 정렬을 사용한다. 자유 Call 이후 정확한 응답 지연, 재개·취소·다른 무기와의 상호 제한을 새로 정하지 않았다.
2. **복수 라인 무기의 변형**: 원본 시작 Offset별 패턴은 보존한다. 한 키 배치에서는 기본 Offset 0을 사용한다. 변형 선택을 플레이어에게 제공할지 검토가 필요하다.
3. **방어 장비 특성 전환**: 넓은 방패의 선봉/후열 두 입력과 기존 수동 반격 콤보를 새 4방향 방어에 어떻게 차별화할지 미정이다. 현재는 각 방향에 같은 장비의 첫 방어 동작을 적용하며 방향별 상태·쿨타임을 독립 처리한다. 반격 노트와 후속 노트 주입의 새 역할, 장비 공통 쿨타임·자원 여부는 검토 대상이다.
4. **몬스터 방향 패턴**: `BeatAttack.DefenseDirection`으로 0~3 방향을 지정할 수 있다. 기존 방향 없는 데이터는 4방향 순환으로 연결하고, 이어지는 같은 몬스터의 홀드는 방향을 유지한다. 실제 몬스터별 방향 악보, 겹치는 공격, 동시 입력 난이도는 별도 설계 대상이다.
5. **성장과 획득 밸런스**: 새 구성에 맞춰 공격 4칸·방어 1칸을 사용한다. 시작 지급과 보스 무기 획득은 기존 흐름이다. 기존 장착 한도 증가 보상의 대체안과 공격 무기 4개를 채우는 속도는 확정하지 않았다.
6. **모션과 음향의 학습성**: 기존 모션에 반 박 앞의 준비 신호와 슬롯별 합성음을 연결했다. 이는 표시용 설정이며 판정 간격을 바꾸지 않는다. 무기별 소리, Call 음형, 홀드·놓기 신호, 안내 강도는 실제 플레이로 검토한다.

## 검증 경로

- `HandCombatTests`: 역할별 편성, 자유 Call, 8입력 동시 처리, 잘못된 방향, 방어 홀드 연속성, 활·석궁, 공격 노트 비표시, 일시정지 복구.
- `FiveLanePlaybackTests`: Unity 실제 화면 구성, 방향별 입력과 재개, 공격 카드·방어 레인, 프리팹 복구.
- `RunSetupTests`·`EquipmentPlacementTests`: 시작 편성 저장, 고정 역할 슬롯, 복수 라인 무기의 한 칸 배치와 드래그.
- 기존 Core checks는 이전 전투와 원본 무기 데이터의 회귀를 함께 검사한다.

2026-10-15 로컬 검증: Core checks 552개, Unity 6000.3.5f2 PlayMode 관련 검사 21개, 화면 프리팹 16개 검사를 통과했다. 1280×720 전투 화면을 렌더링해 확인했다. 키보드는 Input System에 입력 이벤트를 넣어 검증했으며, 실제 손으로 연주하는 감각·키보드별 동시 입력 한계·안내음 청취 밸런스는 아직 확인하지 않았다.
