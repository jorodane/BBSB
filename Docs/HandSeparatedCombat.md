# 방어 중심 전투 · 손 분리 · 장봉 아티팩트

2026-10-16 개편. 방향키로 몬스터의 리듬 공격을 쳐내는 것이 전투의 중심이고, 왼손으로 원하는 때 부유 병기를 호출해 무기의 리듬을 연주한다. 두 행동은 같은 음악 시계에서 독립적으로 진행된다.

## 이전 구현과 현재 구현

| 항목 | 이전 5선 구조 | 이번 기본 전투 |
| --- | --- | --- |
| 중심 루프 | 무기와 방패의 노트를 같은 선에서 처리 | 몬스터 협공의 4방향 노트를 방어 |
| 오른손 | 장비 배치에 따른 입력 | ←/↓/↑/→ 방어 전용 |
| 왼손 | 점유 라인의 무기 노트 | Z/X/C/V 각각 공격 무기 하나의 자유 Call |
| 장착 비용 | 무기마다 1~3라인 점유 | 공격 슬롯 하나씩, 방어 아티팩트 별도 하나 |
| 공격 안내 | 이동하는 공격 노트 | 무기의 준비·타격·당기기·발사 모션과 소리 |

| 적 공격 연출 | 모두 플레이어의 같은 지점으로 이동 | 각 몬스터에서 출발해 네 방향의 서로 다른 접점으로 접근 |
| 동시 방어 | 별도 입력 상태 위주의 표시 | 좌우 펼치기, 상하 세우기, 인접·3·4방향 쓸어내기 |
| 공격·방어 동시 입력 | 장비 라인에 종속 | 8키의 눌림·홀드·해제를 독립 관리 |

노트 라인은 **몬스터 공격만** 표시한다. 전투와 공격 시연에는 낙하·이동 공격 노트가 없다. 노트 조립 메뉴의 정적 패턴 편집은 남겨 두었다.

## 공격: 패턴, 효과, 쿨타임

기본 단검과 쌍검의 단일 타격을 재사용했다. 입력 순간 피해가 나고 단검은 2박, 쌍검은 1박 뒤 다시 사용할 수 있다. 이 값은 기존 반복 간격을 옮긴 것으로 새 밸런스 확정값이 아니다. 계속 누르고 있거나 키 반복 이벤트가 들어와도 자동 재발사하지 않는다. 자유 Call에는 PERFECT·콤보를 주지 않는다.

기본 전쟁 북은 한 번의 Call로 후열의 선봉 교체를 요청한다. 기존 후열 표적 선택 규칙과 교체 예고 시간을 재사용한다. 이미 예고한 위협을 즉시 지우지 않고 공통 시계의 교체 경계에서 이동한다. 쿨타임 8박도 기존 값이다. 후열이 없거나 교체가 이미 진행 중이면 추가 교체를 덮어쓰지 않는다.

검·해머·봉 등 고유 리듬 무기는 기존 패턴을 같은 무기 키로 연주한다. 활의 당기기와 해제 발사, 석궁의 장전과 선택 발사, 연속 공격과 혼돈 속성의 반복·박자 전환을 유지한다. 단검·쌍검의 혼돈 변형은 기존 리듬을 유지하며 단발화할지 별도 검토한다.

제작 데이터의 `attackOnCall`은 첫 입력 자체의 효과 실행을, `cooldownFromLastInput`은 마지막 수행 입력부터의 쿨타임을 지정한다. 패턴의 표시 길이를 늘려도 단발 액션의 쿨타임은 늘지 않는다. 일반 리듬 패턴의 기존 종료·쿨타임 처리도 선택 가능하다.

직접 작성한 프레이즈는 자동으로 대체하지 않는다. 새 기본값은 기본 카탈로그의 대체 경로에만 적용한다. 프레임과 추가 Tap은 단발 Call의 첫 효과를 유지하고, 추가 입력은 직접 연주해야 한다. 첫 Tap에 Hold를 씌우면 기존 준비 시간 1박을 사용한 리듬 응답으로 바뀐다. 교차 주입도 같은 무기 키에서 수행하며 새 모드에서는 점유 라인 수로 장착을 제한하지 않는다. 주입 피해 수치는 기존 값을 유지한다.

기존 북의 후속 노트나 공격 전용 부품이 이미 장착된 인스턴스는 그 원본 패턴을 유지한다. 소유 부품을 삭제하거나 잘못된 노트에 옮기지 않는다. 해당 부품을 해제하면 새 기본 호출 패턴을 사용한다.

## 방어: 하나의 아티팩트, 독립된 네 접점

방어 아티팩트는 공격 슬롯을 쓰지 않는다. 이전 방패 ID와 장비 데이터는 호환용으로 유지하지만, 기본 전투에서는 손에 든 장봉 형태로 표시하며 공격 무기 궤도에서 제외한다.

기존 첫 방어 동작의 Tap/Hold, 누르기·놓기 패링, 홀드 연장, 경감·회복·공명 규칙을 재사용한다. 방향별 상태와 쿨타임이 독립적이다. 방향키로 이전 수동 반격 콤보를 연주하지 않는다. 공격 입력은 방어 노트를 대신 처리하지 않고, 공격 미스도 방어를 중단하지 않는다.

방어 연출은 입력이 공간적 위협에 대한 행동으로 읽히도록 구성했다.

- 좌/우/상/하 위협은 플레이어 주변의 서로 다른 접점으로 접근한다.
- 방어 중인 접점과 접근 중인 위협을 색과 방향 표시로 구분한다.
- 좌우 입력은 장봉을 가로로, 상하 입력은 세로로 펼친다.
- 인접한 두 방향과 3·4방향은 몸통을 비틀어 넓게 쓸어낸다. 빠른 구간에만 팔·봉이 늘어난 스메어를 보여 주고, 홀드 중에는 방어 자세로 멈춘다.
- 각 방향의 패링·연속 공격 효과도 그 접점에서 발생한다.
- 선봉·후열의 공격 출발점과 기존 교체·난입·복귀 흐름을 유지한다.

장봉 자세와 투사체 궤적은 표시 전용이다. 판단 시점·입력 창·피해량을 움직이는 그림으로 다시 계산하지 않는다. PNG가 있는 투사체와 코드로 그리는 대체 투사체 모두 같은 접점 계산을 사용한다.

## 비주얼 기준과 적용 범위

사용자가 첨부한 2026-10-16 이미지의 핵심 구성을 기준으로 한다. 거대한 양끝 동일형 장봉이 캐릭터의 중심 실루엣을 만들고, 주변에는 공격 병기 네 개가 떠 있다. 장봉은 검정 몸체, 금색 테두리와 띠, 분홍색 에너지 코어를 양끝에 반복한다. 기존 공격용 봉 무기와 방어 아티팩트는 서로 다른 장비다.

장비 카드의 방어 아이콘은 장봉으로 표시한다. 부유 병기는 장착된 공격 무기만 표시하며 최대 네 개다. 몬스터·공격 병기·투사체 이미지와 애니메이션은 재사용한다. 캐릭터에는 아래의 전용 방어 포즈 재생을 추가했다.

### 캐릭터 모션과 스메어 (2026-10-16 후속 반영)

기존 `Guard` 한 장의 크기를 바꾸는 표시에서, 두 손·장봉·몸통·무릎·옷자락이 함께 바뀌는 **16포즈 프레임 애니메이션**으로 확장했다. 기존 뒤쪽 3/4 캐릭터와 첨부 장봉을 참조해 실제 알파 PNG를 제작했다. 골격 리깅이나 손 관절 보간 방식은 아니다.

| 입력/상태 | 몸의 동작 |
| --- | --- |
| 좌/우 | 체중 이동, 몸통 비틀기, 옆으로 쳐내기; 왼쪽은 반전 포즈 |
| 아래/위 | 낮게 웅크려 받기 / 두 팔로 봉을 머리 위에 들기 |
| 좌우/상하 | 가로로 펼치기 / 수직으로 세우기 |
| 인접 2방향, 3·4방향 | 크게 감아 준비하고 팔과 봉을 넓은 호로 쓸어내기 |
| 유지 | 해당 방향을 받치는 자세 유지; 무한 회전이나 스메어 반복 없음 |
| 해제 | 복귀 후 대기; 해제 자체가 새 공격 모션을 만들지 않음 |

`PlayerDefenseMotion`이 실제 입력 시각에서 준비(0~0.045박), 스메어(0.045~0.13박), 받아내기(~0.28박), 복귀(~0.48박), 홀드를 계산한다. 수치는 현재 연출 시제품의 값이며 입력 판정 창을 변경하지 않는다. 피해 방어는 입력 순간 처리된다. 일시정지는 동일한 프레임을 유지한다. 추가 방향을 누르면 기존 홀드와 합쳐 새 협공 대응을 재생하고, 해제한 방향은 유지 자세에서 제외한다.

스메어는 캐릭터를 반투명하게 여러 장 복사하는 잔상이 아니라 **팔과 장봉이 늘어난 실루엣**이다. 5번 포즈는 수평 쓸기, 13번 포즈는 큰 회전 쓸기다. 손과 장봉을 같은 그림에서 그려 그립이 분리되지 않는다. 전용 포즈가 보이는 동안 별도 코드 장봉은 숨기며 방향 접점만 유지한다. 작성된 `Hit` 애니메이션이 있으면 재사용하고, 없는 캐릭터는 전용 포즈를 뒤로 밀어 피격을 표시한다. 부유 공격 무기·활 당기기·발사·연속공격은 기존 모션을 독립적으로 계속 재생한다.

아트는 `Assets/BBSB/Resources/BBSB/DefenseMotion/weapon-master.png`로 읽는다. ZIP을 프로젝트 루트에 풀면 적용되며, 코드·가져오기 설정은 Git에 포함한다. PNG와 메타 파일은 ZIP에만 포함한다. 프레임별 경계와 발바닥 기준점을 지정했으므로 단순 4×4 격자 자동 자르기를 사용하지 않는다. 공통 몸 크기를 유지하고 스메어가 셀 밖으로 넓어져도 잘리지 않는다. 새로운 캐릭터에는 이 외형을 강제로 적용하지 않는다.

아트가 없는 체크아웃에서는 기존 캐릭터와 코드 장봉을 사용한다. 이 경우에도 공격이 방어 자세를 덮어쓰지 않고, 장봉의 빠른 구간에만 채워진 부채꼴 스메어를 그린다. 전용 몸 동작을 보려면 별도 ZIP을 설치해야 한다. 아트는 체크무늬를 그린 배경이나 배경색 제거 방식이 아닌 실제 알파 PNG이며 원본 알파를 그대로 유지했다.

## 설계 검토 항목

아래 항목은 새로 확정하지 않았다. 현재 동작은 기존 구현 재사용 또는 실행 가능한 시제품의 기준이다.

1. **단발 및 지원 무기 밸런스**: 단검·쌍검 간격 2/1박, 북 쿨타임 8박, 피해·주입 계수의 조정. 라인 비용 폐기에 따른 교차 주입의 가치 재평가.
2. **북의 대상과 교체 시점**: 현재 기존 규칙대로 살아 있는 후열 중 HP가 낮은 대상을 선택하고 최소 3박의 예고 뒤 경계에서 교체한다. 직접 표적 선택, 즉시 전진, 이미 교체 중일 때의 소비/취소 처리 여부.
3. **Call과 첫 응답**: 긴 패턴의 기존 준비 시간과 빛/어둠 박자 정렬을 유지한다. 개시 취소, 반복 중 재개, 다른 무기 간 제약, 단발의 속성 차별화와 혼돈 단발화.
4. **방어 장비 특성**: 넓은 방패의 과거 선봉/후열 구분, 수동 반격 콤보 및 후속 주입의 새 역할. 방향별 쿨타임을 장비 공통 자원으로 바꿀지 여부.
5. **몬스터 방향 악보·난이도**: 명시한 `BeatAttack.DefenseDirection`을 우선하고, 방향 없는 기존 데이터는 네 방향을 순환한다. 연결된 홀드는 같은 방향을 유지한다. 기존 선봉/후열 공격을 재사용했으며 몬스터별 LR/UD/3방향 악보와 허용 중첩량은 별도 설계한다.
6. **시작 편성과 성장**: 기존 단검·방어 장비 지급과 획득 흐름 유지. 네 공격 슬롯을 채우는 속도, 장착 한도 보상의 대체안, 방어 아티팩트 미장착 출격 허용 여부.
7. **기존 데이터 전환**: 복수 라인 시작 Offset의 대체 선택 방식, 기존 북에 부착된 부품의 이전 방식, 옛 방패별 표시 이름과 아티팩트 외형 차별화.
8. **전용 아트와 학습성**: 16포즈 사이의 추가 중간 그림·방향별 전용 스메어, 동시 방어의 판독성, 빠른 BPM에서의 노출 길이, 방향 접점과 그림의 세부 정합, 소리만으로 입력을 익힐 수 있는지, 안내음 음량과 타이밍. 실제 키보드의 동시 입력 한계도 실기 검토 대상이다. 현재 프레임 애니메이션을 골격 리깅으로 바꿀지는 미정이다.

## 검증
