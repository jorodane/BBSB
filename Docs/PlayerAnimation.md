# 플레이어 판정 애니메이션

제공된 분홍 단발·기계 수신부 헤드셋 캐릭터를 기준으로 **8개 시트, 40개 키포즈**를 만들었다. 이미지 8장이 모두 설치되면 `RunMap`의 준비 화면과 실제 연주 화면 모두 새 캐릭터를 자동으로 사용한다. 이미지나 Animator를 Inspector에 별도로 연결할 필요는 없다.

모션 PNG 8장은 `Assets/BBSB/Resources/BBSB/BattleArt/PlayerMotion`에 포함되어 있다. **자동 배경 제거는 사용하지 않으며, 배경을 제거한 투명 PNG를 같은 파일명으로 넣는다.** 시트가 하나라도 없으면 `PlayerMotionSprites`는 기존 `weapon-master` 초상화를 사용하며, 판정별 모션 선택·이동·회전·효과는 계속 작동한다.

현재 재생 방식은 결과 키포즈 → 복귀 키포즈 → Idle을 교체하고 작은 이동·회전을 더하는 방식이다. 입력 유지에는 준비 → 유지 포즈를 사용한다. 연속 중간 프레임을 그린 전통적인 프레임 애니메이션이나 관절 리깅은 아니다.

## 동작과 판정

| 입력 | Perfect | HalfMiss | Miss |
|---|---|---|---|
| Tap 왼손 | 왼손 잽 | 뻗은 왼팔이 위로 빗나감 | 왼팔을 뻗은 채 몸통 피격 |
| Tap 오른손 | 몸통 앞을 가로지르는 오른손 크로스 | 오른팔이 위·바깥으로 빗나감 | 오른팔을 든 채 몸통 피격 |
| Tap 어퍼 | 위로 올려치는 펀치 | 올려친 팔이 옆으로 빗나감 | 팔을 든 채 몸통 피격 |
| Hold | 낮게 교차한 가드로 받아냄 | 교차한 팔을 유지한 채 움츠러듦 | 가드가 벌어지며 피격 |
| Dive | 몸을 앞으로 낮춰 덕킹 | 머리를 찧고 움츠러듦 | 바닥에 옆으로 누움 |
| Flick | 점프 | 다리가 걸려 공중에서 균형을 잃음 | 엎어지며 턱을 찧음 |
| Shake | 양손으로 밀쳐냄 | 밀던 손을 몸 쪽으로 접어 가드 | 양팔이 벌어지며 피격 |

## 프레임 대응

인덱스는 시트의 왼쪽 위부터 가로 순서다.

| PNG | 배열 | 인덱스 순서 |
|---|---|---|
| `idle` | 2×2 | 0 기본 대기, 1 박자에 맞춘 낮은 대기, 2 공용 앉기, 3 공용 일어나기 |
| `tap-left`, `tap-right`, `tap-upper` | 각각 2×2 | 0 준비/팔 회수, 1 성공, 2 반미스, 3 몸통 피격 |
| `hold` | 3×2 | 0 가드 진입, 1 유지, 2 받아내기, 3 반미스, 4 가드 해제 피격, 5 복귀 |
| `dive` | 3×2 | 0 숙이기, 1 덕킹, 2 머리 피격, 3 누움, 4 앉아서 정비, 5 일어나기 |
| `flick` | 3×2 | 0 도약 준비/착지, 1 점프, 2 다리 걸림, 3 턱 피격, 4 앉아서 정비, 5 일어나기 |
| `shake` | 3×2 | 0 손 준비, 1 밀기, 2 밀쳐내기 마무리, 3 말린 가드, 4 벌어진 팔 피격, 5 복귀 |

`PlayerMotionTimeline`은 Tap의 세 시트를 논리적인 12프레임으로 다룬다. `PlayerMotionSprites`가 `punch * 4 + frame`을 해당 시트의 Sprite로 연결한다. Dive/Flick은 각각 자기 시트의 정비 포즈를 사용하며 Idle의 공용 복귀 2장은 후속 연출용으로 보관한다.

## 실제 입력과 재생

- `RhythmRound.Results`의 입력 종류, 최종 Grade, `JudgedAtSeconds`를 그대로 사용한다. 준비 화면이나 미래의 노트만 보고 성공 동작을 미리 재생하지 않는다.
- Tap은 실제 결과가 생성될 때 세 펀치 중 하나를 무작위로 선택한다. 직전 펀치는 제외한다. 여러 몬스터가 같은 입력을 공유하면 선택은 한 번이고, 실패와 복귀도 같은 펀치 종류를 유지한다.
- Hold/Dive는 유효한 접촉을 유지할 때 준비·유지 포즈를 사용한다. Shake는 구간이 자동으로 열렸다는 이유만으로 움직이지 않으며, 실제로 인정된 이동 거리가 늘 때 밀기 포즈를 사용한다. 복합 유지 중 실제 Shake 움직임이 있으면 짧게 밀기를 보여준다.
- 판정 순간 결과 포즈를 즉시 보여준다. 결과 포즈 길이는 최대 0.24초, 일반 복귀까지는 최대 0.48초이며 빠른 BPM에서는 줄어든다.
- Dive/Flick의 Miss는 누움 → 앉기 → 일어나기 순서다. 다음 입력까지 충분한 틈이 없으면 앉아 있는 단계를 생략한다. 전체 길이는 최대 0.84초다. 새로운 판정이나 유효 접촉은 이전 피격·복귀보다 우선한다.
- 한 시점에 여러 종류가 판정되면 신체 포즈는 더 나쁜 Grade를 우선하고, 같은 Grade에서는 Flick → Dive → Shake → Hold → Tap 순서다. 각 몬스터를 향한 대응 효과와 판정·피해 계산은 모두 유지된다.
- `round.ElapsedSeconds`를 사용하므로 일시정지와 함께 이미지·이동·이펙트가 멈춘다. 시간이 크게 건너뛰면 끝난 반응을 다시 재생하지 않는다.
- 화면의 작은 한글 동작 이름을 새 동작에 맞추고 글꼴의 글자 집합도 갱신했다. 판정·피해 규칙은 변경하지 않았다.

## 이미지 가져오기

PNG의 설치 경로는 `Assets/BBSB/Resources/BBSB/BattleArt/PlayerMotion`이다. 파일명과 위의 2×2 / 3×2 시트 배열을 유지한 채 **실제 알파 채널이 있는 투명 PNG**로 교체한다. `PlayerMotionImporter`는 다음 규칙으로 가져온다.

1. `alphaSource = FromInput`으로 원본 알파를 사용한다. 색상으로 투명도를 추정하거나 녹색을 제거하지 않는다. `PlayerChromaKey` 코드는 삭제했다.
2. 원본 알파를 기준으로 연결된 캐릭터 영역을 각각 찾는다. 누운 캐릭터의 영역이 이웃 칸을 넘어가도 이웃 캐릭터를 함께 잘라 오지 않는다.
3. 한 시트에 동일한 축소 비율을 적용해 칸마다 여백을 확보하고 발 위치를 아래 8%에 맞춘다. 앉거나 누운 포즈를 서 있는 높이로 확대하지 않는다.
4. RGBA32, mipmap 없음, 최대 2048로 저장한다. 게임 실행 중에는 가져온 텍스처의 Sprite 영역만 교체한다.

투명 영역이 없는 이미지는 포즈 자동 정렬을 건너뛰고 픽셀을 그대로 사용한다. 따라서 기존 RGB 시트의 녹색 배경은 투명 PNG로 교체하기 전까지 그대로 보인다. 가져오기 버전을 3으로 올려 이전 배경 제거 결과가 캐시에 남지 않도록 재가져오기를 요청한다. 갱신되지 않으면 `PlayerMotion` 폴더에서 **Reimport**를 실행한다.

컨셉 이미지와 캐릭터 레퍼런스는 `Assets/BBSB/Resources/BBSB/ConceptArt`에 있으며 이후 아트 작업의 참고 자료다. 전투 모션에는 연결하지 않는다. 생성 당시의 프롬프트는 [PlayerMotionPrompts.md](PlayerMotionPrompts.md)에 기록되어 있다. 그 문서의 녹색 배경 지시는 생성 이력이며 현재 가져오기 규칙이 아니다.

## 검증

- 이미지 제외 업로드를 위해 실제 `PlayerMotionSprites` 소스를 Unity API 대역으로 컴파일해, 시트 없음·일부 누락·전체 준비·대체 초상화도 없음의 4가지 로딩/해제 경로를 통과했다. 이는 Unity Editor 실행 검증을 대신하지 않는다. PlayMode의 기존 포즈 테스트도 이미지가 없을 때 모든 포즈가 기존 초상화를 사용하는지 확인하도록 조정했다.
- 실제 `RhythmRound`에 입력을 넣어 5종 × 3판정, 펀치 종류 유지·연속 중복 금지, 공유 입력, 정비 생략, 새 접촉 우선, 정지·시간 점프, 동시 결과를 검증했다.
- 배경 제거 삭제 후 .NET 8에서 실제 소스를 컴파일해 139개 테스트를 통과했다. 투명 시트의 녹색 디테일·부분 알파 보존, 입력 버퍼 보존, 불투명 시트의 무변경 통과를 포함한다.
- 새 투명 원본을 받기 전이므로 교체 후 40개 포즈의 실제 실루엣과 정렬 확인은 남아 있다.
- 일시정지 메뉴는 생성 시 비활성 부모를 포함해 `ScrollRect` 참조를 확보하고 재사용한다. 메뉴 버튼·직접 Pause·포커스 상실·앱 일시정지 후 메뉴 재열기와 스크롤 초기화에 대한 PlayMode 회귀 테스트를 추가했다.
- `BattleArenaTests`에 실제 Sprite 선택·공유 결과·일시정지와 40개 영역 로딩·가져온 알파 확인을 추가했다. **작업 환경에 Unity Editor가 없어 Unity 컴파일, 임포터 콜백, PlayMode 실행과 실제 전투 화면은 아직 검증하지 못했다.** Unity 6000.3.5f2에서 프로젝트를 열어 Test Runner의 EditMode/PlayMode를 실행하고 `RunMap`에서 판정과 모션을 확인한다.
