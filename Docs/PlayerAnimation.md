# 플레이어 판정 애니메이션

제공된 분홍 단발·기계 수신부 헤드셋 캐릭터를 기준으로 **8개 시트, 40개 키포즈**를 만들었다. 이미지 8장이 모두 설치되면 `RunMap`의 준비 화면과 실제 연주 화면 모두 새 캐릭터를 자동으로 사용한다. 이미지나 Animator를 Inspector에 별도로 연결할 필요는 없다.

모션 PNG 8장과 Sprite Editor 분할 정보가 포함되어 있다. `PlayerMotionSprites`는 `idle_0`, `tap-left_1` 같은 이름으로 가져온 실제 Sprite를 사용한다. 한 시트라도 없거나 분할이 불완전하면 기존 `weapon-master` 초상화를 사용한다.

현재 재생 방식은 결과 키포즈 → 복귀 키포즈 → Idle을 교체하는 방식이다. 주인공 전체에 더하던 상하 흔들림, 앞뒤 이동, 피격 기울기, 눌림·늘어남은 제거했다. 입력 유지에는 준비 → 유지 포즈를 사용한다. 연속 중간 프레임을 그린 전통적인 프레임 애니메이션이나 관절 리깅은 아니다.

## 동작과 판정

| 입력 | Perfect | HalfMiss | Miss |
|---|---|---|---|
| Tap 왼손 | 왼손 잽 | 뻗은 왼팔이 위로 빗나감 | 왼팔을 뻗은 채 몸통 피격 |
| Tap 오른손 | 몸통 앞을 가로지르는 오른손 크로스 | 오른팔이 위·바깥으로 빗나감 | 오른팔을 든 채 몸통 피격 |
| Tap 어퍼 | 위로 올려치는 펀치 | 올려친 팔이 옆으로 빗나감 | 팔을 든 채 몸통 피격 |
| Hold | 낮게 교차한 가드로 받아냄 | 교차한 팔을 유지한 채 움츠러듦 | 가드가 벌어지며 피격 |
| Dive | 몸을 앞으로 낮춰 덕킹 | 머리를 찧고 움츠러듦 | 바닥에 옆으로 누움 |
| Flick | 점프 | 다리가 걸려 공중에서 균형을 잃음 | 엎어지며 턱을 찧음 |
| Shake | 양손으로 밀쳐냄 | 밀던 손을 몸 쪽으로 접어 가드 | 양팔이 벌어지며 피격 |

## 프레임 대응

인덱스는 시트의 왼쪽 위부터 가로 순서다.

| PNG | 배열 | 인덱스 순서 |
|---|---|---|
| `idle` | 2×2 | 0 기본 대기, 1 박자에 맞춘 낮은 대기, 2 공용 앉기, 3 공용 일어나기 |
| `tap-left`, `tap-right`, `tap-upper` | 각각 2×2 | 0 준비/팔 회수, 1 성공, 2 반미스, 3 몸통 피격 |
| `hold` | 3×2 | 0 가드 진입, 1 유지, 2 받아내기, 3 반미스, 4 가드 해제 피격, 5 복귀 |
| `dive` | 3×2 | 0 숙이기, 1 덕킹, 2 머리 피격, 3 누움, 4 앉아서 정비, 5 일어나기 |
| `flick` | 3×2 | 0 도약 준비/착지, 1 점프, 2 다리 걸림, 3 턱 피격, 4 앉아서 정비, 5 일어나기 |
| `shake` | 3×2 | 0 손 준비, 1 밀기, 2 밀쳐내기 마무리, 3 말린 가드, 4 벌어진 팔 피격, 5 복귀 |

`PlayerMotionTimeline`은 Tap의 세 시트를 논리적인 12프레임으로 다룬다. `PlayerMotionSprites`가 `punch * 4 + frame`을 해당 시트의 Sprite로 연결한다. Dive/Flick은 각각 자기 시트의 정비 포즈를 사용하며 Idle의 공용 복귀 2장은 후속 연출용으로 보관한다.

## 실제 입력과 재생

- `RhythmRound.Results`의 입력 종류, 최종 Grade, `JudgedAtSeconds`를 그대로 사용한다. 준비 화면이나 미래의 노트만 보고 성공 동작을 미리 재생하지 않는다.
- Tap은 실제 결과나 공미스 누르기가 생성될 때 세 펀치 중 하나를 무작위로 선택한다. 직전 펀치는 제외한다. 여러 몬스터가 같은 입력을 공유하면 선택은 한 번이고, 실패와 복귀도 같은 펀치 종류를 유지한다.
- Hold/Dive는 유효한 접촉을 유지할 때 준비·유지 포즈를 사용한다. Shake는 구간이 자동으로 열렸다는 이유만으로 움직이지 않으며, 실제로 인정된 이동 거리가 늘 때 밀기 포즈를 사용한다. 복합 유지 중 실제 Shake 움직임이 있으면 짧게 밀기를 보여준다.
- 판정 순간 결과 포즈를 즉시 보여준다. 결과 포즈 길이는 최대 0.24초, 일반 복귀까지는 최대 0.48초이며 빠른 BPM에서는 줄어든다.
- Dive/Flick의 Miss는 누움 → 앉기 → 일어나기 순서다. 다음 입력까지 충분한 틈이 없으면 앉아 있는 단계를 생략한다. 전체 길이는 최대 0.84초다. 새로운 판정이나 유효 접촉은 이전 피격·복귀보다 우선한다.
- 한 시점에 여러 종류가 판정되면 신체 포즈는 더 나쁜 Grade를 우선하고, 같은 Grade에서는 Flick → Dive → Shake → Hold → Tap 순서다. 각 몬스터를 향한 대응 효과와 판정·피해 계산은 모두 유지된다.
- `round.ElapsedSeconds`를 사용하므로 일시정지와 함께 이미지·이동·이펙트가 멈춘다. 시간이 크게 건너뛰면 끝난 반응을 다시 재생하지 않는다.
- 화면의 작은 한글 동작 이름을 새 동작에 맞추고 글꼴의 글자 집합도 갱신했다. 판정·피해 규칙은 변경하지 않았다.

판정할 노트가 없는 공미스 입력은 `RhythmRound.FreeInput`에서 별도로 전달한다. 짧게 누르면 펀치 한 번, 0.18초와 반 박 중 짧은 시간 이상 유지하면 가드, 유지하다 떼면 덕킹, 빠르게 움직여 떼면 점프, 누른 채 실제로 움직이면 밀기 포즈를 보여준다. 짧은 Tap을 뗄 때 펀치를 다시 선택하지 않는다. 새 공미스 동작은 이전 복귀를 끊을 수 있으며 유효한 Hold/Shake 접촉과 Flick 준비는 기존 노트 모션을 우선한다.

공미스는 성공 동작의 실루엣을 사용하되 Grade가 없는 입력 피드백이다. 화면에는 `공미스`를 표시하고 판정 횟수·피해·반격 효과를 만들지 않는다. 일시정지 중에는 멈추며 메뉴 뒤 재접촉을 새 누르기나 큰 Shake로 취급하지 않는다.

## 지면과 크기 조절

Project 창에서 `Assets/BBSB/Resources/BBSB/BattleArt/PlayerMotionDisplay.asset`을 선택한다. 준비 화면과 실제 전투가 이 설정을 함께 사용한다.

| Inspector 항목 | 조절 대상 |
|---|---|
| Ground Position | 화면 왼쪽 아래를 (0,0)으로 하는 주인공의 지면 위치. 기본 (0.14, 0.15) |
| Character Scale | 모든 포즈의 공통 배율. 기본 0.5로, 이전 크기의 절반 |
| Reference Pose | 크기를 비교할 기준 대기 Sprite. 기본 idle_0 |
| Motion Sheet → Sheet Scale | Idle, 각 Tap, Hold, Dive, Flick, Shake 시트 전체의 배율 |
| Pose → Pose Scale | 선택한 포즈 하나의 추가 배율 |
| Ground Offset (X / lift) | 기준 캐릭터 높이 단위의 가로 보정과 의도적인 공중 높이. Y=0이면 지면에 접촉 |
| Show Idle Reference | 기준 대기 자세를 반투명하게 겹친 Inspector 미리보기 |

미리보기의 녹색 선과 금색 점이 지면과 기준점이다. 사용자가 조정한 시트·포즈별 배율과 오프셋을 유지한다. 현재 Flick 점프(1)의 높이는 0.4, 공중에서 걸리는 포즈(2)는 0.3이며 앉기·넘어짐에는 개별 접지 보정이 있다. 공중 높이도 시간이 흐르며 흔드는 값이 아니라 해당 포즈의 고정된 보정이다.

각 PNG는 **Sprite Mode: Multiple**로 가져온다. 이미 작성된 40개 분할 사각형과 Sprite ID를 유지하고, Custom Pivot을 원본의 아래쪽 접촉점에 맞췄다. 특정 발 기준을 바꾸려면 해당 PNG의 **Sprite Editor → 포즈 선택 → Pivot: Custom**에서 수정하고 Apply한다. 분할 이름은 기존 `시트명_번호`를 유지한다.

게임은 Sprite의 피벗을 UI Image의 피벗으로 연결한다. 사각형마다 같은 화면 크기를 채우지 않고, `Sprite.rect / Pixels Per Unit`에 기준 자세와 동일한 배율을 적용한다. 따라서 앉기·눕기의 낮은 높이가 유지되고, 배율을 바꿔도 발 기준점은 지면에 남는다. 지면을 옮기면 그림자, 무기와 공격 효과의 기준 위치도 함께 이동한다. PNG 픽셀이나 알파를 다시 처리하지 않으며, 런타임 균등 격자 재분할도 하지 않는다.

설정 에셋은 실행 중에도 반영되며 Inspector 미리보기로 Play 진입 없이 조정할 수 있다. Sprite Editor 피벗은 텍스처 재가져오기 후 다음 전투 진입에서 확인하는 것이 안전하다. 원본 분할 범위에 이웃 포즈 조각이 포함된 경우 그 조각도 Sprite의 일부이므로, 해당 아트/분할은 별도로 정리해야 한다.

모션 이미지 경로는 `Assets/BBSB/Resources/BBSB/BattleArt/PlayerMotion/`이다. 컨셉 이미지와 레퍼런스는 `Assets/BBSB/Resources/BBSB/ConceptArt/`에 보관한다. 생성 당시의 프롬프트는 [PlayerMotionPrompts.md](PlayerMotionPrompts.md)에 있다.

## 검증

- .NET 8에서 실제 핵심·모션·크기 계산 소스를 컴파일해 **154개 테스트 통과**. 공미스의 5종 입력 모션·판정/피해 미생성·실제 접촉 우선순위·일시정지와 재접촉을 검사했다. 웅크림·눕기의 비율 유지, 포즈 배율, 화면 크기 변경과 잘못된 값 검사도 포함한다.
- Unity API 대역으로 실제 `PlayerMotionSprites`와 `PlayerMotionDisplay`를 컴파일해 40개 원본 Sprite 선택, 순서가 섞인 Resources 목록, 12개 펀치 연결, 공유 Sprite 수명, 일부 누락 시 초상화 복귀, PPU와 배율 적용을 확인했다. Unity Editor 검증을 대신하지 않는다.
- 이번 변경에서는 PNG 원본과 8개 메타 파일의 40개 분할·ID·발 피벗을 그대로 유지했다. 실제 PNG와 크기 계산 결과로 만든 별도 미리보기에서 지면 정렬·크기·공중 높이를 확인했다.
- `BattleArenaTests`에 원본 Sprite 재사용과 피벗 보존, 두 화면 비율·배율·실제 판정·일시정지/리사이즈·점프 높이에서의 발 위치 검증을 추가했다.
- **작업 환경에는 Unity Editor가 없어 Unity 컴파일·Inspector 미리보기·PlayMode 실행은 확인하지 못했다.** Unity 6000.3.5f2에서 EditMode/PlayMode 테스트를 실행하고 `RunMap`의 준비/연주 화면을 확인한다.
