# 박자 기반 무기 전투

`RunMap`의 기본 전투는 단검과 히터실드로 시작한다. 무기는 보스 처치 후 3개 중 하나를 선택해 보유 목록에 추가하며 자동 장착되지 않는다. 일반·엘리트 보상과 상점에서는 아이템·증강·프레임·박자 주입을 얻는다. [보스 보상과 다음 필드 진행](BossProgression.md)을 참고한다. 장착 한도는 2개에서 시작해 보스를 클리어할 때마다 1개씩, 최대 5개까지 늘어난다. 일반·엘리트·서비스 노드는 한도를 늘리지 않는다. 이전 Call & Response 모드는 `RunBootstrap.Use Five Lane Combat`을 끄면 실행할 수 있다.

단검은 2박마다, 쌍검은 매 박자 Tap 한 번을 무한 반복하며 초반의 기본 박자를 잡아 준다. 다른 공격·지원 무기는 8~12박 패턴을 사용하고 단발 무기는 6~10박 쿨타임을 거친다. 방패는 짧게 유지한다. [무기별 최신 패턴 표](LongWeaponPatterns.md)를 참고한다. 현재 속성은 **빛·어둠·이면·혼돈**이다. 시작 박자·효과 선택·중복 장착·혼돈 전환의 상세 규칙과 에셋 설정은 [무기 속성](WeaponAttributes.md)을 참고한다.

## 실행과 시작 장비

Unity 6000.3.5f2에서 `Assets/BBSB/Scenes/RunMap.unity`를 열고 탐험 시작 → 몬스터 지역 → 연주 시작. 한 박마다 `Beat → Block → Shake → Beat`를 표시하며 **마지막 Beat가 나오는 순간 곡·전투·입력을 함께 시작한다.** 앞의 세 단어는 곡의 -3/-2/-1박이고 마지막 단어는 0박이다. `RunBootstrap` Inspector의 **Count In Words** 네 항목을 바꾸면 다른 단어를 사용할 수 있다. 곡 시작 전 멈췄다가 이어하면 카운트인을 다시 보여준다.

전열·후열 모두 곡의 첫 3박과 끝 3초에는 공격 노트를 점유하지 않는다. 끝에 걸리는 적 홀드의 꼬리와 피해도 보호 구간 전에 자른다. 곡 반복 때도 적용하며 플레이어의 무기 리듬은 유지한다.

| 슬롯 / 키 | 무기 | 동작 | 종료와 대기 |
|---|---|---|---|
| 1 / D | 단검 (`dagger`) | 2박마다 Tap 한 번 | 성공·반미스 시 무한 반복. 미스 대기 2박. 혼돈에서는 박자 전환 추가 |
| 2 / F | 히터실드 (`heater-shield`, 화면 이름 Heater Shield) | 누르는 순간 패링·홀드 시작. 속성에 맞는 가까운 박자를 기준으로 2박 Hold 패턴. 패링이 없어도 홀드 가능, 홀드 중 피해 50% 감소 | 패링 성공 시 종료·해제 뒤 바로 재사용. 패링이 없으면 종료·해제부터 2박 쿨타임. 해제는 미스가 아님 |
| 자유 배치 | 대형 방패 (`tower-shield`) | 누르는 순간과 1.5박 Hold 끝에서 떼는 순간에 패링. 떼기 패링 성공 시 2.5박의 강타 확정 | 패링 성공 시 쿨타임 회복. 진행 중인 Hold·반격은 유지 |
| 자유 배치 | 쌍검 (`dual-swords`) | 매 박자 Tap 한 번 | 성공·반미스 시 무한 반복. 미스 대기 2박. 혼돈에서는 박자 전환 추가 |
| 연속 2라인 | 봉 (`staff`) | 8박 두드리기·반대쪽 Hold·왕복 | 쿨타임 8박. 혼돈은 무작위 박자 두 구간 |
| 자유 배치 | 신령 방울 (`spirit-bell`) | 12박. 두 번의 양옆 호출과 중간 쿨타임 감소 | 쿨타임 10박. 진행 중인 대상 패턴은 유지 |

S·D·F·Space·J·K·L은 처음부터 모두 열려 있다. S/L은 복수 라인 무기에만 사용한다. 장착 한도는 무기 개수이며 입력 위치의 잠금 개수가 아니다. 준비 화면의 **무기 편성** 또는 메뉴의 장비 화면에서 무기를 드래그해 배치한다. 미사용 위치에도 키 이름은 남고 다른 무기를 해제해도 위치가 당겨지지 않는다. [배치·중심 좌표·확장 라인·Offset 패턴 규칙](EquipmentPlacement.md)을 참고한다.

히터실드의 방어는 누른 실제 시점에 시작하고, 종료는 보정된 시작 박자 +2박이다. 예를 들어 빛 히터실드를 1.42박에 누르면 1박 시작으로 취급해 3박에 끝나고, 어둠은 1.5박 시작으로 취급해 3.5박에 끝난다. 키를 계속 들고 있어도 종료 후 자동으로 다시 시작하지 않는다. 여러 방패를 들어도 피해 감소율은 가장 큰 하나만 적용한다. 패링은 같은 박자에 닿는 모든 공격을 전량 막고, 홀드 피해 감소와 별도로 집계한다. 피해 감소는 적 공격의 실제 박자에 샘플링하므로 이후의 늦은 패링 판정 대기 중 홀드가 끝나더라도 소실되지 않는다. 홀드 종료와 정확히 같은 박자의 공격에는 홀드 감소가 적용되지 않는다.

방패로 실제 패링에 성공하면 **그 방패의 쿨타임을 즉시 회복**한다. 진행 중인 Hold와 확정된 반격은 계속 입력할 수 있으며, 이 패턴이 완료·해제·실패로 끝나도 쿨타임을 다시 부여하지 않는다. 히터실드는 패링 후 떼고 다시 눌러 다음 연타를 패링할 수 있다. 회복은 해당 패턴에만 적용하고 다음 사용으로 이월하거나 다른 무기의 쿨타임을 바꾸지 않는다. 첫 입력 보정만 받은 경우, 패링 실패, 단순 Hold 피해 감소에는 회복이 없다. 실제 패링 창 안의 반미스도 전량 방어와 쿨타임 회복을 적용한다. 대형 방패의 시작 패링은 추가 방어 기회이며, 강타 조건은 기존처럼 Hold 끝에서의 떼기 패링 성공이다.

## 원근 노트 트랙

- 미래 **최대 3박**을 정박 눈금 3개와 작은 반박 보조 눈금으로 표시한다. 화면 하단에 아래쪽으로 넓어지는 원근 레인을 사용하며, 표현 길이가 바뀌어도 미리보기 범위는 3박이다.
- 노트는 **화면 아래에서 위의 판정선으로 일정한 속도**로 이동한다. 정박·엇박을 지날 때 멈추거나 가속하지 않는다. 같은 곡에서는 남은 시간에 비례해 화면 위치가 바뀐다.
- `SteppedNoteTrack`의 이름은 기존 도구 호환을 위해 유지하지만, `Distance(noteBeat, currentBeat)`는 남은 박자를 선형으로 계산한다. `Depth`는 이를 아래쪽 생성점(0)에서 위쪽 판정점(1)으로 바꾼다. 일반 노트, Hold 양끝, 적 공격 노트, 파편과 판정 효과가 같은 좌표를 사용한다. 프레임 누적 보간 없이 실제 음악 시각을 사용하므로 일시정지나 긴 프레임에도 예약된 판정 시각에 도착한다.
- 레인 위에는 **작은 무기 아이콘과 키 이름**을 표시한다. 실제 부유 무기는 플레이어 주변에 별도로 표시하며, 입력 직후 짧은 판정 피드백을 남긴다.
- 적 공격은 공통 붉은 공격 노트로 표시한다. 전열·후열은 이미지로 구분하지 않는다. Hold 공격에는 실제 지속 시간을 나타내는 연결 몸체를 붙인다. 추후 시각적 구분은 공격 형태에 맞춰 추가한다. 여러 방패의 기존 물리 레인 분배는 그대로다.
- Hold 끝이 3박 밖이면 연결 부분을 잘라 표시하고 아직 보이지 않는 끝점은 그리지 않는다.
- 활성 패턴의 Pending/Holding 노트는 선명하게, 아직 조건을 기다리는 Locked 노트는 흐린 테두리와 옅은 내부로 표시한다. 예고 Hold는 점선이다. 실제 성공 시 같은 위치에서 선명한 노트로 바뀐다.
- 반복 무기는 현재 패턴을 성공한다고 가정한 다음 반복들도 3박 범위 안에 흐리게 표시한다. 단검은 2박 간격, 쌍검은 1박 간격으로 실제 노트와 반복 예고를 표시한다. 시작 전이나 쿨타임에는 예고를 생성하지 않는다.
- 실패로 조건이 무효가 되거나 반복이 끊기면 화면에 보이던 해당 예고가 조각으로 갈라져 반 박자 동안 흩어지고 사라진다. 이미 확정된 남은 패턴은 계속 표시한다. 파편도 전투 시계를 쓰므로 일시정지하면 함께 멈춘다.
- `FiveLaneNoteTimeline`은 표시용 예측만 만들며 Core의 NoteStates·입력 대상·피해·콤보를 변경하지 않는다. 매우 짧은 사용자 패턴에서도 표시를 무한 생성하지 않도록 레인당 128개로 제한한다.
- 방패 트랙의 붉은 V 표시는 적 공격이다. 같은 도착점에 닿을 때 패링한다. 적 위의 공격 카운트와 `PARRY IN … / PARRY NOW`도 같은 전투 시계를 사용한다. 패링 완료 표시는 청록색이다. 패링 입력점은 금색으로 표시하며, 대형 방패는 Hold의 시작과 끝에 모두 표시한다.
- 적에서 플레이어로 향하는 공격 표시는 충돌 1박 전부터 같은 공통 곡선을 따라 이동한다. 반박 공격도 충돌 시각을 유지하며 방패 트랙의 V 표시와 동시에 도착한다.
- 현재 정박에 판정점이 맥동한다. 캐릭터와 무기 슬롯은 노트의 판정점과 별개다.

## 생성된 패턴과 조건부 노트

`PhraseLane.NoteStates`는 Locked / Pending / Holding / Hit / Missed / Skipped를 구분한다. 일반 패턴을 시작할 때 조건 없는 모든 노트가 생성된다. 한 노트를 놓쳐도 다른 생성된 노트는 유지되며 마지막 노트까지 판정한 뒤 쿨타임에 들어간다. 미스는 콤보와 연속 완주를 초기화하지만 자체 피해는 주지 않는다. 모든 노트를 성공하면 무기 정의에 따라 반복하거나 종료한다.

| 무기 | 조건 | 생성 시점 |
|---|---|---|
| 버클러 / 원형 방패 | 첫 누르기 패링 성공 | 정해진 반격 노트들을 한 번에 생성. 반격 하나를 놓쳐도 나머지는 유지 |
| 대형 방패 | 1.5박 Hold 끝에서 떼기 패링 성공 | 시작 +2.5박의 반격 생성 |
| 활 | 각 Hold 당기기 성공 | 해당 당기기의 발사만 생성. 실패해도 뒤 당기기는 독립적으로 진행 |
| 단검·쌍검 | 현재 입력 성공·반미스 | 각각 2박·1박 뒤 다음 입력 확정. 혼돈에서는 예고된 전환 구간으로 이어질 수 있음 |
| 검·해머 등 일반 패턴 | 별도 조건 없음 | 패턴 시작 시 전체 생성. 3박 밖의 노트는 시간이 되면 화면에 진입 |

단검·쌍검은 모든 속성에서 2박·1박의 기본 연주를 무한 반복한다. 혼돈 단검·쌍검·진자는 유지 시간 이후 박자 전환도 진행한다. 새로 혼돈을 허용한 21종은 각 구간의 빛/어둠을 독립 추첨해 두 구간을 연주한 뒤 쿨타임에 들어간다. 나머지 단발 무기는 한 구간 후 쿨타임이다. 활은 한 구간에서 세 번 당기고 발사하며, 석궁은 두 번 장전한다. `WeaponPhrase`와 새 Authoring 에셋의 `repeat` 기본값은 false이고 사용자 정의 반복 패턴은 계속 지원한다.

패링 위치와 횟수는 제한하지 않는다. 예를 들어 4박 프레이즈의 0 / 1.5 / 3박에 패링을 넣고 반복하면 트레실로 패링 방패를 만들 수 있다. 해머는 12박 안에 트레실로 세 묶음을 연주하고 구간 완주 시 추가 피해와 4박 그로기를 적용한다.

## 신령 방울의 예약 발동

- 성공한 방울 노트의 기준 박자 +1박을 대상 무기 속성에 맞는 가까운 시작점으로 보정해 양옆 패턴을 예약한다. 대상의 호출 대기가 1박보다 길면 그 대기도 확보한다. 예약된 첫 노트에 대기를 중복 적용하지 않는다. 인접 물리 라인만 보며 빈 라인을 건너뛰지 않는다. 기존 진동 방울(`bell`)과 별도의 무기다.
- 맞닿은 입력 라인의 시작 Offset을 사용하므로, 방울 왼쪽의 봉은 오른쪽에서 시작한다. S/L도 실제 물리 순서대로 처리한다.
- 예약 시 대상의 쿨타임·실행 상태와 무관하게 기록한다. 실행 시 Ready/Cooldown이면 쿨타임을 무시하고 시작하며, Playing이면 현재 패턴과 위상·홀드를 그대로 유지하고 예약을 취소한다. 같은 무기의 동일 박자 중복 예약은 한 번만 실행한다.
- 예약은 최대 3박 범위에서 흐린 노트로 표시한다. 실행되면 조건 없는 노트가 선명해지고, 실행 중이라 취소된 예약만 깨진다. 원래 연주 중이던 노트는 유지한다.
- 패턴 시작과 입력 성공은 별개다. 예약된 첫 노트부터 플레이어가 해당 라인을 입력한다. 첫 노트에도 일반 판정의 빠른 입력 창을 적용하고 예약 박자는 이동하지 않는다. 홀드·패링·후속 조건을 자동으로 성공시키거나 가짜 키다운을 만들지 않는다.
- 이 구분으로 방울끼리 인접해도 입력 없이 자동으로 무한 연쇄하지 않는다. 일시정지는 예약 시계도 멈추고, 긴 프레임에서는 예약·홀드·미스·쿨타임을 시간순으로 처리한다.

## 시계와 판정

DSP 시간에서 음악의 beat를 구한다. 입력·적 공격·Hold·노트·쿨타임은 같은 시계다. 일반 무기의 Ready 상태 첫 누르기는 **호출**이며 피해·회복·콤보·Perfect를 발생시키지 않는다. 호출을 누른 채 기다려도 첫 노트를 자동 성공시키지 않는다. 키를 떼고 예고된 첫 노트에 맞춰 다시 누른다.

`FirstNoteDelayBeats`는 호출 후 첫 판정까지 확보할 최소 준비 시간이다. 기본값은 공격·지원 무기 1박, 방패 0박이다. 호출 시 무기 속성으로 빛/어둠 위상을 고른 뒤, 최소 대기를 확보하는 그 위상의 다음 박자에 첫 노트를 예약한다. 예를 들어 빛 단검을 0박에 호출하면 1박, 0.13박에 호출하면 2박에 첫 노트가 온다. 이후 반박 주입은 그 첫 판정 박자 +0.5박, 단검·쌍검 반복은 +2박/+1박 간격이며 매 반복마다 호출 대기를 추가하지 않는다. 첫 노트가 오기 전의 재입력은 예약을 당기거나 다시 시작하지 않는다.

0박 대기는 기존 즉시 실행 모드다. 방패는 누르는 실제 순간부터 패링·홀드가 가능하고, 가까운 속성 박자를 패턴 기준으로 사용한다. 첫 노트 수락 보정은 이 모드에만 적용한다. 실제 패링·반격에는 적 공격의 입력 창 안에서 누르거나 떼는 것이 필요하다.

대기 뒤 **첫 노트부터** 일반 판정을 적용한다. Perfect는 ±90ms, 반미스는 ±180ms이며 반미스는 최대 0.24박, Perfect는 그 75%로 제한한다. 반미스 피해는 50%, 패링은 전량 방어다. 늦은 패링 허용 시간이 끝난 뒤 적 피해를 확정한다.

### 준비 콜과 효과 리스폰스

- `notes[].role = Call`: 판정을 받는 준비 입력. Tap/Hold 모두 가능하며 성공·실패와 콤보는 집계하지만 피해·회복·가드·마무리 효과는 없다. 활 당기기와 석궁 장전도 이 역할을 사용한다.
- `notes[].role = Response`: 공격·방어·회복·지원 효과가 있는 노트. 기존 에셋은 이 값으로 읽힌다.
- `condition = AllCalls`: 같은 패턴 구간에서 **자신보다 앞에 있는 모든 콜**을 성공해야 리스폰스가 확정된다. 하나라도 미스·취소되면 해당 리스폰스와 예고를 취소한다. 다른 확정 노트는 유지한다. `Hit`/`Parry`의 개별 선행 노트 조건도 계속 쓸 수 있다.
- 콜에는 박자 주입을 장착할 수 있고, 추가된 콜 역시 `AllCalls` 조건에 포함된다. 효과 프레임은 리스폰스에 장착한다. 콜과 리스폰스의 Hold 연결 규칙은 동일하다.

예를 들어 `Use Default Call Timing`을 끄고 `First Note Delay Beats = 2`, 패턴 길이 4박을 설정한다. 0/1/2박에 `Call` 세 개, 3박에 `Response + AllCalls` 한 개를 작성하면 호출 → 최소 2박 준비 → 콜 세 번 → 마지막 공격 한 번이 된다. `AllCalls`에는 prerequisite 인덱스를 지정하지 않는다. 콜 노트의 Effect는 Strike로 두고, 실제 피해량은 리스폰스에 작성한다.

노트 편집기는 호출 대기를 표시하고 준비 콜은 청록색 마름모, 리스폰스는 기존 노트로 구분한다. 오른쪽 예시는 호출 → 대기 → 콜/리스폰스의 자동 입력을 보여 준다.

Esc / II / 포커스 상실 시 모든 시간과 판정을 동결한다. Hold를 유지 중이었다면 해당 키들을 다시 잡은 뒤 재개하며 재접촉은 새로운 패링이 아니다. 준비 화면 복귀에도 같은 전투 객체의 HP·노트·쿨타임을 유지한다. 음악 끝은 반복되며 프레이즈를 초기화하지 않는다. 적 HP 0은 결과 → 보상, 내 HP 0은 게임오버다.

## 프리팹과 데이터 편집

`FiveLaneBattleScreen.prefab`의 `FiveLaneHudBindings`에서 캐릭터·HP·무기·입력·텍스트를 편집한다. 기본 구성은 맨 왼쪽 플레이어, 기존 중앙 플레이어 위치의 선봉, 그 뒤 오른쪽의 후열과 아래 원근 트랙이다. 장착 무기마다 실제 무기 하나가 플레이어 주위를 돌며, 근접 리스폰스 성공 때 목표에게 날아갔다 돌아오고 원거리 투사체도 그 무기 위치에서 출발한다. 방패는 실제 방어 중 플레이어 앞으로 나오며 적 공격의 도착점은 플레이어 몸통이다. 모든 연출은 전투 시계를 사용해 일시정지와 함께 멈춘다. `Arrange Equipped Lanes`는 S·D·F·Space·J·K·L의 고정 위치에 트랙과 입력을 배치한다. 장착 개수가 바뀌어도 키 위치는 압축되지 않는다. 처음부터 7개 입력 라인을 포함한 전체 폭으로 정렬한다. 직접 만든 트랙 위치를 사용하려면 이 옵션을 끄고 `judgmentPoints`, 입력과 텍스트를 편집한다. 기본 트랙은 화면 높이의 6.5% 생성점에서 42% 판정선까지 위로 이어지고 상단의 짧은 띠에 키만 놓인다. 원근 터치 판정은 노트와 같은 투영식을 사용한다. 캐릭터 슬롯과 무기 위치는 이 옵션으로 이동하지 않는다.

기존 프리팹에도 누락된 공격 예고와 슬롯을 보완하므로 수동 재생성이 필요하지 않다. 필수 연결이 잘못된 HUD는 원인을 경고하고 해당 실행에서 기본 HUD를 사용한다. 렌더링·오디오 초기화 실패 시 전투를 정지하고 준비 복귀·재시도를 제공한다.

캐릭터는 기존 Player/MonsterAuthoring과 SpriteRenderer/Animator 또는 Image 초상화를 사용한다. `SpriteCanvasGraphic`은 CanvasRenderer를 필수로 요구하며 생성할 때도 명시적으로 붙인다. Animator가 없는 몬스터도 짧은 준비 동작과 숫자 예고를 표시한다. 새 넓은 방패·축적 방패 이미지는 [통합 전투 이미지 팩](IntegratedCombat.md#이미지-설치)으로 별도 설치한다.

`Create → BBSB → Weapon Phrase` 에셋을 `Resources/BBSB/WeaponPhrases/`에 두면 해당 무기 ID와 시작 Offset의 기본 프레이즈를 덮어쓴다.

| 필드 | 의미 |
|---|---|
| startLaneOffset | 해당 무기의 점유 범위에서 왼쪽부터 센 시작 입력 Offset. Offset마다 패턴·피해·방어 효과를 따로 작성 |
| useDefaultCallTiming / firstNoteDelayBeats | 기본 호출 대기 사용 / 무기별 최소 대기. 방패 기본 0, 나머지 기본 1박 |
| notes: role / condition | Call 준비 입력 / Response 효과 입력. AllCalls는 앞선 콜 전체 성공 조건 |
| notes: laneOffset | 시작한 라인을 기준으로 한 상대 라인. 점유 폭 안에서 순환하며 첫 노트는 0 |
| notes: beat / holdBeats / damage / effect | 박자, 유지 길이, 피해, Strike / Parry / StartAdjacent(인접 패턴 예약) / Heal(회복) |
| notes: condition / prerequisite | Always는 즉시 생성. Hit/Parry는 prerequisite 인덱스의 앞선 노트 성공 후 생성 |
| anyAttribute / attribute, bothSides / beatSide | 속성 및 시작 박자별 효과 선택. 첫 입력의 격자는 무기의 속성이 결정 |
| chaosTransition / chaosMinimumBeats / chaosTransitionChance / chaosEffectMultiplier | 혼돈 전환 패턴 및 유지 시간·전환 확률·효과 배율 |
| holdDamageReduction | 홀드 중 피해 감소율, 히터실드 0.5 |
| parryRequired | 후속 패링 노트에서 실제 패링을 요구할지 결정. 0박 대기 첫 누르기만 수락 보정하며 반격에는 실제 패링이 필요 |
| releaseEndsPhrase | 자발적인 홀드 해제로 패턴 종료 |
| completionCooldownBeats | 정상 완료·자발적 종료 뒤의 쿨타임, 히터실드 2 |
| missCooldownBeats / repeat | 실패 후 대기 길이 / 성공한 패턴의 반복 |
| parryInput | KeyDown(0), KeyUp(1), Both(2). KeyUp/Both의 모든 패링 노트는 Hold여야 함. Both는 시작에도 패링을 시도하고 끝의 떼기 패링 판정을 유지 |

첫 노트는 0박이고 서로 겹치지 않아야 한다. Hold 끝은 다음 노트 시작이나 패턴 길이와 같아도 된다. 같은 라인의 맞닿은 Hold는 유지 입력을 이어받는다. Hit/Parry 조건은 앞선 노트를 참조하고 Parry 조건은 패링 노트를 참조해야 한다. AllCalls 리스폰스는 앞에 콜이 하나 이상 있어야 한다. 잘못되거나 같은 무기 ID + 속성 + 시작 박자 + 시작 Offset + 전환 여부가 중복된 에셋은 오류를 남기고 해당 Offset의 기본 정의를 쓴다. 점유 폭 밖의 노트 Offset도 거부한다.

## 검증

`dotnet run --project Tools/CoreChecks/BBSB.CoreChecks.csproj --configuration Release`와 GitHub Core checks로 엔진 비의존 코드를 컴파일하고 회귀 검사를 실행한다. 호출 대기·첫 노트 일반 판정·복수 콜 조건·쿨타임 재시작·후속 판정, 단검 연쇄, 조건부·반복 예고의 확정과 파괴, 확정된 일반·반격 패턴 유지, 히터실드 피해·종료·일시정지, 일정한 화면 속도와 반박 도착 시각, 보유·장착 분리, 보스별 한도 증가, 중심 스냅, 겹침 교체의 원자성, 무기 참조 유지, S/L 제한, 시작 Offset별 패턴과 기존 패링/그로기를 검사한다.

PlayMode 검사에는 실제 CanvasRenderer의 메시 생성, 기본 장비 2개, Space/K의 비연속 배치, L 입력의 홀드 복귀, 드래그 중심과 범위 초과 거부·S/L 즉시 배치, 초기화 복구, 여러 화면 비율의 캐릭터 배치를 포함한다. GitHub의 C# 구문 검사는 Unity API 컴파일이나 PlayMode 실행을 대신하지 않는다. 이 작업 환경에는 Unity Editor가 없으므로 Unity에서의 실행 확인은 별도로 필요하다.
