# 박자 기반 무기 전투

`RunMap`의 기본 전투는 단검과 히터실드로 시작한다. 보상과 상점에서 빈 슬롯을 채우고 최대 5개일 때부터 교체한다. 이전 Call & Response 모드는 `RunBootstrap.Use Five Lane Combat`을 끄면 실행할 수 있다.

## 실행과 시작 장비

Unity 6000.3.5f2에서 `Assets/BBSB/Scenes/RunMap.unity`를 열고 탐험 시작 → 몬스터 지역 → 연주 시작. 4박 카운트 이후 키보드 또는 하단 입력 영역으로 연주한다.

| 슬롯 / 키 | 무기 | 동작 | 종료와 대기 |
|---|---|---|---|
| 1 / D | 단검 (`dagger`) | 정박에 입력. 성공할 때마다 정확히 다음 1박 뒤의 노트 하나 생성. 반미스도 성공으로 연결 | 실패 시 2박 쿨타임. 다음 노트는 생성되지 않음 |
| 2 / F | 히터실드 (`heater-shield`, 화면 이름 Heater Shield) | 누르는 순간 패링. 최대 2박 Hold. 패링이 없어도 홀드 가능, 홀드 중 피해 50% 감소 | 2박 종료 또는 조기 해제 시점부터 2박 쿨타임. 해제는 미스가 아님 |
| 3~5 / Space·J·K | 획득한 무기 | 무기별 프레이즈 | 빈 슬롯은 레인·무기·입력 영역을 숨김 |

히터실드는 누른 실제 시점부터 2박을 센다. 키를 계속 들고 있어도 종료 후 자동으로 다시 시작하지 않는다. 여러 방패를 들어도 피해 감소율은 가장 큰 하나만 적용한다. 패링은 같은 박자에 닿는 모든 공격을 전량 막고, 홀드 피해 감소와 별도로 집계한다. 피해 감소는 적 공격의 실제 박자에 샘플링하므로 이후의 늦은 패링 판정 대기 중 홀드가 끝나더라도 소실되지 않는다. 홀드 종료와 정확히 같은 박자의 공격에는 홀드 감소가 적용되지 않는다.

## 짧은 노트 트랙

- 미래 **최대 3박**을 정박 눈금 3개와 작은 반박 보조 눈금으로 표시한다. 긴 원근 레인 대신 캐릭터 아래의 짧은 세로 트랙을 사용한다.
- 노트는 자물쇠 번호판처럼 **한 박자에 한 번 출발하고 안착**한다. 음악의 공통 정박을 기준으로 시작과 끝은 느리고 중간은 빠른 대칭 5차 곡선 `6t⁵ − 15t⁴ + 10t³`을 적용한다. 정박에서 속도와 가속도가 0이고, 반박에서는 정확히 중간 지점을 최대 속도로 통과한다. 이동 거리의 약 79%를 가운데 반 박자 동안 지나며, 반박마다 멈추지 않는다.
- `SteppedNoteTrack.Distance(noteBeat, currentBeat)`는 노트의 예약 시각과 현재 음악 시각을 같은 곡선 좌표로 변환한다. 모든 레인이 같은 시점에 가속·감속하고 정박·반박 노트, 자유 시점에서 시작한 Hold 끝도 각각 실제 판정 시각에 도착한다. 프레임마다 보간을 누적하지 않아 일시정지나 긴 프레임에도 위상이 밀리지 않는다.
- Hold 끝이 3박 밖이면 연결 부분을 잘라 표시하고 아직 보이지 않는 끝점은 그리지 않는다.
- 미리 예약된 미래 반복이나 조건 미충족 노트를 그리지 않는다. 실제 생성된 Pending/Holding 노트만 표시한다.
- 방패 트랙의 붉은 V 표시는 적 공격이다. 같은 도착점에 닿을 때 패링한다. 적 위의 공격 카운트와 `PARRY IN … / PARRY NOW`도 같은 전투 시계를 사용한다. 패링 완료 표시는 청록색이다.
- 적에서 플레이어로 향하는 공격 표시는 충돌 1박 전부터 같은 공통 곡선을 따라 이동한다. 반박 공격도 충돌 시각을 유지하며 방패 트랙의 V 표시와 동시에 도착한다.
- 현재 정박에 판정점이 맥동한다. 캐릭터와 무기 슬롯은 노트의 판정점과 별개다.

## 생성된 패턴과 조건부 노트

`PhraseLane.NoteStates`는 Locked / Pending / Holding / Hit / Missed / Skipped를 구분한다. 일반 패턴을 시작할 때 조건 없는 모든 노트가 생성된다. 한 노트를 놓쳐도 다른 생성된 노트는 유지되며 마지막 노트까지 판정한 뒤 쿨타임에 들어간다. 미스는 콤보와 연속 완주를 초기화하지만 자체 피해는 주지 않는다. 모든 노트를 성공하면 무기 정의에 따라 반복하거나 종료한다.

| 무기 | 조건 | 생성 시점 |
|---|---|---|
| 버클러 / 원형 방패 | 첫 누르기 패링 성공 | 정해진 반격 노트들을 한 번에 생성. 반격 하나를 놓쳐도 나머지는 유지 |
| 대형 방패 | 1.5박 Hold 끝에서 떼기 패링 성공 | 시작 +2.5박의 반격 생성 |
| 활 | 1박 당기기 성공 | 시작 +2박의 발사 노트 생성. 당기기 실패 시 발사 없음 |
| 단검 | 현재 정박 노트 성공 | 다음 정박 노트 하나 생성 |
| 검·해머 등 일반 패턴 | 별도 조건 없음 | 패턴 시작 시 전체 생성. 3박 밖의 노트는 시간이 되면 화면에 진입 |

패링 위치와 횟수는 제한하지 않는다. 예를 들어 4박 프레이즈의 0 / 1.5 / 3박에 패링을 넣고 반복하면 트레실로 패링 방패를 만들 수 있다. 해머는 연속 세 프레이즈 성공 시 추가 피해와 4박 그로기를 적용하고 해당 구간의 적 공격을 취소한다.

## 시계와 판정

DSP 시간에서 음악의 beat를 구한다. 입력·적 공격·Hold·노트·쿨타임은 같은 시계다. Perfect는 ±90ms, 반미스는 ±180ms이며 반미스는 최대 0.24박, Perfect는 그 75%로 제한한다. 반미스 피해는 50%, 패링은 전량 방어다. 늦은 패링 허용 시간이 끝난 뒤 적 피해를 확정한다. 일반 무기는 첫 입력을 반박 격자에 맞추고, 필수 누르기 패링의 첫 입력은 적 공격 박자에 맞춘다. 이후 패링은 무기의 기존 박자를 유지한다.

Esc / II / 포커스 상실 시 모든 시간과 판정을 동결한다. Hold를 유지 중이었다면 해당 키들을 다시 잡은 뒤 재개하며 재접촉은 새로운 패링이 아니다. 준비 화면 복귀에도 같은 전투 객체의 HP·노트·쿨타임을 유지한다. 음악 끝은 반복되며 프레이즈를 초기화하지 않는다. 적 HP 0은 결과 → 보상, 내 HP 0은 게임오버다.

## 프리팹과 데이터 편집

`FiveLaneBattleScreen.prefab`의 `FiveLaneHudBindings`에서 캐릭터·HP·무기·입력·텍스트를 편집한다. 기본 구성은 왼쪽 전경 플레이어, 위쪽 몬스터, 아래 짧은 트랙이다. `Arrange Equipped Lanes`는 장착 개수에 맞춰 트랙과 입력을 중앙 정렬한다. 직접 만든 트랙 위치를 사용하려면 이 옵션을 끄고 `judgmentPoints`, 입력과 텍스트를 편집한다. 판정점으로부터 화면 높이의 20%가 트랙 길이다. 캐릭터 슬롯과 무기 위치는 이 옵션으로 이동하지 않는다.

기존 프리팹에도 누락된 공격 예고와 슬롯을 보완하므로 수동 재생성이 필요하지 않다. 필수 연결이 잘못된 HUD는 원인을 경고하고 해당 실행에서 기본 HUD를 사용한다. 렌더링·오디오 초기화 실패 시 전투를 정지하고 준비 복귀·재시도를 제공한다.

캐릭터는 기존 Player/MonsterAuthoring과 SpriteRenderer/Animator 또는 Image 초상화를 사용한다. `SpriteCanvasGraphic`은 CanvasRenderer를 필수로 요구하며 생성할 때도 명시적으로 붙인다. Animator가 없는 몬스터도 짧은 준비 동작과 숫자 예고를 표시한다. 별도의 신규 이미지나 음원은 추가하지 않았다.

`Create → BBSB → Weapon Phrase` 에셋을 `Resources/BBSB/WeaponPhrases/`에 두면 해당 ID의 기본 프레이즈를 덮어쓴다.

| 필드 | 의미 |
|---|---|
| notes: beat / holdBeats / damage / effect | 박자, 유지 길이, 피해, Strike 또는 Parry |
| notes: condition / prerequisite | Always는 즉시 생성. Hit/Parry는 prerequisite 인덱스의 앞선 노트 성공 후 생성 |
| startGridBeats | 시작 격자. 단검 1, 일반 0.5, 히터실드 0(자유 시작) |
| holdDamageReduction | 홀드 중 피해 감소율, 히터실드 0.5 |
| parryRequired | false면 키다운 패링을 놓쳐도 홀드 가능 |
| releaseEndsPhrase | 자발적인 홀드 해제로 패턴 종료 |
| completionCooldownBeats | 정상 완료·자발적 종료 뒤의 쿨타임, 히터실드 2 |
| missCooldownBeats / repeat | 실패 후 대기 길이 / 성공한 패턴의 반복 |
| parryInput | KeyDown 또는 KeyUp. KeyUp의 모든 패링 노트는 Hold여야 함 |

첫 노트는 0박이고 서로 겹치지 않아야 한다. Hold 끝은 패턴 길이와 같아도 된다. 조건은 반드시 앞선 노트를 참조하고 Parry 조건은 패링 노트를 참조해야 한다. 잘못되거나 중복된 에셋은 오류를 남기고 기본 정의를 쓴다.

## 검증

`dotnet run --project Tools/CoreChecks/BBSB.CoreChecks.csproj --configuration Release`와 GitHub Core checks로 엔진 비의존 코드를 컴파일하고 회귀 검사를 실행한다. 단검 연쇄, 일반·반격 패턴 유지, 조건부 생성, 히터실드 피해·종료·일시정지, 정박 단위 곡선 이동과 반박 도착 시각, 2→5개 장비 획득과 기존 패링/그로기를 검사한다.

PlayMode 검사에는 실제 CanvasRenderer의 메시 생성, 기본 장비 2개와 숨겨진 빈 슬롯, 초기화 복구, 여러 화면 비율의 캐릭터 배치를 포함한다. GitHub의 C# 구문 검사는 Unity API 컴파일이나 PlayMode 실행을 대신하지 않는다. 이 작업 환경에는 Unity Editor가 없으므로 Unity에서의 실행 확인은 별도로 필요하다.
