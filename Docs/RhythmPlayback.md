# Call & Response 연주

준비 화면의 **연주 시작**이 현재 `BattlePlan`을 한 번 연주하는 `RhythmRound`를 만든다. 몬스터 계획과 입력 결과의 수명을 분리했다. 곡 종료 시 결과를 집계하고 **다시 준비**로 돌아가며 곡·배치·스테이지 ticket·HP는 바뀌지 않는다. 승패와 무기 효과를 연결하기 전이므로 무입력으로 곡을 끝내도 보상을 받지 않는다.

## 화면과 조작

- 16:9·16:10 가로 화면 전체를 전투 장면으로 사용한다. 주인공은 왼쪽 앞, 몬스터는 오른쪽에 서며 우측 상단의 원형 **메뉴**로 일시정지한다. 상태 표시와 메뉴는 장면 위에 겹쳐 표시한다.
- 화면 위쪽에 겹쳐진 `1 & 2 & 3 & 4 &`는 공격 유무와 관계없이 정박/엇박마다 점멸한다. 정박은 금색, 엇박은 청록색이다. 현재 마디, 박자 위치와 곡 진행률을 함께 보여준다.
- 몬스터 이미지 위에는 Call 문자와 Response를 표시한다. 상세한 남은 박자와 동작 목록은 **메뉴 → 연주 정보 · 패턴**에서 확인한다. 여러 몬스터의 Call/Response가 동시에 진행될 수 있다.
- 전투 장면의 실제 몬스터 이미지가 Call에 맞춰 움직이고 공격 박자에 효과를 보낸다. 웨폰 마스터는 판정에 따라 베기/방어/회피 등의 모션을 재생한다. 여러 입력 결과의 효과를 동시에 표시한다. 이미지와 컷아웃 모션의 구성은 [BattlePresentation.md](BattlePresentation.md)에 있다.
- 메뉴의 패턴 도형에서 흰 선이 정지한 현재 위치다. 누름을 유지하는 입력은 금색, 끝난 입력은 PERFECT 청록/반미스 금색/MISS 붉은색으로 바뀐다. 동일 몬스터의 다음 묶음에서는 해당 묶음의 결과를 표시한다.
- 마우스 왼쪽 버튼 또는 한 손가락으로 조작한다. 메뉴 버튼을 제외한 연주 화면은 하나의 입력 영역이다. 두 번째 포인터의 입력/떼기는 이미 잡은 포인터를 대체하지 않는다.
- 주 화면은 현재 판정, 메뉴의 연주 정보는 몬스터별 최근 결과와 누적 판정 횟수를 표시한다. 연주 종료 집계는 정확 100%, 반미스 50%, 미스 0%의 평균이다. 이 50%는 샘플 판정 효율이며 확정된 무기 밸런스가 아니다.
- Shake 진행 중과 결과에는 구간 전체에 대해 인정된 흔들기 시간의 백분율을 표시한다. 준비 카드와 조작 안내에서도 50%/75% 기준을 확인할 수 있다.

## 손동작 판정

| 종류 | 시작 | 완료 |
|---|---|---|
| Tap | 목표 시점에 누르기 | 누르는 순간 판정 |
| Hold | 목표 시점에 누르기 | 끝까지 유지하면 자동 완료. 끝에 반드시 뗄 필요는 없음 |
| Dive | 목표 시점에 누르기 | 정해진 끝 시점에 떼기. 시작과 끝 중 낮은 판정을 적용 |
| Flick | 미리 누를 수 있음 | 목표 시점에 빠르게 움직이면서 떼기 |
| Shake | 구간 안에서 누른 채 흔들기. 늦게 시작하거나 중간에 쉴 수 있음 | 실제 흔든 시간 50% 이상 반미스, 75% 이상 성공. 구간 끝에 확정 |

공유 입력은 모든 해당 노트에 전달한다. 같은 Press의 Tap/Hold/Dive, Hold 안의 Shake, Dive의 끝과 Flick 등을 하나의 포인터로 수행한다. 움직임 조건이 실패해도 같은 입력의 다른 조건은 독립적으로 판정한다. 예를 들어 떼는 시간만 맞으면 Dive는 성공하고 Flick만 실패할 수 있다.

`RhythmRules`의 초기 수치:

| 항목 | 초기 값 |
|---|---|
| 정확 범위 | 목표 시점 ±70 ms와 ±0.16박 중 좁은 쪽 |
| 반미스 포함 전체 허용 범위 | ±140 ms와 ±0.24박 중 좁은 쪽 |
| Shake 바깥 이동 | 화면 짧은 변의 8% 이상 |
| Shake 복귀 | 시작점에서 짧은 변의 3.5% 이내 |
| Shake 시간 기준 | 구간 전체의 50% 이상 반미스, 75% 이상 성공 |
| Shake 이동 시간으로 인정하는 최소 속도 | 짧은 변의 8%/초 |
| Shake 최대 샘플 간격 | 100 ms. 이보다 긴 관측 공백의 이동 시간은 추정하지 않음 |
| Flick 이동 | 떼기 전 최대 120 ms 동안 짧은 변의 6% 이상 |
| Flick 속도 | 같은 구간 평균으로 짧은 변의 50%/초 이상 |

빠른 곡에서는 반 박자 간격의 허용 범위가 겹치지 않게 시간 폭을 줄인다. Hold를 끝보다 조금 일찍 떼었더라도 끝의 판정 범위 안이면 시작과 끝 중 낮은 판정을 적용한다. Hold/Dive를 유지해야 하는 중간에 떼면 해당 입력은 미스다. 손동작의 방향은 제한하지 않는다.

Shake는 시작/끝의 타이밍 등급으로 낮추지 않고 지정된 구간의 시간 비율로 판정한다. 한 접촉에서 기준점 밖으로 움직였다 돌아오는 동작을 확인한 뒤, 그 접촉에서 실제로 이동한 시간을 누적한다. 왕복을 확인하기 전의 이동 시간도 이때 합산하지만 가만히 누르는 시간, 느린 드리프트, 구간 밖의 움직임은 제외한다. 왕복 없는 한 방향 드래그만으로는 성공할 수 없다. 복귀 경로가 프레임 사이에서 기준점을 가로지르는 경우도 인식한다.

예를 들어 1초 Shake에서 0.50초 움직였으면 반미스, 0.75초 움직였으면 성공이다. 기준을 채운 뒤 멈추거나 떼어도 인정된 시간은 사라지지 않는다. 다시 누르면 새로운 기준점에서 왕복을 확인하고 추가 시간을 합산한다. 같은 입력의 Hold/Dive는 자신의 조건을 계속 요구하므로 Shake 성공과 별개로 일찍 떼면 실패할 수 있다. 판정은 원래 Shake 끝 시점에 확정하며, 그 이후에 흔들어도 재판정하지 않는다.

목표의 반 박자 전이 빈 위치일 때 그 위치부터 이른 반미스 범위 전까지 잘못 누르면, 그 목표의 Press 입력(Tap/Hold/Dive)을 미스로 확정한다. 정상 시점에 다시 눌러도 복구하지 않는다. 실제 앞선 입력이나 유지가 점유한 위치는 비어 있다고 취급하지 않는다. Flick/Shake의 사전 접촉은 새 Press 자체가 요구 조건이 아니므로 이 규칙으로 벌점을 주지 않는다.

## 시간과 수명

- `RhythmRound`는 Unity에 의존하지 않는다. `Advance`, `Press`, `Move`, `Release`에 단조 증가하는 곡 시간을 초 단위로 전달한다. 좌표는 화면의 짧은 변으로 정규화한다.
- `RhythmPlayback`은 `AudioSettings.dspTime`에서 곡 시작 시점을 뺀 시간을 사용한다. 프레임 deltaTime을 누적하지 않는다. 입력 이벤트와 화면이 같은 시간을 참조한다.
- `BeatMetronome`은 첫 박/정박/엇박의 짧은 합성음을 `AudioSource.PlayScheduled`로 예약한다. 현재 샘플에는 실제 음악 파일과 몬스터 음성이 없다. 프레임이 늦어 지난 클릭을 한꺼번에 재생하지 않는다.
- `RhythmInputSurface`는 드래그 임계값을 끄고 한 포인터를 캡처한다. 드래그 이벤트는 최신 위치를 저장하고 `RhythmPlayback.LateUpdate`에서 프레임당 한 번 샘플링한다. UI 이벤트 전에 이전 위치를 집계하여 흔드는 시간이 정지 시간으로 잘못 기록되는 것을 피한다. 누르기/떼기는 이벤트 시점에 반영하며, 정지해 누르는 프레임에도 위치를 샘플링하여 오래 유지한 뒤 마지막에 튕기는 Flick을 판정한다.
- 한 노트는 결과를 한 번만 만든다. 입력하지 않은 노트는 허용 시간이 지나면 미스가 된다. Shake는 끝 시점까지 관측한 움직임을 먼저 반영하고 비율을 판정한다. 곡 끝에 걸친 Dive/Flick 등의 마지막 허용 범위까지 처리한 뒤 회차를 종료한다.
- 메뉴 버튼/Esc와 앱 포커스 상실은 시계·박자음·입력 진행을 함께 멈춘다. 접촉 중이었다면 이어하기 후 새 위치를 누를 때까지 기다린다. 재접촉은 새로운 Press 판정이 아니며 유지/Shake 기준 위치를 옮겨 이어간다. 이 대기 상태에서도 메뉴를 다시 열 수 있고, 메뉴 탐색 중에는 재접촉 입력을 받지 않는다.
- 준비로 돌아가기, 외부 승패 제출, 화면 해제 시 예약된 소리와 포인터 캡처를 정리한다. 생성한 AudioClip도 화면이 파괴될 때 해제한다. 이전 회차의 콜백은 스테이지 ticket과 회차 참조로 걸러진다.

재생 API 참고: [Unity DSP time](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioSettings-dspTime.html), [PlayScheduled](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioSource.PlayScheduled.html), [Input System UI](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.17/manual/UISupport.html).

## 검증과 다음 연결점

Core 테스트 63개 중 리듬 테스트 24개가 5종 판정, 입력 공유, 복합 동작의 독립 결과, 조기 미스, 고속 BPM, 종료 직전 떼기, 무입력 종료, 일시정지/재접촉, 기존 전투 계획 유지 등을 검증한다. Shake에는 50%/75% 직전 및 정확한 경계, 후반 휴식, 늦은 시작, 놓았다 재입력, 구간 경계, 정지 시간 제외, 관측 공백, 30/60/120 Hz 샘플링과 Hold/Dive의 독립 실패 검증이 포함된다.

Unity PlayMode 테스트에는 연주 시작/독립 박자 신호/패턴 도형/곡 종료/다시 준비, 두 번째 포인터 무시, 유지 중 일시정지/재개, 외부 전투 종료를 추가했다. Unity Editor가 없는 환경에서 작성했으므로 이 테스트와 실제 화면·음향·모바일 입력 검증은 아직 실행하지 못했다. 오디오 출력 지연과 입력 지연의 보정 값은 실제 장치에서 확인한 뒤 추가해야 한다.

다음 전투 계층은 `RhythmResult`의 노트·판정·효율을 읽어 기본 상쇄와 무기 효과를 적용하면 된다. 개별 몬스터 HP, 타깃 선택, 곡 종료만으로 승리하는 규칙은 추가하지 않았다.
