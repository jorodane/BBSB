# 전투 화면과 모션

`RunMap` → 탐험 시작 → 전투 노드 → 준비하기 → **연주 시작**으로 진입한다. 기존 씬을 그대로 사용하며 Inspector에서 이미지를 연결할 필요가 없다.

## 화면

16:9·16:10 가로 화면 전체가 전투 장면이다. 왼쪽 앞쪽에 크게 배치한 웨폰 마스터와 다섯 무기, 오른쪽에 깊이를 달리한 몬스터들이 마주본다. 정박/엇박 신호와 판정은 무대 위에 겹쳐 표시되고, 작은 원형 메뉴 버튼이 우측 상단에 독립적으로 놓인다. 일반·엘리트·보스 모두 1필드 최대 1종, 2필드 최대 2종, 이후 최대 3종의 실제 `BattlePlan.Monsters`만 배치한다. 같은 종류가 둘이면 서로 다른 인스턴스로 표시한다. 상세 패턴과 누적 통계는 **메뉴 → 연주 정보 · 패턴**으로 확인한다. 준비 화면도 같은 전체 무대 위에 시작/패턴 버튼을 놓는다. 자세한 구성은 [ScreenLayout.md](ScreenLayout.md)에 있다.

몬스터의 이미지와 이름은 같은 인스턴스에 묶인다. Call 신호에는 금빛 파동과 `CALL · 의성어`가 나타나고, 몬스터가 고유한 예고 동작을 한다. 통통 슬라임은 찌그러졌다 튀고, 박쥐는 떠오르며 기울고, 거북은 낮게 눌리고, 가오리와 정령은 떠오르며 흔들리고, 도깨비는 옆으로 몸을 기울인다. 기존 계획의 **각 ScheduledCall**을 표현하므로 반복되는 공격 묶음에도 전조가 나온다.

Response의 각 시작 박자에 몬스터가 주인공 쪽으로 돌진하며 색이 다른 공격 궤적이 도착한다. 유지 입력에는 끝 박자의 마무리 효과도 있다. 같은 몬스터의 같은 박자에 여러 동작의 경계가 겹치면 공격 궤적은 하나로 합친다. 서로 다른 몬스터의 동시 공격은 모두 표시한다.

## 주인공의 대응

| 입력 | 진행 중 모션 | 결과 모션 |
|---|---|---|
| Tap | 누르는 순간 판정 | 앞으로 치고 나가며 받아 베기 |
| Hold | 유효하게 누른 상태에서 몸을 낮추고 방어막 유지 | 방어막 파동과 받아내기 |
| Dive | 유효하게 누른 상태에서 몸을 낮추고 옆으로 이동 | 끝에 떼면 옆으로 회피하며 반격 |
| Flick | 사전 접촉만으로 반격하지 않음 | 빠르게 떼는 판정에 맞춰 올려 베기 |
| Shake | 왕복 동작의 실제 이동 거리가 늘 때 무기 궤도와 몸이 흔들림 | 구간 끝의 판정에 맞춰 무기 난무 |

Perfect는 큰 청록 효과, 반미스는 약한 금빛 효과다. Miss는 붉은 흔들림과 대응 실패 표시를 사용한다. 너무 일찍 눌러 확정된 Miss는 `너무 이른 동작`으로 표시한다. 주인공 주변의 다섯 무기는 별도 도형으로 떠 있으며 대응에 함께 반응한다. 현재는 전투 연출용 검·방패·창·해머·단검 모티프이며 실제 보유 무기의 외형/편성/효과를 반영하는 장비 UI는 아니다.

한 번의 입력이 여러 몬스터/노트에 결과를 만들면 **모든 결과의 효과를 동시에** 재생한다. 몸의 이동량만 합산 후 제한한다. 한 모션의 완료를 기다리며 다음 결과를 순서대로 지연시키지 않는다. Hold-Dive-Shake와 Dive 끝/Flick 등의 공유 입력 판정은 기존 `RhythmRound`가 그대로 담당한다. Shake는 한 번 왕복하면 성공하고 바깥 이동만 충족하면 반미스이며 자동으로 구간이 시작되었다는 이유만으로 주인공이 흔들지 않는다.

## 시간과 구현

- `BattleArenaView`는 판정 회차를 읽는 표시 계층이다. Call/공격은 계획의 절대 tick, 반격은 `RhythmResult.JudgedAtSeconds`에서 경과 시간을 계산한다. HP나 무기 효과를 적용하지 않는다.
- `RhythmPlaybackView.Refresh`에서 현재 회차로 무대를 갱신한다. 모션과 무기 궤도는 `RhythmRound.ElapsedSeconds`를 사용하며 Animator, 코루틴, 별도의 deltaTime 시계가 없다.
- 일시정지 직전의 입력과 화면을 갱신한 뒤 포즈를 동결한다. 유지 입력의 재접촉을 기다릴 때도 동결하며 다시 눌러야 진행한다. Pause 때문에 포인터가 해제되어도 유지 포즈가 사라지지 않는다.
- 프레임이 크게 건너뛰면 현재 시간에 살아 있는 효과만 그린다. 지나간 Call/반격을 몰아서 재생하지 않는다. 재연주에서는 새 무대와 회차를 만들며 기존 계획을 재사용한다.
- `BattleArenaGraphic`은 배경 바닥, 룬, 다섯 무기와 파동/궤적/베기/방어막을 uGUI 메시로 그린다. `CanvasRenderer`를 명시적으로 요구한다. 캐릭터와 효과는 `raycastTarget = false`이며 무대의 RectMask2D가 화면 밖 효과를 자른다. 메뉴 버튼 외의 전체 화면 입력을 유지한다.
- 한 장의 투명 이미지에 이동·회전·스케일 변화를 주는 **2D 컷아웃 모션**이다. 관절 리깅이나 프레임별 애니메이션 클립은 아직 사용하지 않는다.

## 아트

`Assets/BBSB/Resources/BBSB/BattleArt/`의 PNG 7개를 `Resources.Load<Sprite>`로 불러온다. 원본은 1254×1254 RGBA이고, Unity에서는 Sprite/Single, Full Rect, 알파 투명, mipmap 없음, 최대 512로 가져온다. 생성 원본의 픽셀은 수정하지 않았다. 투명 여백까지 정사각형으로 사용하여 흔들릴 때 가장자리가 잘리지 않게 했다.

행진 슬라임·춤추는 박쥐·뒷박 도깨비는 `ArtId`로 기존 슬라임·박쥐·도깨비 Sprite와 기본 모션을 공유하고 다른 색을 적용한다. 각 몬스터의 이름·인스턴스·패턴은 별도다. Call 합성음도 같은 계획 시점에 예약하며 일시정지와 재개에 함께 대응한다.

내장 이미지 생성 도구로 만든 샘플 아트다. 정확한 프롬프트와 파일 대응은 [BattleArtPrompts.md](BattleArtPrompts.md)에 기록했다. 프로젝트에 원본 PNG와 `.meta`를 포함하므로 별도 다운로드가 필요 없다.

## 확인

`BBSB.UI.Tests`의 `BattleArenaTests`는 7종 Sprite 가져오기, 3개 몬스터의 Call/공격/공유 반격, 실제 접촉에 따른 유지 포즈, 복합 입력 4종의 종료, Perfect/반미스/Miss 모션 차이, 일시정지 포즈, 지난 효과 건너뛰기, 렌더 메시와 입력 비차단을 확인한다. `RhythmUiTests`에도 실제 연주 화면의 무대 연결과 최소 높이 확인을 추가했다.

작업 환경에는 Unity Editor가 없어 이 PlayMode 테스트와 실제 화면은 아직 실행하지 못했다. Unity에서 Test Runner의 `BBSB.UI.Tests`를 실행하고 `RunMap`에서 다음을 확인한다.

1. 16:9와 16:10에서 무대가 화면 전체를 채우고 주인공은 왼쪽, 몬스터는 오른쪽에 보이는지, 원형 메뉴로 상세 패턴을 열고 닫을 수 있는지 확인한다.
2. 매 Call의 몸동작과 신호를 보고 입력한다. PERFECT, 반미스, MISS의 동작 차이와 여러 몬스터의 동시 반격을 확인한다.
3. Hold/Dive 유지와 Flick을 수행한다. Shake는 짧게 한 번 왕복한 뒤 멈추거나 떼어도 성공하는지, 나가기만 하면 반미스인지 확인한다.
4. 유지 중 일시정지 → 이어하기 → 재접촉, 준비로 돌아가기, 곡 종료 → 다시 준비를 확인한다.

플레이어 피격은 별도의 세션 처리에서 연결했다. 판정마다 미스 100%·반미스 75%·퍼펙트 50%의 피해를 받고, 체력 HUD와 최근 피해를 표시한다. HP 0에서 연주와 런이 종료된다. `BattleArenaView` 자체는 표시만 담당한다. 몬스터에게 주는 피해는 무기 배치 이후에 연결하며 공용 적 HP, 자동 승리, Overkill/콘페티도 후속 작업이다. 상세 피격 규칙은 [RhythmPlayback.md](RhythmPlayback.md)에 있다.
