# 전투 화면과 모션

`RunMap` → 탐험 시작 → 전투 노드 → 준비하기 → **연주 시작**으로 진입한다. 기존 씬을 그대로 사용하며 Inspector에서 이미지를 연결할 필요가 없다.

## 화면

16:9·16:10 가로 화면 전체가 전투 장면이다. 왼쪽 앞쪽에 크게 배치한 웨폰 마스터와 다섯 무기, 오른쪽에 깊이를 달리한 몬스터들이 마주본다. 정박/엇박 신호와 판정은 무대 위에 겹쳐 표시되고, 작은 원형 메뉴 버튼이 우측 상단에 독립적으로 놓인다. 일반·엘리트·보스 모두 1필드 최대 1종, 2필드 최대 2종, 이후 최대 3종의 실제 `BattlePlan.Monsters`만 배치한다. 같은 종류가 둘이면 서로 다른 인스턴스로 표시한다. 상세 패턴과 누적 통계는 **메뉴 → 연주 정보 · 패턴**으로 확인한다. 준비 화면도 같은 전체 무대 위에 시작/패턴 버튼을 놓는다. 자세한 구성은 [ScreenLayout.md](ScreenLayout.md)에 있다.

몬스터의 이미지와 이름은 같은 인스턴스에 묶인다. 각 `ScheduledCall.Motion`이 예고 동작과 효과를 고른다. 제자리걸음은 옆 이동과 발자국, 점프는 위로 튀기, 발 구르기는 낮게 누르기와 지면 충격파, 꼬리는 큰 몸 비틀기와 옆으로 휘는 궤적이다. 솟구치기/몸 낮추기는 반대 방향 이동과 화살표, 좌우 비틀기는 회전 파동, 섬광은 몸 확대와 빛을 사용한다. 신호 글자와 패턴 도형도 동작 색을 공유한다. 색이나 문구 없이도 포즈와 효과의 형태가 다르도록 한다.

거북의 두 패턴은 첫 쿵에서 같은 포즈를 취한다. 한 박 뒤 꼬리 궤적이 붙는지를 확인하고 두 박 뒤부터 Hold한다. 꼬리 전조가 있으면 Hold 뒤 Tap을 추가한다. 꼬리 연출은 기존 컷아웃의 회전과 uGUI 궤적이며 별도 꼬리 관절 리깅은 없다. 다른 11종은 각 패턴의 첫 Call부터 다른 동작을 사용한다. 반복되는 공격 묶음의 모든 Call에도 같은 전조를 재생한다.

Response의 각 시작 박자에 몬스터가 주인공 쪽으로 돌진하며 색이 다른 공격 궤적이 도착한다. 유지 입력에는 끝 박자의 마무리 효과도 있다. 같은 몬스터의 같은 박자에 여러 동작의 경계가 겹치면 공격 궤적은 하나로 합친다. 서로 다른 몬스터의 동시 공격은 모두 표시한다.

졸음 슬라임과 시계 정령은 첫 Call 이후 각각 4박·7박을 기억해 Tap한다. Call 모션이 끝나면 평소의 대기 포즈로 돌아가고 한 박 뒤부터 `쉼 · 박자 기억하기`를 고정 표시한다. 중간 Call, 남은 박자 카운트다운이나 대응 직전의 준비 동작·다가오는 공격 궤적은 없다. 대응 박자부터 공격 포즈와 효과를 표시한다. 배경의 정박·엇박 안내는 계속된다.

시소 도깨비는 정박→엇박→정박 연결을 따라 움직인다. 기본 Call은 나무 소리와 제자리걸음, 전환 Call은 올라가는 울림과 몸 비틀기다. 앞 패턴의 마지막 Tap과 다음 Call이 겹칠 때 Call 모션과 공격 모션을 함께 적용하며, 신호에는 `CALL · 또각! · TAP` 또는 `CALL · 당겨! · TAP`으로 둘 다 표시한다.

## 주인공의 대응

모션 시트 8장이 모두 설치되면 주인공은 제공된 분홍 단발·기계 수신부 헤드셋 캐릭터를 사용한다. 이번 업로드에서는 이미지를 제외했으므로 기존 캐릭터 초상화를 사용한다. 8개 시트의 40개 키포즈를 실제 입력 종류와 최종 판정에 맞춰 교체한다. Tap은 왼손·오른손·어퍼를 연속 중복 없이 고르고, Hold는 낮은 크로스가드, Dive는 덕킹, Flick은 점프, Shake는 양손 밀쳐내기다. 각 동작에 성공·반미스·미스 포즈가 따로 있다. 자세한 프레임 대응과 재생 규칙은 [PlayerAnimation.md](PlayerAnimation.md)에 있다.

Dive/Flick 미스 뒤에는 틈이 있으면 앉아서 정비하고 일어난다. 다음 입력이 빠르면 앉기 단계를 생략하며 새로운 입력과 판정이 이전 복귀 모션을 즉시 끊을 수 있다. 공유 입력은 신체 포즈를 한 번 선택하면서 각 몬스터를 향한 효과를 모두 유지한다. 실제 Shake 이동이 없으면 밀기 포즈가 나오지 않는다.

그림과 함께 작은 판정 글자·색상 효과를 표시한다. 동작 선택과 이동·회전은 모두 라운드의 시계를 사용하고 일시정지와 함께 멈춘다. 주인공 주변 다섯 무기는 기존 도형 연출을 유지하며 실제 무기 편성은 후속 작업이다.

## 아트

`Assets/BBSB/Resources/BBSB/BattleArt/`의 기존 몬스터 PNG를 `Resources.Load<Sprite>`로 불러온다. 주인공은 하위 `PlayerMotion/`의 새 시트 8장이 모두 있으면 이를 사용하고, 없으면 기존 `weapon-master` 초상화를 사용한다. 기존 몬스터 원본은 1254×1254 RGBA이고, Unity에서는 Sprite/Single, Full Rect, 알파 투명, mipmap 없음, 최대 512로 가져온다. 몬스터 생성 원본은 그대로 사용한다. 플레이어의 녹색 원본은 전용 임포터에서 투명 처리하고 포즈별 여백과 발 위치를 정렬한다.

행진 슬라임·춤추는 박쥐·뒷박 도깨비는 `ArtId`로 기존 슬라임·박쥐·도깨비 Sprite와 대기 모션을 공유하고 다른 색을 적용한다. 졸음 슬라임은 슬라임 Sprite에 연보라색, 시계 정령은 방울 정령 Sprite에 금색을 적용한다. 시소 도깨비는 도깨비 Sprite를 분홍색으로 구분한다. 각 몬스터의 이름·인스턴스·패턴은 별도다. 패턴의 신호마다 정한 Call 합성음도 같은 계획 시점에 예약하며 일시정지와 재개에 함께 대응한다.

내장 이미지 생성 도구로 만든 샘플 아트다. 기존 몬스터 프롬프트는 [BattleArtPrompts.md](BattleArtPrompts.md), 새 플레이어 프롬프트는 [PlayerMotionPrompts.md](PlayerMotionPrompts.md)에 기록했다. 기존 몬스터와 캐릭터 초상화는 프로젝트에 포함되어 있다. 새 플레이어 모션 PNG와 레퍼런스, 이미지의 `.meta`는 이번 업로드에서 제외했다.

## 확인

`BBSB.UI.Tests`의 `BattleArenaTests`는 7종 Sprite 가져오기, 3개 몬스터의 Call/공격/공유 반격, 실제 접촉에 따른 유지 포즈, 복합 입력 4종의 종료, Perfect/반미스/Miss 모션 차이, 일시정지 포즈, 지난 효과 건너뛰기, 렌더 메시와 입력 비차단을 확인한다. `RhythmUiTests`에도 실제 연주 화면의 무대 연결과 최소 높이 확인을 추가했다.

합성 Call 9종의 초반 파형 차이·재현성·반 박 전 종료와 거북의 같은 쿵/다른 꼬리 포즈를 확인하는 테스트도 추가했다.

긴 쉼에서는 처음 Call이 보이고, 대응 직전에는 고정 쉼 안내와 대기 포즈를 유지하다가 정확한 박자에 공격하는지 검사하는 테스트도 추가했다.

정박·엇박 전환 시 다음 Call과 현재 Tap이 함께 보이는지 확인하는 PlayMode 테스트도 작성했다.

작업 환경에는 Unity Editor가 없어 이 PlayMode 테스트와 실제 화면은 아직 실행하지 못했다. Unity에서 Test Runner의 `BBSB.UI.Tests`를 실행하고 `RunMap`에서 다음을 확인한다.

1. 16:9와 16:10에서 무대가 화면 전체를 채우고 주인공은 왼쪽, 몬스터는 오른쪽에 보이는지, 원형 메뉴로 상세 패턴을 열고 닫을 수 있는지 확인한다.
2. 글자를 읽지 않고도 각 몬스터의 두 패턴을 소리·몸동작으로 구분하는지 확인한다. 거북은 쿵 뒤 꼬리를 확인하기 전에 Hold를 요구하지 않는지, 꼬리가 있으면 Hold 후 한 박 쉬고 Tap하는지 확인한다. PERFECT, 반미스, MISS의 동작 차이와 여러 몬스터의 동시 반격을 확인한다.
3. Hold/Dive 유지와 Flick을 수행한다. Shake는 짧게 한 번 왕복한 뒤 멈추거나 떼어도 성공하는지, 나가기만 하면 반미스인지 확인한다.
4. 유지 중 일시정지 → 이어하기 → 재접촉, 준비로 돌아가기, 곡 종료 → 다시 준비를 확인한다.

플레이어 피격은 별도의 세션 처리에서 연결했다. 판정마다 미스 100%·반미스 50%·퍼펙트 0%의 피해를 받고, 체력 HUD와 최근 피해를 표시한다. HP 0에서 연주와 런이 종료된다. `BattleArenaView` 자체는 표시만 담당한다. 몬스터에게 주는 피해는 무기 배치 이후에 연결하며 공용 적 HP, 자동 승리, Overkill/콘페티도 후속 작업이다. 상세 피격 규칙은 [RhythmPlayback.md](RhythmPlayback.md)에 있다.
