# 무기 속성과 시작 박자

무기 종류(`DefinitionId`)와 속성(`WeaponAttribute`)은 별도 데이터다. 빛 단검·어둠 단검·이면 단검·혼돈 단검은 같은 종류의 서로 다른 속성 무기다. 속성 이미지 팩을 설치하면 그림에도 속성을 반영한다. 등급은 기존 이름·테두리·소켓 수로 구분한다. [이미지 설치](WeaponArt.md#속성-이미지와-13종-무기-확장-팩)를 참고한다.

| 속성 | 새 패턴의 시작점 | 효과 선택 |
|---|---|---|
| 빛 / Light | 가장 가까운 정수 박자 | 빛 정의·정박 중심 |
| 어둠 / Dark | 가장 가까운 `n + 0.5` 박자 | 어둠 정의·엇박 중심 |
| 이면 / Dual | 가장 가까운 정박 또는 엇박 | 시작점이 정박이면 빛, 엇박이면 어둠 |
| 혼돈 / Chaos | 기존 반복형은 가까운 반박, 새 두 구간형은 추첨한 쪽 박자 | 무한 반복·전환 또는 독립 추첨한 두 구간 |

표의 가까운 박자는 **호출 시 위상을 선택하는 기준**이다. 정확히 중간이면 미래 쪽 박자를 선택한다. 1.42박 호출은 빛에서 정박, 어둠·이면·반복형 혼돈에서는 엇박 위상을 고른다. 두 구간형 혼돈은 먼저 빛/어둠을 추첨한다. 일반 무기는 호출 자체를 성공 판정하지 않고, 최소 1박 대기 뒤 선택된 위상의 박자부터 첫 노트를 판정한다. 0박에 부른 빛 무기는 1박, 어둠 무기는 1.5박에 첫 노트가 온다. 호출 대기는 무기 에셋에서 바꿀 수 있으며 반복 중에는 추가하지 않는다. 방패는 기본 0박 대기로 즉시 패링·Hold를 시작한다. [호출과 리스폰스 설정](FiveLaneCombat.md#시계와-판정)을 참고한다.

`StartGridBeats` / `startGridBeats`는 제거했다. 시작점은 무기의 속성이 결정하므로 과거 에셋의 자유 시작 격자는 적용되지 않는다. 패턴 내부에는 기존처럼 반박 등 다른 박자의 노트를 작성할 수 있다. 공격·지원 기본 패턴은 누르기와 홀드 해제의 2/3 이상을 선택한 속성의 박자에 둔다. 방패와 사용자 정의 에셋은 기존 입력을 유지한다.

## 장착·소유·저장

- 같은 `DefinitionId + Attribute`는 동시에 장착할 수 없다. 등급·강화·시작 Offset·점유 폭 차이는 중복 제한의 예외가 아니다.
- 서로 다른 무기는 노트 패턴이 같아도 함께 장착할 수 있다. 같은 무기라도 속성이 다르면 함께 장착할 수 있다. 장착 한도와 물리 라인 규칙은 그대로 적용한다.
- 동일 속성의 새 무기를 기존 무기 위에 놓아 교체하는 것은 허용한다. 최종 배치에서 중복이 남는 경우만 거부한다. 실패한 배치·교환은 이전 편성을 유지한다.
- 소유 목록에는 동일 속성의 동일 무기를 여러 개 보관할 수 있다. 배치·이동·해제는 해당 소유 인스턴스의 바인딩만 변경한다.
- 보스의 무기 3택1은 제시 시점에 속성을 한 번 결정하고 획득 때 그대로 전달한다. 전용 속성이 없는 공격·지원 무기는 네 속성이 동일 확률로 등장한다. 방패는 빛·어둠·이면, 양면 지팡이·일식 거울은 이면만, 혼돈의 진자는 혼돈만 등장한다. 분포와 기존 반복형 구분은 `WeaponAttributes.Roll`, `SupportsChaos`, `UsesChaosTransitions`에서 정한다.
- `PlayerAuthoring.startingWeapons[].attribute`로 캐릭터별 시작 무기의 속성을 지정한다. 기본 시작 무기는 빛 단검과 빛 히터실드다.
- 시작 편성의 바인딩에는 속성을 함께 기록하고, 복원 시 현재 캐릭터의 무기 ID·속성·폭과 대조한다. 저장 정보만으로 다른 무기를 추가하지 않는다. 속성 필드가 없는 기존 v1 저장은 Light=0으로 읽는다. 캐릭터 정의의 속성이 바뀐 항목은 그 항목의 기본 배치를 적용하고 다른 유효한 저장 배치는 보존한다.

## 이면과 Offset별 효과 작성

`Resources/BBSB/WeaponPhrases`의 `WeaponPhraseAuthoring`은 아래 선택자를 갖는다.

| 필드 | 의미 |
|---|---|
| weaponId | 무기 종류 |
| anyAttribute / attribute | 모든 속성의 공통 정의인지, 특정 속성 전용인지 |
| bothSides / beatSide | 빛·어둠 공통 정의인지, 한쪽 시작 박자 전용인지 |
| startLaneOffset | 점유 범위 안에서 시작한 상대 라인 |
| chaosTransition | 혼돈의 전환용 패턴인지 |

정확한 속성의 정의가 공통 속성보다 우선하고, 같은 속성 범위에서는 해당 박자의 정의가 양쪽 공통 정의보다 우선한다. 같은 선택자 조합의 에셋이 중복되면 오류를 남기고 그 조합을 제외해 공통/기본 정의를 사용한다. 기존 에셋의 기본값은 `anyAttribute=true`, `bothSides=true`라 기존 동작을 공통 정의로 계속 사용한다.

예를 들어 이면 무기의 정박 회복·엇박 공격은 같은 무기 ID와 Offset으로 두 에셋을 만든다. 두 에셋 모두 `anyAttribute=false`, `attribute=Dual`, `bothSides=false`로 하고, 빛 에셋은 `beatSide=Light`와 `notes.effect=Heal`, 어둠 에셋은 `beatSide=Dark`와 `notes.effect=Strike`로 설정한다. `damage`는 Heal일 때 회복량으로 쓰며 최대 HP를 넘지 않는다. 회복량은 공격 피해에 합산하지 않는다. 예시 효과를 모든 이면 무기에 강제하지 않으며 별도 정의가 없으면 양쪽 모두 기존 효과를 사용한다.

복수 라인 무기는 이 선택을 Offset마다 따로 작성할 수 있다. 활성화 도중 다른 라인을 입력한다고 선택한 효과가 바뀌지는 않는다. `WeaponPhraseSet.LightStarts / DarkStarts`와 `For(offset, side)`가 실제 판정과 UI에서 같은 정의를 제공한다.

## 혼돈의 반복과 전환

혼돈 단검·쌍검·진자는 **유지 6박, 패턴 경계당 전환 확률 25%, 효과 1.5배**로 무한 반복한다. 기본 구간은 단검 2박의 Tap 한 번, 쌍검 1박의 Tap 한 번, 진자 8박이다. 마지막 성공 노트까지 유지 시간을 세므로 첫 판정이 0박인 예에서 단검은 6박 입력 후 8박부터, 쌍검은 6박 입력 후 7박부터, 진자는 7박 마지막 입력 후 8박부터 첫 전환이 가능하다. 4.5박의 무기별 연결 패턴을 완료하면 반대 박자의 기본 반복으로 이어진다. 단검·쌍검의 빛·어둠·이면은 전환 없이 2박·1박 간격을 유지한다.

새로 혼돈을 허용한 공격·지원 21종은 전환 패턴 없이 두 구간을 연주한다. 각 구간은 빛 또는 어둠을 독립적으로 50% 확률로 고르므로 같은 쪽이 두 번 나올 수도 있다. 박자가 달라지는 경계에서는 반박 쉬고 다음 구간을 시작한다. 두 번째 구간을 마치면 쿨타임에 들어간다. 상세 수치와 무기별 리듬은 [긴 무기 패턴](LongWeaponPatterns.md)을 참고한다.

두 방식 모두 미스가 발생한 구간의 남은 확정 노트는 유지하지만 다음 구간·자동 반복은 끊는다. 반미스는 성공으로 연결한다.

- `repeat=true`, `maximumCycles=0`은 무한 전환형, `repeat=true`, `maximumCycles=2`는 무작위 두 구간형이다. 혼돈의 모든 기본 Offset·박자 정의는 이 값을 통일해야 한다. 두 구간형에는 전환 에셋을 사용하지 않는다.
- 기본 패턴은 반복 가능해야 하며, 같은 박자를 유지하도록 길이가 정수 박자여야 한다.
- `chaosTransition=true` 에셋으로 무기·시작 Offset·진입 박자별 전환 패턴을 덮어쓸 수 있다. 전환은 반복 가능하고 양쪽 박자의 노트를 포함하며, 전체 길이가 `n + 0.5`여야 한다. 성공 후 반대 박자의 기본 정의를 선택한다.
- 별도 전환 정의가 없는 단일 Tap 반복 패턴은 1.5박의 세 Tap 전환을 사용한다. 복잡한 반복 패턴에는 전환을 명시적으로 작성해야 한다. 한 Offset의 전환만 덮어써도 다른 Offset의 기본 전환은 유지한다.
- `chaosMinimumBeats`, `chaosTransitionChance`, `chaosEffectMultiplier`를 Inspector에서 조정한다. 규칙은 선택된 빛/Offset 0 기본 에셋을 기준으로 읽으며 없으면 첫 번째로 적용된 에셋을 쓴다. 최소 유지 시간은 6 이상, 확률은 0~1, 효과 배율은 1보다 커야 한다.
- 배율은 피해·피니셔 피해·회복·홀드 피해 감소에 적용한다. 피해 감소율은 100%를 넘지 않는다. 패턴의 타이밍·쿨타임·입력 성공 여부를 배율로 바꾸지 않는다.
- 전투 시드·장착 항목·활성화 순서·반복 번호로 결정되는 `WeaponRhythmCycle`을 판정과 예고가 공유한다. 화면을 다시 그리거나 일시정지·프레임 수를 바꾸어도 이미 예고한 전환을 다시 추첨하지 않는다. 예고는 기존처럼 최대 3박이며 성공을 가정한 흐린 노트다.

신령 방울은 기존의 +1박 시각을 대상 무기 속성의 가까운 시작 박자로 보정해 예약한다. 예를 들어 0박 빛 방울이 어둠 단검을 깨우면 1.5박에 시작한다. 실행 시 이미 연주 중인 대상은 건너뛰며 실제 입력·패링 성공을 대신하지 않는다.

## 검증

독립 검사는 네 속성의 첫 입력·후속 박자, 이면의 Offset별 회복/공격, 회복 상한, 혼돈 6박 조건·양방향 전환·실패·고정 시드·예고·일시정지, 같은 무기+속성 장착 제한과 교체, 저장·상점 획득의 속성 보존, 방울의 대상 박자 예약을 확인한다. Unity PlayMode에는 에셋 선택자와 PlayerPrefs/JsonUtility 저장 복원 검사를 추가했다. 독립 검사는 Unity API 컴파일이나 실제 화면 재생을 대신하지 않는다.
