# 몬스터 패턴 확장과 지속 방어

기본 12종은 각각 **짧은 기본 패턴 3개 + 긴 후크 패턴 2개**, 총 60개 패턴을 가진다. 기존 24개 패턴의 ID와 Unity 편집 설정은 보존했고, 탭과 홀드를 섞은 36개를 추가했다. 새 기본 패턴은 3~4박, 후크의 Response는 8박이다. 후크 구간에 해당 패턴을 배치할 수 있으면 우선 예약하며, 곡의 슬롯이나 구간 길이가 맞지 않으면 기존 짧은 패턴으로 채운다.

| 몬스터 | 추가 기본 | 후크 1 | 후크 2 |
|---|---|---|---|
| 젤리 슬라임 소녀 | 끈적한 되튐 | 출렁이는 파도 | 부풀어 팡팡 |
| 도자기 골렘 소녀 | 버티는 한 걸음 | 장갑 행진곡 | 두 번의 관절 잠금 |
| 깃춤 하피 | 깃과 바람 | 세 갈래 폭풍 | 날갯짓 후렴 |

| 꿈먹는 맥 소녀 | 하품 끝의 방울 | 긴 꿈의 숨결 | 깜짝 자장가 |
| 태엽 인형 소녀 | 째깍 태엽 감기 | 인형 행진 후렴 | 두 번 감는 태엽 |

## 5라인 전투의 홀드 피해

- 몬스터의 `GestureKind.Hold`는 시작과 종료 시각을 모두 유지한다. 첫 피해는 시작 **0.5박 후**, 이후 0.5박마다 발생한다. 마지막에 반 박보다 짧은 구간이 남으면 종료 시점에 비례한 잔여 피해를 준다.
- 기존 계산된 **홀드 한 노트의 총 피해**를 이 구간에 분배한다. 예: 총 피해 16, 길이 4박이면 반 박마다 피해 2를 8회 적용한다.
- 진입 패리는 처음 누른 시점의 실제 공격 판정을 저장한다. Perfect는 그 공격의 지속 피해를 100% 막고, Half는 50% 막는다. 새 무기 패턴 시작의 입력 허용 보정으로 적 공격 판정을 Perfect로 올리지 않는다.
- 일반 가드는 해당 방패의 피해 감소율과 진입 판정을 저장한다. Heater Shield의 Perfect 일반 가드는 50%, Half 일반 가드는 25% 감소한다. 매 틱마다 새 판정을 요구하지 않는다.
- 중간 진입도 가능하다. 남아 있는 가장 가까운 반 박 판정에 패리하거나 일반 가드를 시작해 그 뒤 남은 구간을 방어한다. 이미 확정된 피해는 되돌리지 않는다.
- 타격 시점에 방어를 기록하고 기존 늦은 패리 허용 구간이 끝나면 피해를 확정한다. 큰 프레임 지연에도 모든 틱을 시간순으로 처리한다.

## 방어 유지와 반격

- 방패의 방어 노트를 성공시키고 같은 입력을 계속 누르면, 해당 홀드 공격 끝까지 방어를 유지한다. 방패의 원래 유지 시간보다 공격이 길어도 연장된다. 버클러 같은 Tap 패리도 길게 누르면 해당 공격을 계속 막는다.
- 대형 방패가 긴 공격을 붙잡은 경우, 연장된 끝까지 누르면 자동 완주한다. 일반 단발 공격에 대한 기존 시작·떼기 패리는 유지한다.
- 방어 연장 시간만큼 뒤따르는 반격 노트와 완료 쿨타임 기준을 늦춘다. 화면의 유지 막대와 반격 예고도 같은 시각을 사용한다.
- 입력을 떼면 이후 틱의 방어가 끝난다. 이미 타격 시점에 막은 틱은 그대로 인정한다. 기본 방어 시간을 채운 뒤 연장 구간에서 자발적으로 뗄 때는 완료한 방어를 미스로 바꾸지 않는다.
- 방어는 붙잡은 공격에만 연결된다. 다른 적의 새 공격을 자동 패리하지 않는다. 일반 방패의 지속 피해 감소는 기존 규칙을 유지한다.
- 쿨타임 중 눌러 둔 입력이 나중에 자동 발동하지 않는다. 사용 가능해진 뒤 다시 누르면 진행 중인 홀드에 진입할 수 있다.
- 일시정지는 피해·입력·유지 시간을 모두 멈춘다. 그로기는 진행 중인 홀드의 남은 피해도 중단한다.

## 화면과 리소스

기존 종족별 투사체·Animator·방어 효과를 재사용한다. 지속 공격은 목표 지점에 남아 반 박마다 맥동하고, 적 공격 모션과 방어 자세를 유지한다. 새 패턴의 Unity 에셋에는 기존 공격 이미지 경로를 연결했다. 새 PNG 설치는 필요 없다. 추가 한글을 포함하도록 UI 글꼴을 갱신했다.

핵심 구현: `MonsterPatternExpansion`, `FiveLaneBattle`, `FiveLaneHoldCombat`. Unity 비의존 회귀 검사는 `Tools/CoreChecks`로 실행한다. Unity Editor의 실제 임포트·PlayMode·화면 재생은 별도 확인이 필요하다.
