# 탐험 시작 준비와 편성 저장

기본 전투 모드에서 타이틀의 `탐험 시작` 또는 종료 화면의 `새로운 탐험`은 **캐릭터 선택 + 시작 무기 편성** 화면을 연다. 시작 화면의 맵 선택은 그대로 적용된다. 현재는 기존 WEAPON MASTER 하나가 표시되고, 시작 장비는 단검과 히터실드다.

왼쪽에서 캐릭터를 선택하고 오른쪽의 작은 무기 이미지 카드를 보드로 드래그한다. 카드 클릭 후 보드 클릭, 복수 라인 중앙 스냅, 겹침 교체, 아래로 끌어 해제도 인게임 편성과 동일하다. 적어도 한 무기가 배치되어야 `편성하고 시작`을 누를 수 있다.

`편성하고 시작`을 누르면 새 런을 만들고 선택한 캐릭터와 그 캐릭터의 시작 배치를 저장한다. 다음 런 및 앱 재실행 후에도 이 선택과 배치를 복원한다. 캐릭터마다 별도의 마지막 시작 배치를 기억한다. 준비 화면에서 캐릭터를 왕복하면 임시 편집 내용은 유지되며, 실제 시작한 캐릭터의 편성만 저장한다. `돌아가기` 또는 Esc는 편집을 취소하고 타이틀로 돌아간다.

## 저장 범위

- `PlayerPrefs`의 `BBSB.RunStart.v1`에 버전, 마지막 캐릭터 ID, 캐릭터별 시작 장비 Key와 왼쪽 배치 Offset·점유 폭·미배치 여부를 JSON으로 저장한다.
- 새 런은 캐릭터가 정의한 시작 무기 인스턴스를 새로 만든다. 시작 편집용 `StartingLoadout`은 런 진행을 만들지 않으며 `RunSession`과 별개다.
- 진행 중 바꾼 편성, 획득 장비, 강화, 보스 장착 한도, HP·골드·맵 진행은 시작 편성 저장값을 바꾸지 않는다.
- 동일 종류의 시작 무기를 두 개 주어도 각 Key로 구분한다. 에셋에서 목록 순서를 바꿔도 배치는 해당 Key에 연결된다.
- 삭제된 캐릭터는 현재 첫 캐릭터로 돌아간다. 변경되거나 잘못된 시작 장비 배치는 현재 정의로 복구하며, 유효한 저장 배치를 먼저 확보한다. 7개 라인은 항상 열려 있지만 잘못된 저장값으로 1라인 무기를 S/L에 놓거나, 겹친 장비를 밀어내거나, 런 보상을 생성하지 않는다.
- 읽을 수 없는 JSON 또는 지원하지 않는 저장 버전은 기본 선택으로 돌아간다. 정상적으로 시작을 확정할 때 다시 저장한다.

## 캐릭터 추가

1. `Assets/BBSB/Resources/BBSB/Characters` 아래에 `Create > BBSB > Player` 에셋을 추가한다. 기존 캐릭터는 `Resources/BBSB/Player.asset`을 유지한다.
2. `characterId`를 기존 캐릭터와 겹치지 않는 고정 ID로 지정한다. 이름, 설명, Portrait, Visual Prefab, Animator Controller와 표시 크기를 연결한다. 선택한 ID가 실제 전투의 외형 참조에도 사용된다.
3. `startingWeapons`에 시작 장비를 설정한다. `key`는 캐릭터 안에서 고유하고 지속적인 장비 식별자, `weaponId`는 무기 카탈로그 ID다. 무기 인스턴스 전체를 저장하는 값이 아니다.
4. `equipped`와 `defaultOffset`은 처음 선택할 때의 기본 배치다. Offset은 왼쪽 점유 라인을 기준으로 S=-1, D=0, F=1, Space=2, J=3, K=4, L=5다. 봉처럼 폭이 2인 무기는 연속 두 라인을 사용한다. 기본 장착 한도는 2개이며, S/L도 처음부터 열려 있다. S/L은 복수 라인 무기만 사용할 수 있다.
5. Player 인스펙터의 `검증 및 저장`으로 Key 중복, 잘못된 무기 ID, 기본 배치 충돌 등을 검사한다. 별도 캐릭터 추가 코드 수정은 필요 없다.

## 화면 편집과 검사

`RunScreenKind.RunSetup`을 화면 목록 끝에 추가해 기존 프리팹 enum 값을 유지한다. `PresentationPrefabBuilder`가 없던 `RunSetupScreen.prefab`과 카탈로그 연결을 Unity에서 자동 생성한다. `CanvasScreen.runSetup`의 `RunSetupBindings`에 캐릭터 목록·초상화·이름·설명·보드·무기 목록·시작/뒤로 버튼을 연결하며, 프리팹을 직접 배치해 편집할 수 있다. 에셋이 없는 환경에서는 같은 기본 구성을 런타임에 만든다.

Core 검사는 배치 복원, 인스턴스 분리, 런 초기화, 동일 종류 장비의 Key, 복수 라인, 잘못된 저장값과 장비 정의 변경을 다룬다. PlayMode 검사는 시작 확정/취소, 재시작 복원, 0개 장착 차단, 캐릭터별 JSON 저장을 다룬다. PlayMode 테스트는 실제 사용자 설정을 보존·복원한다. 기존 Call & Response 시험 모드는 원래의 즉시 시작 흐름을 유지한다.

시작 무기의 속성은 `PlayerAuthoring.startingWeapons[].attribute`로 정하며 편성 저장에도 함께 기록한다. 같은 무기 종류라도 속성이 다르면 함께 배치할 수 있다. 기존 저장은 빛 속성으로 해석한다. [무기 속성 규칙](WeaponAttributes.md)을 참고한다.
