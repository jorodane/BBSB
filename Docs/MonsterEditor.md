# 몬스터 에디터

Unity 메뉴 **BBSB → Monster Editor**에서 몬스터를 추가한다. 프로젝트 창에서는 **Create → BBSB → Monster**로도 만들 수 있다. 유효한 사용자 몬스터는 다음 Play에서 출현 목록과 도감에 함께 등록된다.

## 기존 몬스터 편집

기존 **12종 / 24개 패턴**도 `Assets/BBSB/Resources/BBSB/Monsters/<몬스터 ID>.asset`에 각각 저장되어 있다. Monster Editor의 **등록된 몬스터** 목록에서 이름으로 고르면 같은 탭에서 외형·패턴·출현 가중치·피해를 수정할 수 있다. 새로 생성하거나 데이터를 복사할 필요가 없다.

- Play와 빌드의 출현 목록은 이 폴더의 유효하고 활성화된 에셋만 사용한다. 기존 몬스터도 출현 옵션을 끄거나 에셋을 삭제하면 제외된다. 수정 후 다음 Play 또는 빌드부터 적용된다.
- 기존 종족 ID와 패턴 ID를 유지해야 이미 등록된 전용 이미지 슬롯이 계속 연결된다. 이름과 설명은 자유롭게 변경해도 된다.
- 기존 에셋은 **기존 리소스 몸체 모션 사용**이 켜져 있다. 이미 등록한 Call·Attack·Recover와 전용 공격 연출을 유지한다. 직접 만든 Controller 또는 UI 외형 Prefab을 연결하면 새 외형이 우선한다. 연결을 비우면 기존 모션으로 돌아간다.
- 네코마타(`seesaw-goblin`)는 **Beat Shift** 배치 방식과 전환 전 기본 Call 3회를 유지한다. 다른 종족은 Independent다. 해당 방식의 패턴 조건은 패턴 탭과 저장 검증에서 확인한다.
- 기본 모습 Sprite를 바꾸고 전투에서도 정지 외형으로 사용하려면 기존 리소스 몸체 모션 옵션을 끈다. 옵션이 켜져 있으면 기존 모션 Sprite가 전투 외형을 결정한다.

개발 참고: `MonsterCatalog.BuiltIn`은 Unity 없이 실행하는 시뮬레이션의 기본값과 기존 투사체 연출 키의 기준으로 남는다. Unity 런타임은 에셋 전체 목록으로 교체하며 이 기본값을 추가로 붙이지 않는다. 에셋의 편집 내용을 코드 기본값으로 덮어쓰는 자동 생성 과정은 없다. 에셋 테스트는 현재 설정의 변환과 공격 시각 유효성을 검사하며, 이전 밸런스 수치와 같을 것을 요구하지 않는다.

## 1. 기본 모습

1. **새 몬스터**를 누른다. 에셋은 `Assets/BBSB/Resources/BBSB/Monsters`에 생성된다.
2. 이름, 설명, 주요 입력, 출현 가중치와 판정 기본 피해를 설정한다. 고유 ID는 소문자·숫자·하이픈을 사용하고 다른 에셋과 겹치지 않게 한다.
3. **기본 모습 / 도감 Sprite**에 투명 PNG에서 임포트한 Sprite를 등록한다. Sprite Editor의 Pivot은 발 접지점에 맞춘다. 도감 썸네일과 애니메이션 미등록 시 외형에도 이 Sprite를 쓴다.
4. 크기와 위치 보정으로 전투 배치를 조정한다. 위치 보정은 몸 높이 기준이다.

`출현 목록에 등록`을 끄면 제작 중인 몬스터를 전투와 도감에서 제외할 수 있다. 테스트 장면에서는 이 옵션과 관계없이 선택한 에셋을 연습할 수 있다. 출현 가중치가 높으면 선택될 가능성이 높아진다. 해당 곡의 리듬 소켓에 패턴을 배치할 수 있어야 출현하므로 모든 곡에 강제로 등장하지는 않는다. 기존 스테이지 계획은 재생 중에 바뀌지 않는다.

## 2. 패턴

패턴 탭에서 패턴을 추가하고 **그라데이션 편집기 형태의 타임라인**으로 Call 신호와 Response 입력을 편집한다. 공통 박자 막대 위의 금색 마커는 Call, 아래의 청록색 마커는 Response다. C/R 문자와 위아래 위치로도 구분한다.

| 조작 | 결과 |
|---|---|
| 막대 위 빈 곳 클릭 | 그 박자에 Call 추가 |
| 막대 아래 빈 곳 클릭 | 선택한 **새 Response** 종류로 입력 추가 |
| 마커 클릭 | 아래에 해당 신호/입력의 상세 설정 표시 |
| 마커 좌우 드래그 | 0.25·0.5·1박 스냅으로 시각 이동 |
| Hold/Dive 구간 오른쪽 손잡이 드래그 | 유지 종료 시각 변경 |
| 선택 삭제 / 타임라인에 포커스한 상태에서 Delete·Backspace | 선택한 마커 삭제 |
| Ctrl/Cmd+Z / 드래그 중 Esc | 실행 취소 / 진행 중인 드래그 취소 |

기본 화면은 타임라인을 중심으로 보여 준다. Response 구간·휴식·참여 확률·패턴 상태는 **패턴 구간 · 확률 · 상태 설정**을 펼쳐 편집한다.

마커 상세 설정에서는 **첫 Call부터의 시각**을 숫자로 입력할 수도 있다. Response를 선택하면 바로 아래에 연결된 **공격 설정**이 열리므로 생성 기준 Call, 이동 방식, 이미지, 위치를 같은 화면에서 바꿀 수 있다. 전체 공격을 비교하려면 기존 공격 연출 탭을 사용한다. 확대 슬라이더와 가로 스크롤로 긴 패턴이나 가까운 박자를 편집한다.

- 첫 Call은 0박 시작점으로 고정되어 이동·삭제할 수 없다. Response는 0.25박 이후에 추가할 수 있다.
- 같은 줄의 같은 박자를 다시 클릭하면 기존 마커를 선택한다. 드래그로 같은 줄의 다른 마커와 정확히 겹치는 이동은 적용하지 않는다.
- Response를 기존 구간 시작보다 앞에 배치하면 구간 시작을 앞당기고 **다른 입력들의 실제 박자와 기존 구간 끝은 유지**한다.
- 추가·이동·유지 길이 변경으로 입력이 구간 밖으로 나가면 Response 구간을 확장한다. 이후 휴식 길이는 그대로 둔다. 줄인 경우에는 구간을 자동 축소하지 않는다.
- 이미 무음 대기를 사용하는 패턴은 타임라인 편집 후 마지막 Call과 첫 입력 사이의 실제 간격에 맞춰 대기를 갱신한다. 0으로 꺼 둔 대기는 자동 활성화하지 않는다.
- 마커를 이동해도 해당 입력의 공격·이미지 설정과 Call 연결은 함께 유지한다. Call 배열을 시간순으로 재정렬하지 않는다.
- Call 삭제로 연결 대상이 사라진 공격은 시간상 앞의 가장 가까운 Call로 연결하고 안내를 표시한다. 이후 생성·판정 시각을 검증한다.
- 새 Response는 이전 입력의 공격이나 Sprite 설정을 복사하지 않고 새 설정으로 시작한다.
- Call이 입력보다 늦거나 유지 입력끼리 충돌하는 등 패턴 규칙 위반은 **설정 검증 및 저장**에서 확인한다.

| 설정 | 의미 |
|---|---|
| Response 구간 시작 | 첫 Call부터 편집용 Response 구간까지의 박자 수. 첫 실제 입력 앞에 빈 공간을 둘 수 있음 |
| Response 구간 길이 | 모든 Response와 유지 종료를 포함하는 구간 |
| 이후 휴식 | 해당 구간 뒤의 휴식 |
| Call 시작 정렬 단위 | 1박이면 정박, 0.5박이면 반 박, 0.25박이면 4분의 1박 단위로 배치 가능 |
| 마지막 Call → 첫 입력 대기 | 보통 0. 지정할 때는 마지막 Call부터 실제 첫 입력까지의 양수 박자 수와 일치시킴. 3박 대기도 가능 |
| 패턴 참여 확률 | 배치 가능한 후보 중 이 패턴을 제출할 확률 |

타임라인과 선택 마커의 시각은 **첫 Call을 0으로 센 공통 박자**이며, 숫자 입력은 0.25박 단위로 반올림한다. 에셋 내부의 Response offset은 Response 구간 시작에 대한 상대값으로 저장되며 선택 패널에서 참고값으로 표시된다. 첫 Call의 상대 시각은 0이어야 한다. 첫 Response에는 빈 박자를 둘 수 있다. Call은 실제 첫 입력 전에 모두 끝나야 한다. 편집 구간이 먼저 시작하더라도 마지막 Call 뒤 입력이면 유효하다.

예: Response 구간 시작 2박, Call 마커 0박·1박, Response Tap 마커 2박·2.5박이면 에셋의 Response 상대값은 0박·0.5박으로 저장된다. Response 구간을 1박으로 잡으면 이후 휴식은 전체 3박부터 시작한다.

- Tap/Flick/Shake: 한 시점에 입력한다.
- Hold/Dive: 유지 길이를 지정한다. 시작과 종료를 모두 포함하도록 Response 구간을 잡는다.
- 각 Call은 기존 합성음 종류와 기본 동작을 선택할 수 있다.
- 패턴 사이의 Call 구분은 저장 가능한 경고로 표시한다. 중복 입력과 병행 불가능한 입력, 입력보다 늦은 Call은 오류로 거부한다. 긴 무음 대기 패턴은 한 몬스터당 하나만 허용한다.

## 3. Animator로 모션 등록

**Animator 모션 → Animator · Clip · UI Prefab 기본 틀 생성**을 누르면 몬스터 에셋 옆에 새 폴더가 생긴다. Controller, 9개 Clip, UI Prefab을 만들고 자동 연결한다. 재생성할 때 기존 파일을 덮어쓰지 않고 새 폴더를 만든다.

초기 Clip은 모두 기본 Sprite를 유지하는 자리 표시자다. **외형 Prefab 열기**로 Prefab Mode에 들어가 `Visual` 루트를 선택하고 Animation 창에서 각각의 Clip에 Sprite 교체·자식 위치·회전·크기를 기록한다. **Animator 열기**에서는 각 State의 Motion에 직접 만든 Clip을 등록할 수도 있다.

| 상황 | 재생 시점 |
|---|---|
| Idle | 콜이나 공격이 없는 대기 |
| Call | 각 Call 시각. 다음 Call 또는 첫 Response까지 |
| Attack | 각 Response 시작. Hold/Dive는 유지 구간까지 |
| Recover | Attack 구간 뒤 반 박 |
| Hit | 실제 무기 타격이 몬스터에 닿았을 때 |
| Perfect | 플레이어가 해당 몬스터의 Response를 퍼펙트로 처리했을 때 |
| HalfMiss | 플레이어의 반미스 확정 |
| Miss | 플레이어의 미스 확정; 몬스터의 공격 성공 반응으로 활용 |
| Defeated | 적 전체 HP가 0이 된 뒤 마지막 판정 구간을 마무리했을 때 |

상황별 모션에는 `Base Layer.Call`처럼 **레이어를 포함한 전체 상태 경로**와 재생 길이(박), 반복 여부를 지정한다. 같은 상황의 상태를 중복 등록하지 않는다. 패턴별 Attack/Recover 상태, Call별 상태는 패턴 탭에서 덮어쓸 수 있다. 이때 재생 길이와 반복 여부는 해당 상황의 공통 설정을 사용한다. 비워두면 공통 상태를 사용한다.

애니메이션은 현재 곡 시각으로 정규화 시간을 계산해 샘플링한다. 일시정지 중에는 같은 자세를 유지하고 연습 반복은 처음 상태로 돌아간다. 비반복 모션은 설정한 길이 후 마지막 프레임을 유지한다. Attack이 길게 유지돼야 하면 반복 모션을 쓸 수 있다. 새 콜과 최근 사건이 이전 반응을 교체하며 같은 시각의 실제 타격은 판정 반응보다 우선한다.

### 외형 Prefab 규칙

- 현재 전투는 Canvas 기반이므로 **UI Image**를 쓴다. SpriteRenderer나 3D 모델 프리팹을 그대로 넣는 방식은 지원하지 않는다.
- 루트는 RectTransform, 기준 높이는 512, 기준 발 위치는 아래 중앙이다. 루트에 Animator 하나를 두고 자식 `Portrait` 또는 직접 만든 자식 Image 계층을 움직인다.
- 전투 위치와 피격 흔들림은 바깥 래퍼가 맡는다. 외형 애니메이션은 그 안의 자식 계층에 작성한다.
- Controller는 Base Layer 하나와 상태별 Clip으로 구성한다. 자동 Transition은 만들지 않는다. 코드가 상황별 상태와 재생 위치를 지정한다.
- 루트 모션과 Animation Event는 재생하지 않는다. 입력 판정·피해·투사체 생성은 기존 전투 로직이 담당한다. StateMachineBehaviour에도 전투 로직을 넣지 않는다.
- 지정한 상태를 찾지 못하면 경고를 한 번 남기고 Idle로 돌아간다. Animator가 없으면 등록한 Sprite 또는 UI Prefab을 기본 동작과 함께 표시한다.

공격 연출 탭에서 각 입력의 투사체를 직접 설정한다. Animator 연결 대상은 몬스터 몸체다. 개별 투사체 이미지 제작은 기존 `MonsterAttacks/<몬스터 ID>/<패턴 ID>/step-N` 슬롯 규칙을 사용할 수 있다. 기본 12종의 전용 공격 연출은 그대로 유지된다.

Animator API 참고: [Animator.Play](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Animator.Play.html), [Animator.Update](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Animator.Update.html).

## 4. 검증과 테스트

**설정 검증 및 저장**으로 패턴·ID·Prefab·Animator 경로를 확인한다. 에셋이 `Resources/BBSB/Monsters` 밖에 있으면 전투에 자동 등록되지 않는다. 유효하지 않은 에셋과 중복 ID는 플레이 시작 시 Console에 이유를 표시하고 등록에서 제외한다.

**선택한 패턴의 테스트 장면 열기**는 현재 장면의 저장 여부를 확인한 뒤 별도의 빈 테스트 장면을 연다. 선택한 몬스터·패턴·BPM이 연결된 `Monster rehearsal` 오브젝트가 생성된다. Play를 누르면 같은 패턴을 반복 연습할 수 있다.

- 상단: Call/Response 타임라인과 현재 시각.
- 전투: 실제 행동 아이콘, 몬스터 외형·Animator, 기본 공격 효과와 플레이어 대응 모션.
- 하단: 몬스터·패턴 이름과 콤보.
- 우측: 일시정지·처음부터·소리 켜기/끄기.

테스트는 별도의 RhythmRound를 사용하므로 탐험 HP·보상·저장 데이터에 영향을 주지 않는다. 유지 입력 중 일시정지하면 화면을 다시 눌러 이어간다. 테스트를 마친 뒤 원래 장면은 Project 창에서 다시 연다. 테스트 장면은 필요하면 직접 저장할 수 있다.

자동 검증에는 커스텀 목록의 중복 거부·원자적 갱신, 새 패턴의 기본 공격 연출, Call/Attack/Recover/판정 상태 선택과 반복을 포함한다. Unity 테스트에는 에셋 변환·등록/제외·Animator 상태 샘플링과 입력 통과를 추가했다. 작업 환경에는 Unity Editor가 없어 Unity 테스트 실행과 실제 에디터/게임 화면 검증은 별도로 필요하다.


## 공격 연출 편집

**공격 연출** 탭에서 패턴을 고르고 Response 입력마다 **이 입력의 공격 직접 설정**을 켠다. 기존 12종의 42개 입력에는 Master 조정안을 바탕으로 편집 가능한 설정을 연결했다. 이미지 자체를 새로 만들지 않고 기존 이미지 슬롯을 재사용한다.

- **생성 기준 Call + 생성 지연**: 어느 Call에서 몇 박 뒤에 공격을 생성할지 설정한다. 생성 시각은 실제 입력보다 앞이어야 한다.
- **이동 방식**: Linear 직선, Lob 포물선, Relay Call마다 도약, WaitRush 대기 후 돌진, Walk 박자에 맞춘 걸음, Extend 늘어남, Materialize 판정 때 출현.
- **WaitRush 돌진 길이**: 판정 직전 몇 박 동안 이동할지 설정한다. 이전 시간에는 발사 위치에서 기다린다.
- **높이·궤적·늘어남·지면**: 크기와 이동 모양, 몸체 연결 여부를 조정한다. 도착 시각은 해당 Response 판정에 고정된다.
- **발사 위치·판정 위치·표시 보정**: 옵션을 켜면 해당 입력의 설정이 기존 전체 표시 설정보다 우선한다. 발사 보정은 몬스터 키, 판정·이미지 보정은 플레이어 키 기준이다.
- **단계별 Sprite 프레임**: Spawn / Wait / Travel / Contact / Perfect / HalfMiss / Miss에 Sprite 배열과 반복 여부를 등록한다. 빈 단계는 기존 리소스 이미지 또는 이동 이미지로 보완한다. 유지 종료·판정 반응은 실제 판정 시계가 제어한다.
- **기존 이미지 폴더**: Resources 기준 상대 경로를 지정해서 다른 입력의 이미지를 재사용할 수 있다. 직접 연결한 단계별 Sprite가 우선한다.

예를 들어 Call이 0·0.5·1·1.5박, Tap이 2·2.5·3·3.5박인 하피는 각 발을 대응하는 Call에서 생성하고 WaitRush 길이를 0.5박으로 설정한다. 네 발이 각각 대기했다가 자기 판정 직전에 출발한다. 타임라인과 **선택한 패턴의 테스트 장면 열기**에서 실제 공격·판정·모션을 확인한다.

공격 설정은 입력 행에 붙어 있으므로 입력을 추가·삭제하면 그 공격도 함께 추가·삭제된다. 입력 시각을 바꾸면 도착 시각이 따라 바뀐다. 실행 중인 계획은 설정의 복사본을 사용한다. 새 설정은 다음 Play/새 테스트 계획에서 적용된다.

## Master 박자 조정안의 표현

아라크네처럼 Response 구간 시작 1박, 첫 입력 상대 시각 0.5박이면 실제 첫 입력은 첫 Call 후 1.5박이다. 에디터 값은 유지하고 내부 계획만 첫 입력 기준으로 정규화한다. 전체 구절 길이와 피해 가중치, 각 Call·입력 시각은 보존된다.

Call 구분 경고는 소리나 동작만으로 다음 입력을 예상하기 어려운 경우를 알린다. 경고가 있어도 저장·연습·출현할 수 있다. 갑각 용인의 현재 패턴은 일반 Independent로 등록했다. Beat Shift는 Hold를 엇박으로 옮기는 일반 옵션이 아니라 네코마타의 연결된 Tap 반복 전용이다.

네코마타의 **패턴 확률을 반복과 전환에 적용**을 켜면 기본 패턴 확률은 연속 구간 진입에, 전환 패턴 확률은 최소 기본 Call 횟수 이후 매 Call의 전환 시도에 사용된다. 전환되지 않으면 기본 Tap을 이어가므로 연속 박자는 끊기지 않는다. 같은 시드는 같은 결과를 만든다. 배치 후보가 부족하면 기존의 완전한 정박→엇박→정박 구절을 사용하며, 빈 박자 보충도 완전한 구절 단위로 동작한다. 옵션을 끄면 고정 횟수 전환을 유지한다.


개발 검증: `MonsterTimelineEditorTests`는 Unity EditMode에서 Response 기준점 이동 시 기존 박자 보존, Call 삭제 후 연결과 Undo 복원, 새 공격 초기화, 0박 고정·중복 방지, 유지 구간 확장을 확인한다. 이 테스트는 Unity Editor가 필요하며, headless CoreChecks의 실행 대상에는 포함되지 않는다.


## 구간 바 · 이미지 드롭 · 커브 미리보기

타임라인 아래 **Response 구간 바**의 양 끝 손잡이를 드래그해 구간을 늘리거나 줄인다. 왼쪽을 옮겨도 입력의 실제 박자는 그대로 유지되며, 오른쪽은 마지막 순간 입력의 0.25박 뒤 또는 유지 입력의 종료까지 줄일 수 있다. 입력을 지우거나 잘라내지 않는다. **끝을 마지막 입력에 맞추기**는 뒤에 남은 빈 공간을 한 번에 정리한다. 이후 휴식 길이는 유지한다. 드래그는 한 번의 Undo로 되돌리며 Esc로 취소할 수 있다.

Response를 선택하고 **공격 직접 설정**을 켜면 다음을 편집할 수 있다.

- **공격 이미지**: 등록할 단계를 고른 뒤 Project 창의 Sprite나 이미지 파일을 드롭한다. 여러 파일이나 Multiple Sprite 이미지는 프레임으로 추가되며, Multiple 내부 Sprite는 이름 순서로 들어간다. 각 프레임의 썸네일을 보고 교체·삭제하거나 화살표로 순서를 바꿀 수 있다. 같은 Sprite를 다시 넣어 반복 프레임으로 쓰는 것도 가능하다.
- Sprite로 임포트되지 않은 텍스처는 대기 목록에 놓는다. **Sprite로 임포트하고 등록** 버튼을 누르면 해당 파일의 Texture Type을 Sprite / Single로 변경한다. 이미 Sprite로 설정된 파일의 슬라이스는 유지한다. 드롭만으로 임포트 설정을 바꾸지는 않는다.
- **궤적 · 진행 미리보기**: 흐린 선은 전체 경로, 진한 분홍 선은 현재까지의 이동이다. 재생/정지와 생성→판정 슬라이더로 WaitRush 대기·출발, Relay의 튀는 움직임, 해당 시점의 이미지 프레임을 확인한다. Materialize는 이동선 없이 판정 지점에 나타난다.
- **Animation Curve로 궤적 조절**: 진행률과 높이 커브를 눌러 Unity의 커브 편집기에서 키와 접선을 수정한다. 직선·포물선 버튼으로 초기 형태를 잡을 수 있다. 진행률은 기존 이동 방식의 진행 0~1을 다시 매핑하고 높이는 플레이어 키 단위로 기존 Lift를 대체한다. 키의 가로 범위는 0~1을 포함해야 한다.
- 커브의 양 끝 값은 출발·도착에 맞게 보정된다. 높이는 양 끝을 잇는 기준선을 빼서 양 끝이 0이 되며 진행률은 끝 값 기준으로 정규화한 후 0~1로 제한한다. 판정 박자는 바뀌지 않는다. WaitRush의 대기·이동 구간과 판정 후 반응도 유지한다. 커브를 끄면 기존 경로를 사용한다.

경로 미리보기는 전투의 타이밍과 경로 계산을 공유한다. 몬스터와 플레이어를 같은 기준 키, 기본 거리 3키로 놓은 상대 미리보기이며 이미지는 알아보기 쉽게 확대한다. 실제 전투의 크기·배치·몸체에 붙은 공격과 판정 후 연출은 기존 테스트 장면에서 확인한다. 미리보기에는 유효한 몬스터 설정이 필요하며 문제가 있으면 이유를 표시한다.

실행 중인 전투는 커브 키를 포함한 설정의 복사본을 사용한다. 에디터에서 커브를 고쳐도 이미 시작한 전투의 공격이 중간에 바뀌지 않는다. Unity 테스트에는 구간 축소·입력 시각 보존·Undo와 커브 경로·도착 위치·복사본 유지·잘못된 커브 거부를 추가했다.
