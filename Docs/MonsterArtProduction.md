# Sol 인수인계 — 몬스터 이미지 제작 명세

이 문서를 그대로 이미지 제작 채팅에 전달한다. **몬스터 공격 이펙트와 몬스터걸 본체**의 실제 PNG 납품 명세다. 현재 본체 93개·공격 223개 PNG의 제작·업로드·코드 연결을 완료했다. 아래 캔버스 크기는 최초 제작 목표이며 업로드 파일은 생성된 원본 크기를 유지한다. 최초 명세의 기준 런타임은 `codex/roguelike-foundation`의 [`936fd59`](https://github.com/jorodane/BBSB/commit/936fd591ca34b200cab9700983928e4f24ac5f2f)이다.

## 1. Sol이 받을 작업 범위

| 구분 | 새로 제작할 서로 다른 그림 | 최종 PNG 배치 수 | 범위 |
|---|---:|---:|---|
| A. 공격 이미지 | 84장 | 223개 | 16개 그림 세트를 36개 공격 단계에 연결. 인형 걷기 4프레임 포함 |
| B. 몬스터걸 본체 | 54장 | 93개 | 12종 대기 + 33개 Call 자리 + 24개 Response 자리 + 24개 복귀 자리 |
| 전체 | **138장** | **316개** | 동일 그림 복사 178개 포함 |

위 수량은 **이 문서의 1차 완성 세트**다. 엔진 실행에 전부 필수인 것은 아니다. 공격부터 적용하려면 A를 진행하고, 본체는 기존 그림으로 계속 동작한다. 새 몬스터걸 외형까지 교체하려면 B도 제작한다. 각 원본은 한 번만 만들고 지정된 곳에 그대로 복사한다. 각 폴더마다 새 그림을 생성할 필요가 없다.

정확한 파일 목록은 [MonsterArtFiles.json](MonsterArtFiles.json)에 있다. `sources`는 **실제 제작할 원본별 크기·그림 설명·첫 저장 경로**, `files`는 **모든 최종 파일의 경로·크기·generate/copy·copyFrom**이다. 파일 수에는 아래 선택 애니메이션이 포함되지 않는다.

## 2. 공통 제작 규격

| 항목 | 납품 규칙 |
|---|---|
| 파일 형식 | 실제 알파 채널을 가진 RGBA PNG, sRGB. 배경 픽셀은 투명 |
| 캔버스 | 아래 표의 **가로×세로 px**. 생성 도구의 원본 크기가 달라도 최종 납품은 이 크기로 맞춘다 |
| 방향·시점 | 화면 오른쪽에 선 몬스터가 왼쪽을 향하는 측면에 가까운 약한 3/4 시점. 플레이어와 같은 고정 시점 |
| 그림체 | 기존 플레이어의 선명한 어두운 외곽선, 큰 색 면, 셀 채색에 맞춘다. 작은 화면에서 읽히는 단순한 장식과 큰 관절·재질 차이 |
| 포함 대상 | 본체 PNG는 몬스터 1명, 공격 PNG는 공격체 1개 또는 깃털 한 묶음. 본체와 발사체를 합성하지 않는다 |
| 투명 가장자리 | 흰 테두리·초록색 번짐·검은 매트가 없어야 한다. 체크무늬·초록 배경을 그림으로 넣지 않는다 |
| 그림 밖 요소 | 배경, 바닥 원반/그림자, 플레이어, UI, 글자, 박자 숫자, 방향 화살표, 워터마크 제외 |
| 프레임 구성 | **PNG 한 파일에 한 포즈.** 여러 포즈를 한 장에 배열한 시트는 런타임 납품 파일로 사용하지 않는다 |
| 크기 유지 | 같은 세트의 모든 포즈는 같은 캔버스·신체 비율·기준점. 웅크린 포즈를 캔버스에 맞춰 확대하거나 포즈마다 자동 크롭하지 않는다 |

아래 픽셀 크기는 이번 제작에서 정한 납품 규격이다. 런타임에 박힌 필수 해상도는 아니다. 새 공격 PNG 임포터가 긴 변을 최대 1024로 가져오므로 그 안에서 정했다. **투명 배경을 자동 제거하는 기능은 없다.** 최종 PNG 자체가 투명해야 한다.

스타일 참고: [현재 플레이어 원본](../Assets/BBSB/Resources/BBSB/BattleArt/PlayerMotion/idle.png), [몬스터걸 종족 설정](MonsterGirls.md). 플레이어 참고 PNG는 여러 포즈가 들어 있는 기존 파일이며, 이번 몬스터 납품은 별도 PNG 방식이다. 이전 플레이어 프롬프트의 배경·아틀라스 지시를 이번 작업에 적용하지 않는다.

### 캔버스와 실제 화면의 관계

`H`는 현재 설정의 플레이어 **기준 표시 높이**다. 이미지의 투명 여백도 표시 높이에 포함된다. 기본 캐릭터 배율 0.5에서 1280×720 무대는 H≈252px, 1280×800은 H≈280px다. 설정을 바꾸면 함께 달라진다. 아래 화면 높이는 첫 값의 예시이며 렌더 실측값은 아니다.

| 이미지 종류 | 최종 캔버스 px | 기준점 | 기본 화면 높이 예시 |
|---|---|---|---|
| 본체 전체 | 1024×1024 | 아래 중앙 | 1~3마리 편성·깊이에 따라 대략 120~175px |
| 지면 젤리 / 공중 젤리 | 각 512×512 | 지면형 아래 중앙 / 공중형 중앙 | 약 121 / 86px |
| 도자기 장갑 | 512×512 | 중앙 | 약 76~86px |
| 깃털 묶음 | 768×512 | 중앙 | 약 76px |
| 여우불 / 꿈방울 / 전기 구슬 / 갑각 조각 | 각 512×512 | 중앙 | 약 60 / 81 / 63 / 66px |
| 작은 인형 | 768×1024 | 아래 중앙 | 약 131px |
| 비늘 방패 | 512×768 | 중앙 | 약 151px |
| 해파리 우산막 | 768×768 | 중앙 | 약 131~151px |
| 꼬리 / 지속 방전 / 장막 | 각 1024×256 | 오른쪽 중앙 | 띠 두께 약 43 / 76 / 55~63px |
| 발목 실 | 1024×128 | 오른쪽 중앙 | 캔버스 두께 약 18px. 실 본선은 그 일부 |

작은 탄의 핵심 무늬는 1~2개, 깃털은 큰 깃 3개 정도로 잡는다. 미세한 문양과 넓고 희미한 외곽광으로 실제 공격체가 작아 보이지 않게 한다.

### 접점과 투명 여백

아래 픽셀 좌표는 **왼쪽 위=(0,0), 오른쪽으로 X 증가, 아래로 Y 증가**다. 코드의 피벗 Y는 아래부터 센다.

| 형식 | 그림 배치 |
|---|---|
| 일반 중앙형 | 중심과 주요 반응점을 `(W/2,H/2)` 부근에 둔다. 기본 여백은 상하좌우 5~8%. contact에서 눌리는 부분도 중앙 근처에 오게 하며 상태별 원점을 유지한다 |
| 본체 | 기준 지면 `(512,1023)`. 서 있는 기준 포즈의 머리 끝은 대략 y=100~140, 발/하반신 접지점은 y=1022~1023. 크기·지면을 정한 뒤 모든 포즈에 동일 적용. 넓은 날개·뱀 하반신·거미 다리도 프레임 밖으로 자르지 않는다 |
| 지면 젤리 | 바닥 `(256,511)`, 최종 타격 돌기 `(256,21)` 근처. **아래에 일반적인 5~8% 투명 여백을 두지 않는다**. 결과 파편도 동일 원점. 도약 높이는 코드가 만든다 |
| 작은 인형 | 바닥 `(384,1023)`, contact의 주먹 접점 `(384,118)` 근처. 공격 손은 바닥에서 약 88% 높이. 날아가거나 걷는 그림도 같은 크기·아래 원점. 이동·통째 들썩임은 코드가 담당 |
| 연결 띠 | 오른쪽 중앙이 몬스터에 붙는 뿌리, 왼쪽 중앙이 플레이어에 닿는 끝. 양 끝을 파일 가장자리 0~2px 이내까지 연결. 위아래에만 여백. 코드가 **가로 길이를 늘리므로** 원·얼굴·글자·정비례 장식을 띠에 넣지 않는다 |

본체의 발이 없는 종족은 뱀의 접힌 몸·거미 지지발·촉수 최하단처럼 반복해서 쓸 기준을 잡는다. 해파리의 부유 여백은 의도한 높이를 처음 정하고 모든 본체 포즈에서 유지한다. 일반 PNG의 넓은 아래 여백 때문에 서 있는 캐릭터가 뜨는 일이 생기지 않게 한다.

공격 PNG의 기준점은 런타임 설정을 사용하므로 Sprite Editor의 피벗만 바꿔서는 공격 접점이 보정되지 않는다. 필요하면 `Display.asset`의 해당 단계 `Poses → Override Pivot / Pivot`, `Image Offset`, `Scale`로 조정한다. 연결 띠는 오른쪽 중앙이 고정이다. 본체는 임포트된 Sprite 피벗을 사용한다.

## 3. 파일명과 표시 시점

모든 경로의 기준 폴더:

```text
Assets/BBSB/Resources/BBSB/BattleArt/MonsterAttacks/
```

공격은 `<몬스터 ID>/<패턴 ID>/step-N/<상태>.png`에 넣는다. `N`은 원본 대응 단계이며 0부터 시작한다. **무기 개수만큼 복제하거나 step 번호를 새로 만들지 않는다.**

| 파일 | 그릴 상태 / 사용 시점 |
|---|---|
| `spawn.png` | Call 또는 예정된 후속 발사 직후. 지면 젤리는 각 Call 때 반복 |
| `wait.png` | 생성 후 대기하는 여우불·갑각 조각·실에만 사용 |
| `travel.png` | 이동 중 그림. 이동 궤적은 코드가 만든다 |
| `contact.png` | Response에 도착한 모습. Hold/Dive/Shake는 유지 시간 동안 사용 |
| `perfect.png` | 실제 Perfect에 맞는 파괴·회수·뒤집힘 등 |
| `half-miss.png` | 실제 HalfMiss에 맞는 부분 변형. 전체적으로 비껴가는 이동·회전은 코드가 담당 |
| `miss.png` | 실제 Miss 때의 온전하거나 더 강한 접촉 상태. 플레이어 피격 포즈를 넣지 않는다 |

이번 1차 제작은 **단일 키포즈 + 코드 이동**을 기본으로 한다. 예외는 인형의 걷기 `travel-0.png`~`travel-3.png` 4장이다. 표의 `복사`는 파일을 생략하라는 뜻이 아니라, 같은 PNG를 그 경로에 실제로 복사하라는 뜻이다. 다른 폴더의 이미지를 자동으로 찾아 재사용하지 않는다.

### 이후 프레임을 추가할 때의 한계

- 번호는 `travel-0.png`, `travel-1.png`처럼 0부터 연속이다. `travel-1.png`부터 시작하지 않는다. 번호 파일이 있으면 같은 이름의 단일 `travel.png`보다 우선한다. 1차 납품에는 선택 프레임을 섞지 않는다.
- 일반 상태의 기본 재생은 **한 박에 2프레임**이고 프레임 끝에서 반복한다. 대부분의 spawn과 0.25박 급발진 travel은 짧아 여러 프레임을 넣어도 첫 장만 보일 수 있다. 단일 PNG를 쓴다.
- 인형은 4장으로 **2박에 한 주기**, 매 박마다 한 걸음이다. 전신을 프레임 안에서 위아래로 이동시키지 않는다. 코드의 발걸음 이동·도약과 중복된다. Walk 중 멈칫하는 구간도 travel이므로 `wait.png`를 만들지 않는다.
- 결과는 **0.32초, 초당 12프레임**이다. 나중에 결과를 애니메이션으로 확장하면 `perfect-0.png`~`perfect-3.png`처럼 최대 4장으로 잡는다. 1~2장 번호 클립은 반복하고, 6~8장을 넣어도 뒷부분은 표시되지 않는다. 단일 결과 PNG도 코드의 이동·확대·페이드로 동작한다.
- 실제 Shake 왕복 입력과 contact의 프레임 번호는 연결되어 있지 않다. 첫 제작에서는 막의 중립 접촉 1장과 최종 결과만 그린다. 자율 루프로 성공 동작을 먼저 재생하지 않는다.
- Perfect의 확대/되튕김/회수, HalfMiss의 대각선 이동·회전, Miss의 왼쪽 이동과 모든 결과의 페이드는 코드가 만든다. PNG는 해당 재질의 **국소 변형**을 담고 화면 전체 궤적·회전·페이드를 중복해서 그리지 않는다.

## 6. B — 몬스터걸 본체 파일

본체는 모두 **1024×1024px**다. 먼저 각 종족의 `idle.png`로 외형·크기를 확정한 뒤 같은 개체를 유지하며 포즈를 만든다. 공격체와 본체에 같은 물체를 이중으로 그리지 않는다. 분리 주먹·작은 인형·긴 꼬리·장막·실은 별도 공격 PNG가 그린다.

| 위치 | 의미 |
|---|---|
| `<몬스터 ID>/idle.png` | 해당 몬스터걸의 기본 전신. 12종 각각 1장 |
| `<몬스터 ID>/<패턴 ID>/body/call-0.png` | 첫 Call. 발사/발구르기/던지기/내려놓기 등 |
| 같은 폴더의 `call-1.png`, `call-2.png` | 그 패턴에 실제 두 번째·세 번째 Call이 있을 때만 |
| 같은 폴더의 `attack.png` | **플레이어의 Response 시점**에 보여줄 유지/마무리 자세. 발사 포즈라는 의미가 아니다 |
| 같은 폴더의 `recover.png` | 1차에는 해당 종족의 idle.png를 그대로 복사해 복귀 |

Call 포즈는 기본 0.65박, Tap/Flick의 attack은 0.3박, recover는 0.35박이다. Hold/Dive/Shake의 attack은 유지 시간만큼 표시된다. 한 패턴의 모든 Response가 같은 `body/attack.png`를 사용한다. 예를 들어 용인의 복합 패턴에서는 Hold와 뒤의 Tap에 같은 본체 포즈를 쓴다. 서로 다른 모습이 필요한 발사 단계는 Call 그림에 담는다.

긴 쉼에 별도의 `sleep.png`, `wait.png` 본체 슬롯은 없다. 맥의 Call 포즈도 0.65박 뒤에는 idle로 돌아가므로 **맥 idle 자체를 졸고 있는 중립 자세**로 만든다. 인형의 7박 걷기는 작은 인형의 공격 이미지에서 진행한다. 이번 파일만으로 본체가 7박 동안 새로운 전용 연속 연기를 한다고 가정하지 않는다.

본체 번호 클립을 나중에 추가하려면 첫 Call의 두 프레임은 `call-0-0.png`, `call-0-1.png`다. `call-1.png`는 첫 Call의 다음 프레임이 아니라 **두 번째 Call**이다. 현재 1차 명세는 본체 단일 PNG만 사용한다.

## 7. Sol용 생성 지시문

아래 공통 문장에 제작표의 **해당 원본 한 행**을 붙인다. 여러 원본을 한 이미지에 합치지 않는다. 종족의 idle 또는 앞서 만든 같은 세트의 PNG를 참조해 같은 디자인을 유지한다.

> BBSB 리듬 전투 게임에 바로 사용할 개별 스프라이트 PNG 한 장을 제작한다. 배경은 실제 알파 투명, 기존 플레이어와 어울리는 선명한 어두운 외곽선과 셀 채색, 단순하고 읽기 쉬운 큰 색 면을 사용한다. 몬스터는 화면 오른쪽에서 왼쪽을 향하는 고정된 측면에 가까운 약한 3/4 시점이다. 지정한 한 포즈만 그린다. 배경·바닥 그림자·UI·글자·플레이어·여러 포즈 배열은 넣지 않는다. 아래 파일 설명의 캔버스 크기, 피벗과 접점, 투명 여백을 유지한다. 같은 세트의 기존 그림과 신체 비율·재질·색·원점을 일치시킨다. 최종 출력 이름과 픽셀 크기는 아래 항목을 따른다.

예시 — 작은 인형의 최종 접촉 그림:

```text
종족: 태엽 인형 소녀가 사용하는 작은 태엽 인형
파일: clock-spirit/clock-quick-tap/step-0/contact.png
최종 크기: 768×1024 RGBA PNG
그림: 왼쪽을 향해 착지한 작은 인형이 왼쪽 위로 주먹을 높게 내민 단일 전신 포즈.
기준점: 발바닥 아래 중앙 (384,1023), 공격 손의 접점은 (384,118) 부근.
본체는 손보다 오른쪽으로 배치해 공격 손이 지정 접점에 온다.
태엽·큰 손·구체 관절·단순한 얼굴. 큰 본체 인형과 같은 크림·버건디·황동 디자인.
몸통 위치와 캔버스 크기를 다른 작은 인형 포즈와 일치시킨다.
플레이어, 큰 본체 인형, 바닥, 이동 궤적은 넣지 않는다.
재사용: clock-spirit/clock-seven-beat-wait/step-0/contact.png에도 동일 PNG를 복사한다.
```

생성 도구가 지정한 직사각형 해상도를 직접 지원하지 않으면 최종 내보내기 단계에서 **비율 유지·투명 캔버스 배치**로 맞춘다. 개체 자체를 찌그러뜨려 크기를 맞추거나 흰 배경 JPEG를 PNG 확장자로 바꾸지 않는다. 생성 결과의 실제 알파·크기를 확인한 뒤 납품한다.

## 8. 납품과 적용 순서

1. 공격만 먼저 만들 때도 종족의 디자인 기준을 한 번 정한다. 전체 교체를 진행한다면 본체 idle 12장을 먼저 만들고 같은 디자인으로 Call과 공격 이미지를 잇는다.
2. A01~A16의 `원본` 행과 B의 `원본` 행을 제작한다. 전체 목록은 JSON의 `sources`와 일치해야 한다.
3. JSON의 `files`를 순서대로 처리한다. `generate` 파일에는 원본을 저장하고, `copy` 파일에는 `copyFrom`의 **PNG 바이트만** 복사한다. 대상은 모두 저장소 루트 기준 경로다. 같은 원본의 복사본은 임의로 리사이즈하지 않는다.
4. 최종 전달은 이 폴더 구조를 유지한 PNG 묶음과 제작 완료 목록으로 한다. `sources`의 분류 ID 이름으로 새 Resources 폴더를 만들지 않는다. 기존 폴더와 `.meta`를 유지하고 새 PNG의 `.meta`는 Unity에서 생성한다. 다른 파일의 `.meta` GUID를 복사하지 않는다.
5. PNG 임포트 완료 후 전투나 연습을 다시 시작한다. 런타임은 이미지 목록을 캐시하므로 실행 중 파일만 추가한 상태로는 즉시 새 그림을 찾지 않을 수 있다.
6. 기존 준비 화면의 패턴 연습에서 왼쪽 방향, 도착 접점, 인형 접지, 장막/실 높이, Perfect·HalfMiss·Miss의 구별을 확인한다. 필요하면 [기술 적용 가이드](MonsterAttackArt.md)의 `Display.asset` 보정값을 조절한다.

1차 납품 범위는 위에 연결된 이미지다. 사망/피격 전신, 상태 아이콘, 배경, 무기 그림, 새 음원, 걷기 발소리는 이 목록에 포함하지 않는다. 몬스터별 공유 HP와 무기 피해·입력 판정의 변경도 이 이미지 작업의 범위가 아니다.

## 9. 명세 검증 범위

명세의 12종·24패턴·36개 step 및 33개 Call을 현재 카탈로그/원본 패턴과 대조하고, 모든 목적지 폴더·파일명·원본 참조·해상도·복사 수를 검사했다. 선택 애니메이션은 기본 납품 수량에서 제외했다. 이 작업은 문서와 파일 목록만 추가하며 런타임을 변경하지 않는다.

새 PNG 316개와 도감 아이콘 36개가 업로드되었으며 배치 경로와 원본 일치를 확인했다. Unity Editor는 이 환경에 없어 실제 임포트·축소 가독성·전투 화면은 Unity에서 확인해야 한다. `MonsterArtIntegrationTests`로 전체 이미지 경로와 패턴 상태 연결을 검사할 수 있다.
